## Objective

Axiom V1 ships with **no first-party cloud**. Every upstream cloud service (Orca Cloud account/login, relay director, push gateway, artifact sharing, skill sharing/cloud skills) becomes *unconfigured by default* through `src/shared/product-egress-policy.ts` (M0-03), and stays reachable **only behind explicit environment flags** that upstream already honours (`ORCA_CLOUD_API_URL`, `ORCA_CLOUD_CLIENT_ID`, `ORCA_PUSH_GATEWAY_URL`, `ORCA_ARTIFACTS_API_URL`, …). Unconfigured means: no request, no sign-in prompt, no share buttons, typed "unconfigured" results on every lane that upstream already models as unconfigured.

Not in this task: plugin marketplace, skills install source, the star prompt (M0-06b); human-facing copy and locale catalogs (M0-05); `mobile/`, `cloud/` (M0-07).

## Design

Extend `ProductEgressPolicy` (and its pinned test) with:

```ts
/** Packaged-build defaults for first-party cloud services. null = unconfigured unless the env flag is set. */
readonly cloudAuth: { readonly apiBaseUrl: string; readonly clientId: string; readonly relayDirectorUrl: string } | null
readonly pushGatewayOrigin: string | null
readonly artifactShareApiOrigin: string | null
/** Hosts whose URLs are accepted as skill-share links; empty = bare share ids only. */
readonly skillShareHosts: readonly string[]
```

All four are `null` / `[]` in V1. Consumers read the policy instead of the `PRODUCTION_*` literals; the existing env-flag code paths stay exactly as they are (they are the "keep-behind-flag" mechanism), with one rule: **a packaged build never falls back to a vendor default** — if the env flag is unset and the policy is null, the service is unconfigured.
