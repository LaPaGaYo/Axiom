## Objective

Produce the execution contract for an Attempt and the deterministic machinery that chooses it:

1. **AgentSpec** — content-addressed row in `agent_specs` (`id = 'spec_' + sha256(canonical spec)`), an execution contract, not a persona (§8.2): role, capabilities, provider, model, reasoning, permissions, budget, workspace strategy, the Task and its acceptance criteria, the ContextPackage identity, the submission contract, and the **selection record** (installed set, filters applied, ranked fallback order, chosen provider, rationale).
2. **AgentFactory** — builds the AgentSpec for a Task from the Task spec + Mission policy + host availability in the §8.3 order: filter (not installed / policy-disallowed / tier too low for the risk) → rank (RulesEngine) → pick provider / model / reasoning → record (row + audit event).
3. **RulesEngine** — the mandatory `DecisionEngine` baseline (D8): a deterministic implementation of `choose / score / classify / rank` over a closed candidate set; Jev and others come later behind the same interface. Its output is advisory: it orders candidates that already passed the deterministic filters and can never re-admit a filtered one.
4. **Mission policy routing (v44)** — the user's provider preference per Mission: additive column `mission_policies.routing` + `PolicySchema.routing`, exposed as `axiom.policy.show / update` (M2: `routing` and `concurrencyLimit` only; a `budget` change is an Approval action and is refused with `approval_required` until M4) and `axiom mission policy show | update`.
