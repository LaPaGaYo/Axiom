Today a settled Submission keeps its Worker terminal forever: `settleSubmission` calls `db.retainWorkerTerminalResource(attemptId)` and nothing ever closes the terminal, so the agent and anything it started (dev servers, watchers, sub-agents) keep running, and nothing preserves what the agent did once its own session files rotate. D76 (Henry's choice) replaces that with: archive the Worker's output as a redacted Axiom Artifact at SUBMISSION, record which processes were still alive, and close the Worker's terminal (agent process tree included) shortly after the CLI has its receipt. No children_active refusal, no stop before the snapshot (both rejected in D76). No kernel (Orca orchestration) change, no schema migration, no renderer change, no new dependency.
