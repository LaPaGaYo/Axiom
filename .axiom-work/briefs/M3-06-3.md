# Task M3-06-3 — Rule supervision, first part: the runtime limit as the `timeout` rule, stall observation, measured event cadence (D88 rules 9–10; D60 / D68 revision rows of 2026-10-26 and 2026-11-09)

Planner brief, 2026-11-12 (verifier). D88 rule 9 decided how Axiom supervises a running Worker with deterministic rules only: a limit a human set (the runtime limit; a token budget when one is set) acts automatically (`auto`); a threshold the system guesses (how long without output counts as stalled) only **observes** first — it writes what it would have done and changes nothing — until evidence justifies more. M3.md splits the work in three, and this is the first part:

- **M3-06-3 (this Task)**: the supervision step in recovery's reconcile pass; the existing runtime-limit stop becomes the `timeout` rule (same behaviour, aligned vocabulary, a supervision audit); the stall rule in `observe` mode; every headless Attempt's measured event cadence; the stall threshold derived from verified Attempts.
- M3-06-3-2: reconciling each observation with what happened later, the per-rule evidence table, the proposal to raise a rule's mode, and the stall rule's `notify` / `stop` tiers (needs a policy field, which needs a schema migration).
- M3-06-3-3: the token budget (`budget_exhausted`).

## Outcome

After this Task, every reconcile pass supervises each live, current Worker Attempt: the runtime limit stops it exactly as today but is recorded as the `timeout` rule (`reason: 'timeout'`, plus an `attempt.supervised` audit naming the rule, its threshold and where the threshold came from); a headless Attempt whose events file has been silent longer than the stall threshold gets one `attempt.supervised` "would have" audit and keeps running; and every headless Attempt leaves one `attempt.cadence` audit with the largest silence measured while it ran. The stall threshold is twice the largest silence of recently verified Attempts once enough of them exist, otherwise a fixed default.

## Deliverables

1. **The supervision step.** A new module under `src/main/axiom/recovery/` (e.g. `attempt-supervision.ts`) owns what happens to a live, current, non-planner binding in the branch of ground truth 1. `reconcileAttempt` calls it there instead of the inline runtime-limit block and returns what it returns; everything else in `reconcileAttempt` stays where it is. Order inside the step: the stall observation (deliverable 3) first, then the timeout rule (deliverable 2), so a pass in which both apply writes the observation before the stop. The step never throws for a missing or unreadable events file.
2. **The `timeout` rule** (`auto`; a human set the limit). Same limit lookup, same clock, same stop, the same capture and the same re-reads as ground truth 1 — the behaviour is unchanged. Only the vocabulary changes: the stop audit, the `stop_unknown` audit and the settlement reason are `'timeout'`. In the same settlement transaction, before `attempt.stopped`, it writes `attempt.supervised { rule: 'timeout', mode: 'auto', thresholdMs, thresholdSource: 'task' | 'policy', elapsedMs, action: 'stopped' | 'stop_unknown' }` (through `auditAttempt`, which adds `taskId` and `seq`); `thresholdSource` says whether the limit came from the Task spec or the policy. A `stop_unknown` receipt writes the supervision audit and `attempt.stop_unknown { reason: 'timeout' }` once and settles nothing, as today. TUI Attempts are stopped as today (no capture). With no limit there is no rule and no audit.
3. **The stall rule, `observe` only** (headless Attempts whose events file exists). The Attempt's *last event* is the events file's modification time; its *silence* is `now` minus that time. A missing file means the harness has not started writing: the rule and the sampling of deliverable 4 skip the Attempt for that pass. When the silence exceeds the stall threshold (deliverable 5), write once per Attempt `attempt.supervised { rule: 'stalled', mode: 'observe', thresholdMs, thresholdSource: 'measured' | 'default' | 'e2e', idleMs, lastEventAt, wouldActAt }` (ISO timestamps; `wouldActAt` = last event + threshold). Nothing else: no stop, no stage change, no message, no effect. A later pass of the same Attempt writes no second stall observation, whatever its silence. A file that cannot be read for another reason than "missing" skips the rule for that pass.
4. **Measured cadence.** While a headless Attempt is live and current and its events file exists, each pass samples its silence (deliverable 3) and keeps, in memory and per runtime instance (the pattern of ground truth 7), the first and last sample time, the number of samples and the largest silence. After each pass of `reconcileAttemptBindings`, an Attempt that is no longer current (no longer the running, unsubmitted latest Attempt of its Task, or its binding is gone) gets exactly one `attempt.cadence { maxEventGapMs, samples, resolutionMs, partial }` audit and its entry is dropped; `resolutionMs` is the reconcile interval; `partial` is true when the first sample came more than two intervals after the binding's `createdAt` (the process restarted while it ran). Nothing is written while the Attempt is current. A process restart loses the entries; nothing reconstructs them.
5. **The stall threshold.** A new module with the constants (in the manner of `interruption-policy.ts`) computes it at most once per pass, and only when a live headless Attempt needs it: (a) under e2e, a positive integer in `AXIOM_E2E_STALL_THRESHOLD_MS` → that, source `e2e`; (b) otherwise the newest 20 *qualifying* `attempt.cadence` audits across all Missions — not `partial`, at least 2 samples, and the Attempt's Submission has a candidate with a `PASS` verification run — and, when there are at least 5, `max(5 minutes, 2 × their largest maxEventGapMs)`, source `measured`; (c) otherwise 20 minutes, source `default`. The query reads `audit_events` by event across Missions the way ground truth 9 describes, newest first, bounded.
6. **Fixture and E2E** (host, verifier-run; you cannot run Electron). The fixture gains `stallThresholdMs?: number` → `AXIOM_E2E_STALL_THRESHOLD_MS` (unset → empty string, as `interruptionBackoffMs` does). `tests/e2e/mission-budget-stop-continuation.spec.ts` keeps its flow and its title and adds `stallThresholdMs: 1000`; it now asserts: Attempt 1's `attempt.stopped.reason` is `timeout`; Attempt 1 has an `attempt.supervised` with `rule: 'timeout'`, `mode: 'auto'`, `action: 'stopped'`, `thresholdSource: 'task'`; Attempt 1 has exactly one `attempt.supervised` with `rule: 'stalled'`, `mode: 'observe'`, `thresholdMs: 1000`, `thresholdSource: 'e2e'`, `idleMs >= 1000`, written before its `attempt.stopped`; the successor prompt contains `timeout`; and eventually Attempt 1 has one `attempt.cadence` with `samples >= 1`. Everything else it asserted stays.
7. **Docs.** `docs/reference/control-plane.md`: rule d of the Recovery table (the limit is the `timeout` rule) and a new subsection "Supervision rules" — the step and its order, the two rules here with their modes, the cadence audit, the threshold and its sources, what is not supervised (planner, TUI stall, token budget), the M3-06-3-2 / M3-06-3-3 boundary. `docs/GLOSSARY.md`: `attempt.supervised`, `attempt.cadence`, the rule names `timeout` / `stalled` and the modes `observe` / `auto`, the threshold constants.
