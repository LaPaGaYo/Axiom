# Task STRUCT-1 — Structure only, no behaviour change: one shared scope for the git writes that run no repository hook, used by the seven places that each wrote their own; the redaction functions move out of `context-builder` into a module of their own (the 结构整理 row of `docs/plans/M4.md`; D93 item 1, parts a and b, approved by Henry 2026-11-16; main process only; no store, contract, renderer, CLI, RPC or e2e change)

Planner brief, 2026-11-16 (verifier). Two things in `src/main/axiom` are written more often than they should be. "Turn the repository's hooks off for this git write" exists in seven places — each makes its own empty temporary directory, spells `-c core.hooksPath=…` itself and removes the directory itself, and two of them also spell the protection that keeps git from acting on a repository above the given directory. And `redactContext` / `detectSecretPatterns` live in `context-builder/redaction.ts`, although seven directories import them and only one of those is the context builder. This Task gives the first one home — a small scope function that every one of the seven uses — and moves the second to a module of its own. **Nothing a caller, a user or a test can observe changes**: the same git commands with the same arguments in the same order, the same options, the same results, the same errors. That is the whole point of doing it as a Task of its own, and it is why this brief is long about what must stay and short about what is new.

Parts c (one definition for the audit event names that code reads) and d (a lint rule on `getAxiomControlPlane()`) of the same decision are **not** this Task: c is a later Task (STRUCT-2), d is the planner's commit when this one is merged.

## Deliverables

1. **NEW `src/main/axiom/execution/hookless-git.ts`**, exporting exactly two functions and importing nothing from `src/main/axiom`:
   1. `confinedGitEnv(cwd: string, env: NodeJS.ProcessEnv = process.env): NodeJS.ProcessEnv` — answers `{ ...env, GIT_CEILING_DIRECTORIES: path.dirname(cwd) }`: git started under it in `cwd` cannot act on a repository above `cwd`.
   2. `withHooklessGit<T>(cwd, settings, use): Promise<T>` with `settings: { timeout: number | undefined; confine: boolean; env?: NodeJS.ProcessEnv }` — **`timeout` and `confine` are required keys**, so that every caller says in its own code whether it has a deadline and whether it is confined — and `use: (git: { hooks: readonly string[]; options: …; directory: string }) => Promise<T>`. It
      - makes one new, empty directory under `os.tmpdir()` (`mkdtemp`);
      - calls `use` once with `hooks` = `['-c', 'core.hooksPath=<that directory>']` (the fragment a caller puts in front of the git subcommand), `options` = `gitOptionsForWorktree(cwd)` plus `timeout` **only when** `settings.timeout` is not `undefined`, plus `env` **only when** `settings.confine` is true (then `confinedGitEnv(cwd, settings.env)`) or `settings.env` is given without `confine` (then that environment as it is) — with `{ timeout: undefined, confine: false }` the options are exactly `gitOptionsForWorktree(cwd)` and have neither key — and `directory` = that directory;
      - answers what `use` answers and rejects with what `use` rejects with, unchanged;
      - afterwards, in both cases, removes the directory with everything in it (`rm`, recursive and force), **best effort**: a removal that fails neither rejects nor changes what `use` answered or threw.
      It runs no git command itself, imports nothing from `src/main/git/runner` (several tests replace that module with a factory that has only `gitExecFileAsync`) — only `gitOptionsForWorktree` from `src/main/git/git-runtime-options` and Node built-ins — catches nothing that `use` throws, and logs nothing.
2. **The seven places use it** — each keeps its own argument lists, its own order of calls, its own error handling and its own results; what goes is its `mkdtemp`, its spelling of the hooks option, its `try` / `finally` around the directory and (places 5, 7 and `readIntegrationGit`) its spelling of the ceiling environment. Settings per place: 1 — `{ timeout: undefined, confine: false }`; 2 — `{ timeout: 30_000, confine: false }`, the scope opened inside the outer `try` and **awaited there** (`return await withHooklessGit(…)`: a bare `return` of the promise would let a rejection escape the `catch` that answers `unavailable`), the write and the readback both under the scope's `options`; 3 — `{ timeout: input.timeout, confine: false }`, the private index inside the scope's directory, the line that builds the private-index options exactly `const isolated = { ...options, env: { ...process.env, GIT_INDEX_FILE: path.join(directory, 'index') } }` with `options` the scope's (never `...options.env`: the scope's options have no `env` here, and an `env` without `process.env` would lose `PATH`); 4 — `{ timeout: 30_000, confine: false }`, **awaited inside the outer `try`** like place 2, the readback after the write as today; 5 — `{ timeout: 120_000, confine: true, env }` with the function's own `env` parameter passed through (so `undefined` falls back to `process.env` exactly as today); `readIntegrationGit` builds its environment with `confinedGitEnv(cwd)`; 6 — `{ timeout: undefined, confine: false }`, `branch -f` still without the hooks option; 7 — the two reads under `{ ...gitOptionsForWorktree(cwd), env: confinedGitEnv(cwd) }`, the scope `{ timeout: undefined, confine: true }` opened **only** when the three conditions hold, as today.
