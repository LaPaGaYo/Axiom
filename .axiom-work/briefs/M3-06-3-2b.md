# Task M3-06-3-2b — Rule supervision, third part: reconciling stall observations with what happened, the evidence table, upgrade proposals and the person's answer (D88 rule 9 (b) and its 2026-11-12 revision; DEF-35)

Planner brief, 2026-11-12 (verifier). M3-06-3 made the stall rule observe; M3-06-3-2 gave it modes — a global default (initially `observe`) plus a per-Mission override, changed only from the desktop app — and the `notify` / `stop` tiers. D88 rule 9 (b) asks for the rest of the loop: every observation is later reconciled with what actually happened to its Attempt, the results add up to a read-only evidence table, and when the evidence is strong enough the system proposes to raise the global default one tier; a person accepts or dismisses. Henry fixed the bar on 2026-11-12: **at least 20 observations with a known outcome, at least 90% of them real stalls** (later timed out or failed, not passed verification).

## Outcome

After this Task, each stall observation (`observe` or `notify`) gets exactly one reconciliation audit once its Attempt's outcome is known — a hit, a false positive, or inconclusive — with the minutes that stopping it would have saved. `axiom.supervision.show` reports the evidence for the stall rule since the last global decision and in total. When that evidence reaches the bar, the system records one open proposal to raise the global default one tier, and a person accepts or dismisses it from the desktop app; accepting writes the new global revision.

## Deliverables

1. **Reconciliation.** A new module under `src/main/axiom/recovery/` runs after the cadence flush of every pass (`recovery-service.ts` gains the call and nothing else). It reads observations without a reconciliation, oldest first, at most 100 per pass, and for each decides:
   - **pending** (write nothing): the Attempt is current; or it submitted and its candidate has no PASS run while some run is not terminal (QUEUED, RUNNING, INCONCLUSIVE, SPECIALIST_REVIEW, HUMAN_REVIEW).
   - **false_positive**: its Submission's candidate has a PASS verification run.
   - **hit**: it ended without a Submission through `attempt.stopped { reason: 'timeout' }` or `attempt.failed` with `settlement.kind` `failed` or `unchanged`; or it submitted and its candidate has a FAIL run, no PASS run and no non-terminal run.
   - **inconclusive**: any other ending — `attempt.failed` with `interrupted`, `no_change` or `blocked`; `attempt.stopped` for any reason but `timeout` (the stall rule itself, `kernel_stopped`, cancellation); `attempt.abandoned`; a candidate whose runs are all CANCELED; a binding that is no longer current but shows none of these.
   It writes `attempt.supervision_reconciled { rule: 'stalled', mode, observationSequence, outcome: 'hit' | 'false_positive' | 'inconclusive', endedBy, endedAt, savedMs? }` on the same Attempt (through `auditAttempt`): `endedBy` names the deciding fact (`timeout`, `failed`, `unchanged`, `verification_pass`, `verification_fail`, `interrupted`, `declared`, `stopped`, `abandoned`, `canceled_runs`, `unknown`); `endedAt` is that fact's time in ISO (the ending audit, or the Submission for a verification outcome); `savedMs = max(0, endedAt − wouldActAt)` for a hit only. An observation is reconciled once; a failing read or write for one observation is logged and leaves it for the next pass without stopping the others.
2. **Evidence.** For the stall rule, the decision window starts after `max(the latest global revision's audit_sequence, the latest resolved proposal's through_sequence)` (0 when neither exists). Window evidence counts reconciliations with a higher audit sequence: `known = hits + falsePositives`, `inconclusive`, `hitRate = hits / known` (null when known is 0), `savedMs` (the sum over hits), `sinceSequence`, `throughSequence` (the highest counted). Totals over all reconciliations too. The read goes through the index on `audit_events(event, sequence)`.
3. **Proposals.** A new table `supervision_proposals` in `create-axiom-supervision-sql.ts`: `id TEXT PRIMARY KEY`, `rule TEXT NOT NULL`, `from_mode TEXT NOT NULL`, `to_mode TEXT NOT NULL`, `status TEXT NOT NULL` (`OPEN` | `ACCEPTED` | `DISMISSED` | `SUPERSEDED`), `evidence TEXT NOT NULL DEFAULT '{}'`, `since_sequence INTEGER NOT NULL`, `through_sequence INTEGER NOT NULL`, `resolver TEXT`, `created_at TEXT NOT NULL DEFAULT (datetime('now'))`, `resolved_at TEXT`, and a unique index on `rule` where `status = 'OPEN'` (at most one open proposal per rule); register it for the WSL mover and in the schema test's contract. Proposal rows are global; no trigger deletes them. After the reconciliation of each pass: when the global stall mode is not `stop`, no proposal is open, `known ≥ 20` and `hits / known ≥ 0.9`, insert one `OPEN` proposal from the current global mode to the next tier (`observe` → `notify` → `stop`) with the window evidence as its snapshot and `through_sequence` the highest counted reconciliation. The numbers are constants in one module, next to the stall constants.
4. **The answer.** `axiom.supervision.resolve { proposalId, resolution: 'accept' | 'dismiss' }` — `desktop_only`, a mutation, in the `axiom.supervision.` namespace. An unknown proposal id is `invalid_argument`; a proposal that is not `OPEN` is `illegal_transition`; nothing is written in either case. `accept` requires that the global mode still equals the proposal's `from_mode` (otherwise `stale_state`, nothing written); it appends a global revision with `mode = to_mode`, `actor: 'user'`, `provenance: { kind: 'proposal', proposalId }`, and marks the proposal `ACCEPTED`; `dismiss` marks it `DISMISSED`. Both set `resolver: 'user'` and `resolved_at`, in one transaction. A direct global change through `axiom.supervision.update` marks an open proposal `SUPERSEDED` in its own transaction. The response is the show view.
5. **Show.** `axiom.supervision.show` (and the update / resolve responses) gain, additively: `evidence: [{ rule: 'stalled', window: {…}, total: {…} }]` and `proposals` (the open proposal, if any, and the five most recent resolved ones, newest first: `{ id, rule, fromMode, toMode, status, evidence, sinceSequence, throughSequence, resolver, createdAt, resolvedAt }`); `globalSource` gains `proposal` (the latest global revision came from an accepted proposal).
6. **E2E** (host, verifier-run). `tests/e2e/mission-budget-stop-continuation.spec.ts` keeps its flow and title and adds: eventually Attempt 1 has exactly one `attempt.supervision_reconciled` with `outcome: 'hit'`, `endedBy: 'timeout'`, `mode: 'observe'`, `observationSequence` equal to its observation's sequence, `savedMs >= 0`. Nothing else changes in the spec or the fixture.
7. **Docs.** `docs/reference/control-plane.md` Supervision rules (reconciliation, the outcome table, the evidence window, proposals and the answer), `docs/GLOSSARY.md` (`attempt.supervision_reconciled`, the outcomes, the proposal statuses, the bar), `docs/reference/orca-mapping.md` (the new table and index, `axiom.supervision.resolve`).
