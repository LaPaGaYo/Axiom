# Task M3-09-2b-3 — Mission UI: a person adjusts or cancels a Task from the Task page (D70 ②, D78, D86 ③, STYLEGUIDE rule 4; renderer, plus one refusal in the main process)

Planner brief, 2026-11-13 (verifier). M3-09-2b-2 put the two review actions on the Task page. This part adds the two Task actions the pending view lists: **adjust** (add allowed paths, raise the Attempt limit or the token limit, or reopen with a rationale alone) and **cancel**. The rule is the same: an action is offered only when a pending item of the Task lists it. One main-process change rides along: `axiom.task.cancel` refuses a rationale that looks like a secret, as resolve, rerun and adjust already do — the page is the first place a person types that rationale. Replacing a Task's acceptance criteria is not in this part (Non-goals).

Read first: `AGENTS.md` (UI and Product Experience; Human Approval; Destructive Actions), `docs/STYLEGUIDE.md` (Components — Buttons, Form anatomy; UX rules 1, 3 and 4; "`destructive` is for actions that lose data or can't be undone"), `docs/GLOSSARY.md` §4.4a, `docs/reference/control-plane.md` (the table "M3-04b / D70 ② 的 Task 阻塞处置"; "人工 Task 调整（M3-04b；D70 ② / D78 / D85）"; "Task 页的人工处置与重验（M3-09-2b-2）").

## Outcome

On the Task page a person can do everything the Control Plane says a Task needs from them, and only that: besides the two review actions, adjust the Task — seeing its scope and limits, with the paths the Worker asked for already filled in and one line that says what resolves this block — or cancel it, after reading what that costs and confirming. Refusals are shown as the Control Plane words them and the form keeps what was typed. A cancellation's rationale can no longer put a secret into the audit.
