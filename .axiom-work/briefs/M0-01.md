# Task M0-01 — Vendor-egress ratchet (script + baseline + lint wiring + tests)

You are a Worker on the Axiom project (a product fork of Orca). Read `AGENTS.md`, `docs/PROJECT_CONSTITUTION.md` §3–§5 and `docs/reference/orca-mapping.md` §7 before touching code. Stay strictly within the scope below; anything else becomes a follow-up in your report.

## Objective

Add a CI ratchet that freezes every reference to the upstream vendor's identity and network endpoints in the codebase, so that milestone M0 ("fork isolation") can shrink that set to zero and CI fails whenever a NEW reference appears. Model it on the existing `config/scripts/check-ts-nocheck-ratchet.mjs` (baseline file, grandfathered occurrences, "the baseline may only shrink").

## Scope (allowed to create/modify)

- `config/scripts/check-vendor-egress-ratchet.mjs` (new)
- `config/scripts/check-vendor-egress-ratchet.test.mjs` (new; vitest, same style as `check-ts-nocheck-ratchet.test.mjs`)
- `config/vendor-egress-baseline.txt` (new; generated by the script's `--write-baseline` mode)
- `package.json`: add script `check:vendor-egress-ratchet` and insert it into the `lint` chain right after `check:runtime-electron-ratchet`. No dependency changes.
- Nothing else. Do not change any product code, branding, endpoint, or config value in this task.

## Behavior

1. Scan these roots (tracked files only — use `git ls-files`): `src/`, `config/`, `Casks/`, `mobile/` (excluding `mobile/node_modules`), `cloud/` (excluding `cloud/**/node_modules`), `resources/`, `skills/`, `skill-guides/`, `skill-stubs/`, `electron.vite.config.ts`, `package.json`, `orca.yaml`, `README.md`.
2. Flag these needles, case-insensitive, one finding per (file, line): `onorca.dev`, `orca.dev`, `stablyai`, `com.stablyai`, `com.stably.orca`, `posthog`, `orca-plugins`, `SignPath Foundation`, `signpath.io`. A line matches at most once per needle.
3. Ignore: the ratchet's own files, `config/vendor-egress-baseline.txt`, `docs/**`, `LICENSE`, `pnpm-lock.yaml`, binary files, and any line containing the exact marker `vendor-egress-ratchet: allow` (document this escape hatch in a comment; it is for lines that must legitimately mention the vendor, e.g. attribution).
4. Baseline format: one entry per line, `<repo-relative path>:<needle>:<count>` sorted; the count is the number of matching lines for that needle in that file. Line numbers are deliberately NOT stored so that unrelated edits don't churn the baseline.
5. Default mode: compare current findings with the baseline. Exit non-zero and print each NEW `(file, needle)` pair or any count that grew, with the offending lines. Print the pairs whose count shrank or disappeared as informational, and instruct the user to run `--write-baseline` to shrink it. A baseline entry whose count is now lower must NOT fail the check by itself (shrinking is allowed), but stale entries should be reported so the baseline gets tightened.
6. `--write-baseline` mode regenerates the baseline from the current tree. `--json` prints findings as JSON. Keep the script dependency-free (Node built-ins only), ESM `.mjs`, under the repo's max-lines limit, and typed via JSDoc where useful. No `@ts-nocheck`.
7. Run `--write-baseline` once so the generated baseline is part of your changes. Then confirm the default mode passes.

## Acceptance criteria

- `pnpm run check:vendor-egress-ratchet` exits 0 on the resulting tree.
- Adding a temporary line `const x = 'https://onorca.dev/x'` to any tracked `src/**` file makes it exit non-zero and name that file, that needle, and the line; a `// vendor-egress-ratchet: allow` marker on the same line suppresses it. Cover both with tests (use a temporary git-less fixture directory in the tests, or make the scanner accept an injected file list so tests don't depend on `git ls-files`).
- The baseline covers at least: `config/electron-builder.config.cjs`, `src/main/telemetry/client.ts`, `src/main/artifacts/artifact-cloud-config.ts`, `src/main/updater/updater-setup.ts`, `src/main/ipc/feedback-request.ts`, `src/main/orca-profiles/profile-cloud-auth-config.ts`, `src/main/plugins/plugin-kill-list-service.ts`, `src/shared/plugins/plugin-marketplace.ts`, `src/shared/agent-feature-install-commands.ts`, `Casks/orca.rb`, `mobile/app.json`. If any of these is missing from the baseline, explain why in the report (path moved? needle spelled differently?) rather than forcing it.
- `pnpm test config/scripts/check-vendor-egress-ratchet.test.mjs` passes.
- `pnpm tc:node` passes (the script is `.mjs`; this guards `package.json`/config typing only).
- `pnpm run check:code-quality:changed` passes.
- `pnpm lint` is NOT required in full (it is long); run only the pieces above.
