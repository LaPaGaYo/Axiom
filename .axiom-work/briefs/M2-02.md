## Objective

Two Control Plane services the Scheduler (M2-04), the attempt-launcher (M2-05) and the submission path (M2-07) will build on:

1. **ArtifactStore** — content-addressed files under `<userData>/axiom/artifacts/<sha256>` with metadata rows in `artifacts` (the database stores references and hashes only; large content never goes into SQLite), exposed as `axiom.artifact.put / read / list` and `axiom mission artifact put | read | list`.
2. **ContextBuilder** — turns a Task into a reproducible `ContextPackage`: a deterministic mandatory set, a ranked candidate set cut to a token budget, a canonical manifest whose sha256 is the package id, and a rendered Worker prompt **template** (the Attempt id and dispatch capability are filled in at delivery time by M2-05). Same inputs → same id, every time.

- The artifact root: `path.join(getAppEnvironment().getPath('userData'), 'axiom', 'artifacts')` — compute it in `src/main/axiom/control-plane.ts` when creating the plane and inject it into `ArtifactStore`'s constructor (tests inject a temp dir; never call `getAppEnvironment()` from the store itself).
- Content addressing: `sha256` of the bytes names the file (`<root>/<sha256>`; write to `<root>/.tmp-<random>` then `rename`, so a crash never leaves a half file under its final name; writing an existing sha is a no-op). The row id is `art_<sha256 of canonical JSON {missionId, kind, sha256}>` (so re-putting the same content for the same Mission and kind is idempotent and returns the existing row; the same bytes under another kind get another row but share the file). `read` re-hashes the file and fails with `artifact_corrupt` if it does not match the row. Size cap for the RPC path: 8 MiB (`invalid_argument` beyond).
- Reading repository rules for the context: the Mission row has `repoPath` and `targetBranch`; read `AGENTS.md` and `CLAUDE.md` **at the target branch** with `gitExecFileAsync(['show', `${targetBranch}:AGENTS.md`], gitOptionsForWorktree(repoPath))` (missing file → omitted, not an error); cap each at 16 KiB; never read `.env*` or anything outside those two names.
- Mission policy: `verificationRules` is `Record<string, json>` (`PolicySchema`, `src/shared/axiom-contract/mission-objects.ts`); treat `verificationRules.commands` as `string[]` when present (zod-parse it; absent → the section says "none configured"). `budget` and `concurrencyLimit` come from the same policy; the Task's `retryPolicy`, `scope.allowedPaths`, `acceptanceCriteria`, `requiredEvidence`, `risk` come from `task_stages.spec` (`TaskSpecSchema`).
- Token estimate: `Math.ceil(utf8Bytes / 4)` — one function in the builder; no dependency.
- D16 Worker verbs (M2-06 implements them; M2-02 only renders the recipe): `axiom attempt submit | ask | blocked | handoff | inform | request | request-subtask | check`, every call carrying `--attempt <attemptId> --dispatch-capability <capability>`; the artifact verb for Workers is `axiom mission artifact put --mission <id> --kind <kind> --file <path> --related <taskId>` (this Task).
- Registration: five steps per AGENTS.md (params in `src/shared/axiom-contract/artifact-params.ts`; `src/main/runtime/rpc/methods/axiom/artifact.ts` aggregated into `AXIOM_METHODS`; `axiom.artifact.put` added to `AXIOM_MUTATION_METHODS` in `src/shared/axiom-contract/mutations.ts`; regenerate the catalog with `node config/scripts/generate-rpc-params-catalog.mjs`; CLI spec `src/cli/specs/axiom-mission.ts` gains the `mission artifact put | read | list` sub-group like `mission goal …`, handler in `src/cli/handlers/axiom/`).
