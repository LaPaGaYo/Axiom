## The application (keep it boring and complete)

FlowTask manages projects and tasks for one user on one machine.

- **Domain** (`src/domain/`): `Project` (id, name, archived), `Task` (id, projectId, title, description, status `todo|doing|done|canceled`, priority `p1..p4`, dueDate (ISO date or null), tags, `blockedBy` task ids, createdAt/updatedAt, recurrence rule or null), `Tag`, `Recurrence` (daily / weekly on weekdays / monthly on day-of-month / every N days; next occurrence generated when a recurring task is completed), `ActivityEvent` (append-only log of changes), `SavedView` (named filter + sort), validation errors as typed `Result`-style values, not thrown strings.
- **Storage** (`src/storage/`): `Repository` interface; `JsonFileRepository` (one JSON file, schema-versioned with a `version` field and an explicit migration step from v0 → v1 so a migration exists to test); `MemoryRepository` for tests.
- **Services** (`src/services/`): create/update/complete/cancel task (completing a recurring task schedules the next one), dependency rules (cannot complete a task whose `blockedBy` tasks are not done; cycles rejected), scheduling (`ready` tasks = not blocked, sorted by priority then due), overdue detection (clock-based), tag operations, project archive (with open tasks → rejected), activity log queries, saved views, import/export (JSON and CSV, round-trip tested), reports (counts by status, overdue list, upcoming-7-days, completion-per-day over a range, dependency graph as text).
- **CLI** (`src/cli/`, binary `flowtask`, built to `dist/cli.js`): `node:util.parseArgs`; commands `init`, `project add|list|archive`, `task add|list|show|update|done|cancel|block|unblock`, `tag add|rm|list`, `view save|list|run`, `export`, `import`, `report <name>`, `serve`; global `--data <file>`, `--json` (machine-readable output), `--now <iso>` (clock injection for determinism); exit codes 0 / 2 (usage) / 3 (domain error) / 4 (storage error); human output is plain tables, no colors, no spinners.
- **HTTP API** (`src/api/`, `node:http` only, JSON, built to `dist/server.js`): `GET /health`, CRUD for projects, tasks, tags, views; `POST /tasks/:id/done`; `GET /reports/:name`; `GET /export`, `POST /import`; one file per route; consistent error envelope `{ error: { code, message } }`; `X-FlowTask-Now` header for clock injection in tests.
- **Docs**: `README.md` (what it is, that it is a frozen acceptance fixture for Axiom, how to run the checks), `docs/ARCHITECTURE.md` (module map, invariants, data format), `docs/CLI.md`, `docs/API.md` — hand-written, short, accurate.

Keep the module graph acyclic (`domain` ← `storage` ← `services` ← `cli`/`api`). No global mutable state. `tests/integration/` uses `tests/helpers/` to spawn `dist/cli.js` and `dist/server.js` with a temp data directory and the injected clock.
