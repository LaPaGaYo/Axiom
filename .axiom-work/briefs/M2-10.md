## Objective

1. **Task Detail** (new, inside the Missions view): selecting a row of the Tasks table opens a detail section for that Task with (a) its Attempt list — one row per `attempt_bindings` row from `axiom.attempt.list({ missionId, taskId })`: seq, branch, provider, `state`, `liveness` (+ `livenessReason` when not `live`), workspace (`retained` / `released` / `pending`), created / updated; (b) the Submission summary of the latest submitted Attempt — Candidate commit (short sha, full in a title attribute) and tree, files changed, checks run (command / result / note), limitations, risks, follow-ups, created-at; (c) a typed message timeline for the Task (`axiom.message.list({ missionId, taskId })`, newest last): type badge, attempt seq, summary, created-at; QUESTION rows that are `pending` get an inline answer form (`axiom.message.answer`), REQUEST_SUBTASK rows that are `pending` get Accept / Reject with a rationale field (`axiom.message.resolve`). The timeline is DEF-6 ②'s minimal form: one list, no tabs; terminal output, diffs and Artifacts stay drill-downs (link the Attempt's `worktreeId` to the existing worktree selection when one is set — `useAppStore.getState().selectWorktree?`-style actions already exist for the sidebar; if none is reachable from the missions slice, render the id as text and note it in the report).
2. **Mission Home**: the Progress block adds RUNNING / SUBMITTED Attempt counts (from `axiom.attempt.list({ missionId })`, Attempts whose `state` is `RUNNING` / `SUBMITTED`, Workers only); the Pending items block lists open QUESTIONs and REQUEST_SUBTASKs across the Mission (`pendingOnly: true`) with a count and a jump to the owning Task's detail; a "Planner in progress" line appears while a planner Attempt (new `role: 'planner'` on `AttemptSummary`, see 3) is `STARTING` / `RUNNING`.
