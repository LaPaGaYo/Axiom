## Objective

Implement the eighth verb and the only path from `RUNNING` to `SUBMITTED`:

1. **`axiom.attempt.submit`** (mutation, receipts) — after the M2-06a authority check (`resolveAttemptSender`: `unknown_dispatch | inactive_dispatch | stale_dispatch | dispatch_capability_invalid | sender_not_assignee`, no state change), validate the Submission report against the contract, **fix the Candidate identity on the Control Plane side** (D4: snapshot commit on the Attempt worktree, or adopt `HEAD` when clean), then in one `runLifecycleWriteTransaction` write `candidates` (new `ACTIVE`, the Task's previous `ACTIVE` → `SUPERSEDED`), `submissions` (immutable, `dispatch_id UNIQUE`), the `artifact_git` observation facet, call `db.settleWorkerReportInTransaction({ taskId, dispatchId, outcome: 'succeeded', result })` (a `rejected` result rolls everything back and surfaces its code), move the stage `RUNNING → SUBMITTED`, retain the worker's terminal resource (`db.retainWorkerTerminalResource`), enqueue a `verification_runs` row `QUEUED` (verifier `VerificationService`, M3 consumes it), audit `attempt.submitted`, then persist the `SUBMISSION` typed message (M2-06a router) — the stage trigger reschedules.
2. **Idempotency**: a second `submit` for the same Attempt returns the existing Submission (`duplicate: true`), no new Candidate; `--retry-request` replays the recorded receipt.
3. **CLI** `axiom attempt submit --attempt <id> --dispatch-capability <dcap> --report <path.json> [--json]` where the JSON is the full contract (summary, filesChanged, checksRun[], artifacts[], limitations[], risks[], questions[], followUps[]) — the Worker's `REPORT.md` is attached as an Artifact first (`axiom mission artifact put --kind worker_report`), its id goes into `artifacts`.
4. **Host e2e extension**: the D49 test provider, after acking the preamble, runs the fixture stub Worker and submits; `mission-attempt-launch.spec.ts` (or a new `mission-attempt-submit.spec.ts`) asserts three `SUBMITTED` Tasks, three `ACTIVE` Candidates whose `commit_sha` exist on the attempt branches, three Submissions, three `QUEUED` VerificationRuns, and that a forged second submit from a different pane is rejected without change.
