# Task M0-05b-1 — Product name in the app and CLI: "Orca" → "Axiom" in user-visible strings, keys stable, translations kept

You are a Worker on the Axiom project (a product fork of Orca). Read `AGENTS.md` (including the Lazy Senior Dev Mode section), `docs/PROJECT_CONSTITUTION.md` §3–§5 and Decisions D13, D21, D31, D32 in `docs/decisions/DECISION_LOG.md` before touching code. Stay strictly within the scope below; anything else becomes a follow-up in your report.

## Objective

Every string a user can read in the desktop app or the CLI names the product **Axiom**, never Orca. This is a *text* task: identifiers, file names, environment variables, skill names, the daemon name and test fixtures do not change.

The localization keys are stable identifiers (`auto.<file>.<sha1>` hashes are only computed for *new* strings by `config/scripts/localize-renderer-strings.mjs`; existing `translate(key, default)` calls keep their key whatever the default says). Therefore the right shape is: change the call-site default **and** the catalog values together, keys untouched. That keeps every translation (the brand word is Latin in all six catalogs — replace it inside the translated values) and avoids any growth of the runtime-required catalog. The verifier checks that `config/scripts/verify-localization-extraction.mjs` reports **no new fallback drift** (en.json value ≠ call-site default).

## Rules of replacement

- Replace the brand word only where it is user-visible text: `translate(...)` defaults, JSX text, `aria-label`/`title`/`placeholder` literals, dialog/notification/menu/toast/tray strings in `src/main`, CLI help/spec/usage/error strings in `src/cli`, and catalog **values** in the six locale files.
- Forms: `Orca` → `Axiom`; `Orca's` → `Axiom's`; the product-as-command `orca`/`orca-dev` inside copy → `axiom`/`axiom-dev` (the CLI was renamed in M0-02); `orca://` is already done.
- Never change: identifiers and symbols (`OrcaRuntime`, `orcaStore`, `useOrca…`, `ORCA_*` env vars — D13), import paths and file names, catalog **keys**, `data-testid` values, CSS classes, skill names (`orca-cli`, `orca-linear`, `orca-per-workspace-env`, `orca-marketplace.json`), the daemon name `orcad`, telemetry/log event names and logger lines, test fixture data under `__fixtures__`, upstream attribution text (README, NOTICE), anything under `docs/`, `skills/`, `skill-guides/`, `resources/` (M0-05b-2), `mobile/`, `cloud/`.
- Do the bulk with a throwaway script that only touches string literals / JSX text / catalog values and prints every changed line for your review; then read the diff file by file. Do not keep the script in the tree.

## Scope (allowed to modify)

1. `src/renderer/src/**` (non-test files) — user-visible string literals as defined above.
2. `src/renderer/src/i18n/locales/{en,es,fr,ja,ko,zh}.json` and `src/renderer/src/i18n/en-runtime-required.json` — values only; regenerate the runtime-required catalog with `pnpm run sync:localization-runtime-catalog` after the value edits (it must not grow).
3. `src/cli/**` (non-test) — help, specs, usage and error strings.
4. `src/main/**` (non-test) — strings that reach the user: `dialog.showMessageBox*`, `Notification` titles/bodies, menu and tray labels, toasts, update/install prompts, error messages returned to the renderer or CLI. Not logs, not telemetry event names, not identifiers.
5. `src/shared/**` (non-test) — shared user-facing copy (e.g. error messages, labels) only.
6. Tests that assert the old strings — update expectations; do not delete or skip tests.
7. `config/vendor-egress-baseline.txt` — regenerate last (the ratchet needles do not include the brand word, so it should not change; report if it does).
