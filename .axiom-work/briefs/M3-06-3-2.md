# Task M3-06-3-2 — Rule supervision, second part: stall modes (global default + per-Mission override) and the stall rule's `notify` / `stop` tiers (D88 rule 9 and its 2026-11-12 revision; D60 / D68 revision rows)

Planner brief, 2026-11-12 (verifier). M3-06-3 put a supervision step into recovery's reconcile pass: the runtime limit acts as the `timeout` rule (`auto`, a human set it), and a headless Attempt whose events file has been silent longer than the stall threshold gets one "would have" observation (`observe`) and keeps running. Henry decided on 2026-11-12 how the stall rule's mode is chosen: **a global default plus a per-Mission override**, both set only by a person; the global default starts at `observe`. D88 rule 9 fixed the tiers above `observe`: the stall rule's first automatic action is a pending item (`notify`), the next one is the stop (`stop`). The remaining work of M3-06-3-2 is split in two:

- **M3-06-3-2 (this Task)**: where the modes live and how they are read and changed; the `notify` and `stop` tiers of the stall rule.
- M3-06-3-2b: reconciling each observation with what happened later, the per-rule evidence table, the proposal to raise the global default (at least 20 observations with a known outcome, at least 90% real stalls), and the person's answer to it.
- M3-06-3-3: the token budget.

## Outcome

After this Task a person can set the stall rule's mode for all Missions (the global default, initially `observe`) and override it for one Mission, from the desktop app only; every change is kept as a revision. The supervision step reads the Mission's effective mode on each pass. In `observe` it behaves as today; in `notify` it writes one stall notification per Attempt and changes nothing else, and the read RPC lists the notification as long as its Attempt is current; in `stop` it stops the silent Attempt the way the `timeout` rule stops an Attempt over its runtime limit — stop, confirm, preserve, settle as a counted failure with the reason `stalled` — and the successor continues from the preserved work.

Rows are only inserted, never updated; the current value of a scope is its highest revision. `provenance` and `audit_sequence` are written now because a later column would need a schema version: M3-06-3-2b counts evidence only after the latest global decision (`audit_sequence`) and records an accepted proposal in `provenance`.

5. **The effective stall mode.** For a Mission: its latest override revision if that mode is not `NULL`, else the latest global revision, else `observe`. Read on every pass in which the stall rule needs it; no cache across passes (a person's change takes effect on the next pass).
6. **The `notify` tier.** When the effective mode is `notify` and the silence exceeds the threshold, write once per Attempt `attempt.supervised { rule: 'stalled', mode: 'notify', thresholdMs, thresholdSource, idleMs, lastEventAt, wouldActAt }` (the observation's fields) — nothing else changes: no stop, no stage, no message, no effect. The "once" lookups of `observe` and `notify` are per Attempt **and mode** (an Attempt observed under `observe` is still notified once after the Mission switches to `notify`). `axiom.supervision.show` lists, as `notifications`, every `notify` row whose Attempt is still the running, unsubmitted latest Attempt of its Task: `{ missionId, taskId, seq, attemptId, idleMs, thresholdMs, thresholdSource, lastEventAt, notifiedAt }` (`notifiedAt` = the audit's time), oldest first. When the Attempt stops being current, the item is gone from the list; the audit stays.
7. **The `stop` tier.** When the effective mode is `stop` and the silence exceeds the threshold, stop the Attempt through the same sequence as the timeout rule (ground truth 1): the kernel stop, the worker row re-read, the capture for a `stopped` receipt, the same fence; then one transaction writes `attempt.supervised { rule: 'stalled', mode: 'stop', thresholdMs, thresholdSource, idleMs, lastEventAt, action: 'stopped' | 'stop_unknown' }`, then for `stopped` `attempt.stopped { reason: 'stalled' }`, `attempt.preserved` when captured and the settlement with reason `stalled` (counts toward `maxAttempts`, NEEDS_FIX → READY / BLOCKED as for `timeout`); for `stop_unknown` `attempt.stop_unknown { reason: 'stalled' }` only. An earlier `observe` or `notify` row of the same Attempt does not prevent the stop. Order inside the step: the stall rule first; when it stops the Attempt, the timeout rule is not evaluated in that pass; when it does not, the timeout rule runs as today. The timeout path is unchanged, including its transaction name. Share the stop sequence between the two rules instead of copying it (e.g. one function that takes the rule's facts); new logic goes into new modules under `src/main/axiom/recovery/`.
