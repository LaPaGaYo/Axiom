# Task M3-06-2c — In-place continuation for Codex: the next Attempt takes over the interrupted Attempt's worktree and resumes its session (D88 revision row of 2026-11-11, items ① ② ④ ⑤ ⑥)

Planner brief, 2026-11-11 (verifier). Since M3-06-2b, an Attempt that was interrupted from outside (a usage limit, an expired login, a restart) is preserved as an immutable snapshot and the next Attempt continues from that snapshot — in a **new** worktree and a **new** harness session that has to read everything again. **Henry decided on 2026-11-11 (D88 revision ①) that, when the process exit has hard evidence and the worktree still equals the snapshot, the next Attempt instead takes over the previous Attempt's worktree and resumes the original harness session ("原地续", in-place continuation); everything else keeps the merged behaviour (②); a resume the harness refuses does not count toward the three in a row and the next Attempt immediately uses a new session (④); there is no session-length threshold (⑤); and in V1 this is built for Codex only (⑥, Claude is DEF-50).** Two host probes of 2026-11-11 answered what the brief needed (ground truth 3 and 4). This Task implements exactly that and nothing else.

## Outcome

After this Task, when a headless Codex Attempt was interrupted from outside, its exit has hard evidence (an accepted exit marker, or a restart in which the host saw the process exit), its worktree still equals what it left, and nothing about the agent, the account, the harness version, the Task contract or the session record has changed, the next Attempt **runs in that same worktree, on its own branch at the preserved commit, and resumes the same Codex session** with a short continuation prompt; the full, current contract lies in `.axiom/prompt.md` as today. In every other case the next Attempt starts exactly as on main — a new worktree from the baseline and a new session — and the launch audit says which rule decided. A resume Codex refuses ends that Attempt at once without waiting and without counting toward the three in a row, and the next Attempt starts at once in a new worktree with a new session.

## Deliverables

1. **The decision** (new modules under `execution/`; pure rules over evidence gathered by small read-only adapters; it never throws, never makes a launch fail and never delays it beyond its own bounded reads). It runs in the launcher after `resolveAttemptBaseline` and **before any worktree is created**, for a headless worker Attempt with seq > 1, and answers either `resumed_in_place` — with the previous worktree, the thread id, the session's origin seq and the commit to move to — or `fresh` with exactly one reason: the first rule that fails, in this order:
   - `not_interrupted` — Attempt N−1 has no `attempt.failed` with `settlement.kind: 'interrupted'`, or it has an `attempt.stopped` or a Submission (stopped, failed and submitted predecessors, including the fix loop after a verification failure, always get a new session — D88 ②, ⑤).
   - `resume_refused` — Attempt N−1's `attempt.failed` has `reason: 'resume_refused'` (deliverable 6; D88 ④).
   - `no_exit_evidence` — N−1's `attempt.failed` is neither the exit path's (`evidence: 'exit_code'` with an integer `exitCode`) nor recovery's host-observed exit (`reason: 'process_exited'`, `evidence: 'runtime_restarted'`). The daemon-loss ending (`reason: 'terminal_missing'`) ends here (D88 ②).
   - `snapshot_unusable` — N−1 has no `attempt.preserved`, or it is `unavailable`, or it is `preserved` but not usable (`baseline` is not a `snapshot` with `previousSeq` N−1 — a secret, a path outside the current scope); `empty` passes.
   - `agent_changed` — N's AgentSpec differs from N−1's in `provider`, `model` or `reasoning.effort`.
   - `capability_unproven` — the certified combination of this provider has no session-resume record (deliverable 2) covering the harness version this launch will report (the same cached probe and the same binary resolution as `buildHeadlessWorkerCommand` — share them, do not copy them).
   - `account_changed` — the account home of this launch (`runtime.resolveCodexHomeForWorkerLaunch()`, added as an optional member of the launcher's runtime type; absent → `evidence_unreadable`) is not the home `readAttemptAccount` returns for N−1.
   - `contract_changed` — N's and N−1's manifests differ in `planRevisionId`, or do not list the same sections in the same order, or any section other than `Previous-Attempt failure evidence` has another `sha256` (an answered question or a changed repository rule counts as a change). N−1 passed the same rule at its own launch when it was itself resumed, so the comparison reaches back to the prompt the session began with.
   - `session_unknown` — no well-formed thread id (the regex of ground truth 8) for N−1: its `attempt.failed.providerSessionId`, else the first `thread.started` within the first 64 KiB of N−1's host-captured `events.jsonl`; when N−1 was itself launched `resumed_in_place`, the id counts only if it equals the id that launch asked for.
   - `session_record_missing` — no `rollout-*-<thread id>.jsonl` **or `.jsonl.zst`** exists in the account home's day directories from the origin Attempt's dispatch `created_at` until now (the bounded lookup of ground truth 8, generalized and shared, not copied).
   - `worktree_changed` — N−1's launch record is unusable, or the worktree directory is gone, or it is not on N−1's branch, or its HEAD and its private-index tree (`withWorktreeSnapshot`, unchanged) are not what N−1 left: for a `preserved` N−1, HEAD = the snapshot's parent commit and tree = `snapshot.treeSha`; for an `empty` N−1, HEAD = N−1's `baselineSha` and tree = that commit's tree, and in that case the commit of `attemptBaselineRef(baseline)` must also be N−1's `baselineSha` (a moved integration branch ends here). A worktree that is already on N's branch at the target commit with that tree (an earlier launch of this same Attempt took it over and did not finish) passes.
   - `evidence_unreadable` — anything above could not be read or timed out (bound the git work by the preservation timeout).
   `originSeq` is N−1, or N−1's own `originSeq` when N−1 was itself `resumed_in_place`. The target commit is the snapshot's commit for a `preserved` N−1 and N−1's `baselineSha` for an `empty` one — in both cases the commit of `attemptBaselineRef(baseline)`.
