# Task M3-04c — Human actions only from the desktop app, the agent-session second layer, V1 dependency threshold, retired-term test (D78, D69 revision, fix plan ⑥)

You are a Worker on the Axiom project (a product fork of Orca). Read `AGENTS.md` (Integration and Promotion, Human Approval, Authoritative Sources by Topic), `docs/plans/M3.md` (the M3-04c row, exit criterion 11), `docs/decisions/DECISION_LOG.md` **D78**, **D73**, the **D69** revision of 2026-10-25, `docs/reference/control-plane.md`, then the code named below.

Today every `axiom.*` method is `permission: 'workspace'`, and Orca treats an unstamped local call as owner, so a Worker's own `axiom` CLI can approve plans, change policy, answer its own Questions and accept its own subtask requests — and the audit records a human. D78 fixes this: decisions that belong to a human are accepted only from the desktop app's own IPC caller. This Task also makes V1 accept only `INTEGRATED` dependencies (D69 revision) and adds a test that keeps retired terms out of the current docs. No schema migration, no renderer change, no new dependency.

## Objective

1. **Caller classes** — new module `src/main/axiom/authority/caller-authority.ts`:
   - `AXIOM_METHOD_CALLER_CLASS: Record<string, 'desktop_only' | 'attempt' | 'read'>` covering **every** registered `axiom.*` method:
     - `desktop_only`: `axiom.mission.create / plan / start / pause / resume / cancel`, `axiom.goal.propose / activate`, `axiom.plan.approve / reject`, `axiom.policy.update`, `axiom.task.create / cancel`, `axiom.message.answer / resolve`;
     - `attempt`: the eight `axiom.attempt.*` Worker verbs in `AXIOM_ATTEMPT_CALLER_METHODS`; `axiom.plan.propose` and `axiom.artifact.put` are **`attempt` when the params carry `attemptId`, `desktop_only` otherwise** (express this with a small resolver function, not two table rows);
     - `read`: `axiom.artifact.read / list`, `axiom.attempt.show / list`, `axiom.goal.show`, `axiom.message.list`, `axiom.mission.show / list`, `axiom.plan.show / list`, `axiom.policy.show`, `axiom.task.list / show`, `axiom.verification.show / list`.
   - A unit test enumerates the method names actually registered (`AXIOM_METHODS` from `src/main/runtime/rpc/methods/axiom.ts`) and fails when one is missing from the table or the table names a method that does not exist — a new method cannot ship unclassified.
2. **Enforcement** — `assertAxiomCallerAuthority(method, params, ctx)` in the same module, called from the dispatcher right beside the existing `assertAttemptRequestAuthority` call in `invokeUnary` (`src/main/runtime/rpc/dispatcher.ts` ~line 205; that point already runs for both dispatch paths and before receipt replay). For a `desktop_only` class: `ctx.caller?.kind !== 'desktop'` → throw `OrchestrationError('caller_not_desktop', 'Make this decision in the Axiom app; human actions are not accepted from the CLI or an agent session.')`. `ctx.caller` is stamped by the transport (`rpc-caller-identity.ts`; the desktop renderer arrives over `runtime:call` IPC as `{ kind: 'desktop' }`, every terminal CLI as `local-cli`); a missing caller is refused. When the request's host-resolved session (`ctx.orchestrationCaller`) maps to a dispatch with an Axiom `attempt_bindings` row, write an audit event `authority.refused` (`{ method, callerKind, attemptId }`) against that Attempt's Mission and Task before throwing; otherwise only refuse. The dispatcher change is additive and at most a few lines.
3. **Agent-session second layer** (misuse guard, not the boundary — D78 ④): in the same hook, when `ctx.orchestrationCaller` maps to an Axiom Attempt / Planner / Reviewer dispatch, refuse with `caller_not_permitted_for_agent`: methods whose declared `permission` is not `'workspace'` (pass `method.permission` from the dispatcher), `agentSession.respondToApproval`, `agentSession.respondToQuestion`, and the Orca orchestration methods that create Runs or start workers (`orchestration.runCreate`, `orchestration.dispatch`, `orchestration.workerStart`, `orchestration.taskCreate`). First establish, with a test, for which methods the host resolves `ctx.orchestrationCaller` when the CLI runs inside an agent session (`orchestration-session-caller.ts` validates the injected session id on every request but binds a caller only for the methods it lists) and state the coverage in the report; methods the host cannot attribute are left to the sandbox posture (D63) — do not invent a second identity mechanism.
4. **`axiom.artifact.put` bound to its Attempt**: `ArtifactPutParams` gains optional `attemptId`; with it, the call is an `attempt` call verified by `resolveAttemptSender` (add the method to `AXIOM_ATTEMPT_CALLER_METHODS` only if that is how `assertAttemptRequestAuthority` must see it — keep `plan.propose`'s "no `attemptId` → not an attempt call" behaviour for both), and the handler sets `createdBy` to `attempt:<attemptId>` and adds the Attempt's Task and Attempt ids to `related` (ignoring caller-supplied `createdBy`); without `attemptId` it is `desktop_only`. CLI: `axiom mission artifact put` gains `--attempt <id>`; update the help text in `src/cli/specs/axiom-attempt.ts` ("Attach REPORT.md first with axiom mission artifact put --attempt <id> --kind worker_report …") and the Worker contract in `src/main/axiom/context-builder/render.ts` wherever it shows that command.
5. **Human-action provenance**: the handlers that write `kind: 'user'` / `actor: 'user'` / `resolver` (plan approve / reject, policy update, task cancel, question answer, goal lifecycle) stay as they are — after step 2 only the desktop app reaches them. Do not add a provenance field or change a schema for this.
