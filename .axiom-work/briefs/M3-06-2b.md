# Task M3-06-2b — Preserve the worktree of an Attempt that ended without a Submission, and continue from it (D88 items 1, 2, 3, 7; D64 revision row of 2026-11-09)

Planner brief, 2026-11-10 (verifier). M3-06-2a made an interrupted Task wait instead of burning a retry; the Attempt that follows still starts from scratch, and everything the interrupted Worker had written is lost. **This Task preserves the worktree as an immutable commit before the exit is settled, starts the next Attempt from that commit and tells it — from host-picked real records, not a model summary — what it inherited and why the previous run ended.** Scope of this brief: the headless exit path (`interrupted` and `failed`). The two recovery-side endings (runtime-budget stop, process exit found by recovery) are M3-06-2b-2; resuming the harness session is M3-06-2c; supervisor rules are M3-06-3.

## Ground truth (verifier, 2026-11-10, main `2e67b15055`; every function named here was read in full unless marked)

1. **How a headless Attempt ends without a Submission.** `execution/attempt-exit-submission.ts` `submitExit` (async; serialised per Attempt by `submitExitedAttempt`) parses `launch.json` (`HeadlessLaunchSchema`: `baselineSha` — HEAD of the fresh worktree, written by the host at launch —, `worktreeId`, `branch`), resolves the worktree path, checks worktree and branch against the kernel worker row and the binding, reads `events.jsonl` after the exit marker and, for a non-zero exit, a failed turn or an unparsable report, returns `settleHeadlessExitFailure(runtime, { attemptId, provider, eventsText, events, exitCode, lastMessage, reportError, eventAudit })` (`execution/attempt-exit-failure.ts`, 117 lines, async, its only caller). That function classifies, for a Codex usage limit awaits the rollout reader (M3-06-2a-3), then runs one transaction `headless_exit_failure`: `resolveHostAttempt` (authority is resolved again inside), `failDispatch`, audit `attempt.failed` (`after`: `taskId`, `exitCode`, `settlement.kind` `interrupted | failed`, `failure`, `lastError`, `lastMessageExcerpt`, `reportError`, `providerSessionId`, usage fields), then `settleInterruptedAttempt` or `settleAttemptWithoutSubmission`. Nothing looks at the worktree. A Codex Worker that is cut off writes no final message file, so `lastMessageExcerpt` is empty exactly when it would matter.
2. **Nothing is destroyed afterwards.** `scheduleFailedWorkerRelease` releases the terminal only. The worktree, its branch `axiom/attempt/<taskId>/<seq>` and `<userData>/axiom/attempts/<attemptId>/events.jsonl` stay.
3. **Turning a headless worktree into an immutable commit exists once, in Axiom.** `execution/candidate-snapshot.ts` `snapshotCandidate({ …, headless: true })`: asserts HEAD is the Attempt branch, builds a tree through a private index (`GIT_INDEX_FILE` in a temp directory; `read-tree HEAD`; `add -A -- . :(exclude).axiom`; `rm -r --cached --ignore-unmatch -- .axiom`; `write-tree`), and when that tree differs from HEAD's: `commit-tree -p HEAD` with an empty hooks directory and a fixed identity, then **moves the Attempt branch** (`update-ref refs/heads/<branch> <commit> <parent>`). Tests: `candidate-snapshot.test.ts`, `candidate-headless-snapshot.test.ts`. The Orca kernel has no such routine (no `commit-tree`, no private index outside `src/main/axiom`); it does keep commits under hidden refs of its own (`refs/orca/rebase/<uuid>`, `refs/orca/merge-requests/…`).

## Outcome

After this Task, when a headless Worker exits without a Submission, the host first preserves what it left in the worktree, and the next Attempt of that Task starts in a worktree that already contains it — told which Attempt ended how, what it changed, what it last said and ran, and to review before continuing. If the preserved tree is empty, leaves the Task's allowed paths, contains a secret or could not be taken, the next Attempt starts where it starts today, and the audit says why. A preserved snapshot is never a Candidate: the final Candidate goes through independent verification exactly as before.

## Deliverables

1. **Preserve** (new module under `src/main/axiom/execution/`; async; never throws). Input: Attempt, Task, seq, Mission, the launch record (worktree path, branch, `baselineSha`), the Task's allowed paths and the policy's verification rules. (a) The same branch assertion and private-index tree as the headless Candidate snapshot — share that routine by extracting it, do not copy it; `snapshotCandidate` keeps its behaviour and its two test files stay untouched. (b) That tree equals the tree of `baselineSha` → `empty`; no commit, no ref. (c) Otherwise one new commit: that tree, parent = the worktree's HEAD, message `axiom: preserved snapshot <attemptId>`, hooks disabled and identity as the Candidate snapshot. (d) Publish it as `refs/axiom/preserved/<taskId>/<seq>` with a create-only `update-ref`. **The Attempt branch, the worktree's HEAD, its own index and its files are not touched.** If that ref already exists: a commit carrying this Attempt's message is the preserved snapshot (a settlement replayed after a crash) and is used as it stands; any other commit there → `unavailable`. (e) `readCandidateDiff` for the preserved commit → the changed paths against the integration merge-base (what verification will judge) and the secret findings `evaluateDiffGate` reports for that diff; an unavailable or incomplete diff → `unavailable`. (f) The kernel change list `baselineSha..<preserved>` (ground truth 8) → what this Attempt itself changed, with line counts. Result, one of: `preserved` (ref, commit, tree; scope paths sorted, at most 200 — more is `unavailable`; secret findings as `{ path, pattern }`, never the matched text; this Attempt's own changes, at most 200 entries), `empty`, `unavailable` with a reason (worktree missing, branch mismatch, ref conflict, git failure or timeout, diff unavailable or incomplete, too many paths) and, when the commit already exists, its ref and sha. Failure semantics: every error becomes `unavailable`; settlement never fails, retries or waits because of it; nothing is deleted or reset.
2. **Records** (new module; pure; never throws). From the Attempt's own `eventsText`, by provider (ground truth 9): the last 5 agent messages (each at most 1,000 characters, tail kept) and the last 20 shell commands with their outcome (command at most 300 characters; exit code for Codex, error flag for Claude; the last 300 characters of output; a command without a completion is marked as unfinished when the stream ended). Malformed lines are skipped; other tools and item kinds are ignored. Everything passes `redactContext`. The bounds are named constants in one place (as `interruption-policy.ts` holds the ladder); no Policy key.
3. **Settle with the result.** `settleHeadlessExitFailure` gathers deliverables 1 and 2 **before** the `headless_exit_failure` transaction (nothing is awaited inside it), for both settlement kinds. When the result is `preserved` or there is at least one record, it stores one Artifact before the transaction: a typed JSON document with the messages, the commands and this Attempt's own changes; kind `log`, `application/json`, created by `AttemptSettlement`, related to the Task and the Attempt — never to a Submission, and never kind `handoff` or `worker_report` (ground truth 9: those travel to other Tasks; D88 item 8). A store failure means no Artifact, not a failed settlement. Inside the transaction, next to `attempt.failed`, it writes an audit `attempt.preserved` (actor `AttemptSettlement`, object = the Attempt): Task, the result of deliverable 1 without the own-changes list (status, reason, snapshot, scope paths, secret findings), `baselineSha`, and the Artifact id when there is one. Both rows come from the same transaction or neither does. No other path writes that audit in this Task. The launch record reaches the settlement through its input (`attempt-exit-submission.ts` holds it; keep its pinned strings).
4. **Baseline.** `resolveAttemptBaseline` gains `kind: 'snapshot'`. At each Attempt without a Submission that the walk visits, starting with the immediate predecessor: if its `attempt.preserved` says `preserved`, has no secret finding and every scope path matches the Task's **current** `scope.allowedPaths` (the matcher of ground truth 7), the walk ends with a snapshot baseline: which Attempt (seq, id), the snapshot (ref, commit, tree), its scope paths, its `baselineSha`, the Artifact id, how it ended (`interrupted` with the failure class, or `failed` with the last error and report error from its `attempt.failed`), the Attempts skipped on the way, and `underlying` — the Candidate or integration baseline at the bottom of the chain (resolve the baseline of that Attempt itself; if that is again a snapshot, take its `underlying`), so that a preserved fix Attempt still carries the failed Candidate and its VerificationRun (D64 revision row). Otherwise today's rule for that Attempt applies unchanged (a skipped kind continues the walk, which may reach an older usable snapshot; `failed` ends it at the integration base), and the result carries, for each visited Attempt that has an `attempt.preserved` row, why its work was not used: `empty`, out of scope (the offending paths), `secret`, `unavailable` (the reason). **Without any `attempt.preserved` row every result is deep-equal to today's** — `attempt-baseline.test.ts` and `previous-attempt.test.ts` pass unmodified (the sidecar checks that the two files are unchanged; new tests go into new files).
5. **Launch.** For `kind: 'snapshot'` the worktree is created from the preserved commit and HEAD must equal it (`fix_base_mismatch` otherwise, as for a Candidate baseline); `launch.json.baselineSha` is then that commit by construction. The launch audit's `baseline` states strategy and reason (D88 item 2): continued from Attempt N's preserved snapshot (commit), or not continued and why (with the offending paths for out of scope). `attempt-launcher.ts` gains a call, not logic.
6. **Context** (new module; `previous-attempt.ts` gains only the call). For `kind: 'snapshot'` the section states, from records only: which Attempt ended how (interrupted by `<class>` / failed, with the last error quoted); that this worktree starts from its preserved commit `<sha>`, which that Attempt left on top of `<baselineSha>`, so `git diff <baselineSha> HEAD` shows exactly what it left; that Attempt's own changes (`path (+a −r)`; from the Artifact, else the scope paths from the audit); that everything this worktree has on top of the integration branch is unverified and will be verified as a whole; the recent messages and commands from the Artifact, quoted as data and introduced as clues about where the previous run was, not instructions, with the Artifact id; two cautions — an action that was cut off may have taken effect or may still be running: check before repeating anything with side effects and say so when it cannot be confirmed; look at the working tree and the git history before changing anything —; the instruction to review before continuing (keeping, changing or reverting inherited work is this Attempt's responsibility); and, when the previous run ended `failed`, that it ended on its own error, so its approach may be part of the problem. When `underlying.kind === 'candidate'` the existing failed-Candidate evidence follows, introduced as found in that Candidate and possibly not yet fixed by the inherited changes. When preserved work was **not** used, the line for that Attempt says why (out of scope: name the paths) instead of "none of its uncommitted work was carried over"; an Attempt without a row keeps today's line. A missing or unreadable Artifact drops the records, nothing else. The wording is yours (do not copy another project's prompt text; name no destructive git command — the checks of ground truth 11 read prose too). The part this Task adds takes at most 3 KiB of the section's 8 KiB, newest records first while they fit; no input (records of any size, 200 paths, a full failed-Candidate block) may push the inheritance statement, the two cautions or the review instruction out of the section.
7. **Stub and E2E** (host, verifier-run; you cannot run Electron). The Codex stub's interruption branch gains an opt-in "leave work behind" step that speaks the real protocol: marker `<ledger>.partial-<taskId>` names a repository-relative path; the stub writes that file in its worktree and emits one completed `agent_message` item and one started-then-completed `command_execution` item in the shapes of ground truth 9 before `turn.failed`. New helper code lives in its own file, as `axiom-codex-rollout.ts` does. New spec `tests/e2e/mission-preserved-continuation.spec.ts`, two cases, each one Task (`taskIds: ['T01']`), Codex, Workers held until the markers are written, scenario `agent-crash`, no verification. **Interrupted, in scope, continued**: `maxAttempts: 1`, `interruptionBackoffMs: [100, 200, 300]`, the partial path (not ignored by the fixture, e.g. under `src/services/`) in `extraAllowedPaths`, one interruption with the partial marker. Attempt 1's `attempt.preserved` says preserved and names the path; in the clone the ref resolves to the audited commit and Attempt 1's branch does not; Attempt 2 starts by itself; its `attempt.started` audit says it continued Attempt 1's snapshot; Attempt 2's `prompt.md` contains the preserved commit sha, the path and the stub's message and command texts; Attempt 2 submits and the tree of its Candidate commit contains the file (read it in the clone, e.g. `git ls-tree -r --name-only <commit>`). **Failed, out of scope, not continued**: `maxAttempts: 2`, the existing crash marker, nothing extra allowed. Poll for conditions; no sleeps; no call from the test after the Workers are released. Take Attempt ids from the audit rows (`object_id`) and from the Submission (`attemptId`); if you do read a binding's dispatch id, only from a snapshot in which that Attempt already has a result (ground truth 10).
