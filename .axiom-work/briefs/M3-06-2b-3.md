# Task M3-06-2b-3 — A restart that also lost the daemon is an external interruption: preserve, settle as interrupted, continue (D88 revision row of 2026-11-11, item ③)

Planner brief, 2026-11-11 (verifier). When Axiom restarts and its terminal daemon is gone too (the app was restarted and the daemon killed, or the machine rebooted), the kernel's own recovery finds a running headless Worker's terminal missing and writes the worker `abandoned` with stage `terminal_missing`. Recovery then settles the Attempt as `attempt_abandoned`: it counts against `maxAttempts`, gets no waiting ladder, and the next Attempt restarts from the integration base — everything the Worker wrote is left behind unused. **Henry decided on 2026-11-11 (D88 revision ③) to accept that kernel verdict for this case: the Attempt is an external interruption (not counted, waiting ladder), it is preserved, and the next Attempt continues in a new worktree with a new session from the snapshot.** This Task implements exactly that and nothing else.

## Outcome

After this Task, a headless Attempt whose runtime restarted without its terminal daemon — the kernel found its terminal gone and wrote `abandoned` / `terminal_missing` — is settled by recovery as an external interruption: the host first preserves what the Worker left, then settles it as interrupted (refunded, continued after the waiting ladder; three consecutive interruptions block the environment as today), and the next Attempt continues in a new worktree with a new session from that snapshot and is told that the runtime restarted. Every other ending is settled exactly as on main.

## Deliverables

1. **Which ending.** In (b) a binding is *lost with its daemon* when all of these hold at that point of `reconcileAttempt`: headless (not a planner); worker state `abandoned` **and** stage `terminal_missing`; the worker's `runtime_epoch` differs from the current runtime (null counts as different, as in (c)); the Attempt's directory holds no exit marker the exit path would accept (an `exit-code` with an integer). Read the verdict only from this Attempt's own worker row — no matching on `last_error`, nothing inferred from terminal handles, pty ids or liveness (ground truth 6, #32341). Everything else in (b) is settled as on main: `terminal_missing` from the current runtime, stage `abandoned` (Axiom's own abandonment, including its evidence re-attachment), `failed`, `stopped` (also `stopped` / `terminal_missing` after a pending stop), an Attempt with an exit marker, TUI Attempts and planner bindings.
2. **Preserve first.** The capture of M3-06-2b-2 gains a proof for this ending; before any worktree IO it checks that the worker row still shows that ending (as the `'stopped'` proof does). Same routine, same `attempt.preserved` payload, same failure semantics: no error of the capture reaches the caller; an unusable launch record means no capture, and the settlement proceeds; nothing is deleted or reset.
3. **Settle as an interruption.** The capture is awaited outside any transaction; afterwards durable authority is read again exactly as for the other recovery endings (`recoveryEndingStillCurrent`): when it no longer holds, nothing of this branch is written and the binding is reconciled again from the top. Otherwise one transaction writes, all or nothing: `attempt.failed { reason: 'terminal_missing', lastError: <the worker's last_error>, failure: { class: 'unknown', retryable: true, source: 'absent' }, evidence: 'runtime_restarted', settlement: { kind: 'interrupted' } }` (through the recovery audit helper, which adds `taskId` and `seq`), then `attempt.preserved` when captured, then `settleInterruptedAttempt` exactly as the restart branch of (c) calls it. **No kernel call** — the kernel has already closed the dispatch: no `failDispatch`, no stop, no abandon, no release. No `attempt.abandoned`, no evidence re-attachment. The reconcile entry reports action `interrupted`. A later pass finds nothing to do (no second audit, no second refund).
4. **Baseline and context.** The successor continues from the snapshot under M3-06-2b's conditions (preserved, no secret finding, every scope path within the Task's current `allowedPaths`). This Attempt's `attempt.failed` reads as an interruption **with the restart evidence**, so the successor is told that the runtime which started the Attempt restarted and its process was gone afterwards — the statement the restart ending of (c) gets — not "interrupted by unknown", and neither the failed nor the stopped statement. Without a usable snapshot the walk treats it like any interrupted predecessor today (skipped; when a preserved row exists, `notContinued` says why). Without this row every baseline is deep-equal to today's: `attempt-baseline.test.ts` and `previous-attempt.test.ts` pass unmodified.
