## Objective

Give a running Worker its typed voice, and close the remaining Orca side doors:

1. **Worker verbs** `axiom.attempt.inform | request | blocked | handoff | request-subtask` — each a mutation that persists one typed message (`payload.axiom.type` ∈ `INFORM | REQUEST | BLOCKED | HANDOFF | REQUEST_SUBTASK`, D9 Orca `messages.type` for routing only) after the sender proved it is the live assignee of the named Attempt with the dispatch capability; stale / duplicate / mismatched / unauthorized calls are rejected with Orca's codes and **no state change**.
2. **`axiom.attempt.check`** — the Worker reads its own `dispatch:<attemptId>` mailbox (Control Plane replies, DECISION notifications, M2-06b answers) through the kernel's `checkWorkerMailbox`, same authority check, long-poll preserved.
3. **MessageRouter (M2 subset)** — `src/main/axiom/messaging/message-router.ts`: route by object relationship, never broadcast: every Worker message goes to the Mission's Control Plane mailbox; `INFORM` and `HANDOFF` are additionally delivered to the active Attempts of the sender Task's **direct downstream** Tasks (`mission_task_edges`); the run-mailbox consumer (M1-08) records each typed message (`message.received` audit with the type and ids) and, for `REQUEST_SUBTASK`, leaves it as a **pending item** (D50 step 1: persisted, listable; the deterministic checks and `axiom.task.create` are M2-06b).
4. **`axiom.message.list`** (read) — typed messages of a Mission for the UI and tests (`{ missionId, type?, taskId?, attemptId?, pendingOnly? }`).
5. **Admission interception points** (mapping §4b new rows; M2 exit criterion "§4b 新增拦截点有测试"): `orchestration.workerStop / workerAbandon / workerRelease / workerRetain / workerTerminalUserInput` on a Mission Attempt, `orchestration.ask` / `orchestration.reply` from or into a Mission Run (Workers must use `axiom attempt ask` — M2-06b — and the Control Plane answers), `orchestration.send` to a group address (`@all`, `@worktree:`…) within a Mission Run, and `orchestration.workerStart --on <environment>` for a Mission Run (already refused by the existing `workerStart` guard — prove it with a test, no new code).
