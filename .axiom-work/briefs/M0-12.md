# Attempt 2 addendum — host verification found a toolchain incompatibility in the helper build (attempt 1 candidate `101036a53`)

Attempt 1 is correct and complete for its scope (every string check passed; focused tests, `tc` ×3 green; the only red gates were the verifier's own pipeline script, since fixed on `main`). Building the renamed helper on the host then failed **before** your change is reached:

```
$ pnpm run build:computer-macos          # Apple Swift 6.4 (swiftlang-6.4.0.27.1), Xcode 26, arm64-apple-macosx26.0
swift build -c release --package-path native/computer-use-macos --triple arm64-apple-macosx   → Build complete!
swift build -c release --package-path native/computer-use-macos --triple x86_64-apple-macosx  → Build complete!
lipo: warning: file not found '…/.build/arm64-apple-macosx/release/orca-computer-use-macos'
lipo: warning: file not found '…/.build/x86_64-apple-macosx/release/orca-computer-use-macos'
lipo: no eligible inputs found
```

Cause (measured on the host, `.axiom-work/logs/chain-20261016-000811.log`): SwiftPM's default build system in this toolchain ("swiftbuild") writes every `--triple` build to the same directory — `swift build -c release --triple <any> --show-bin-path` prints `native/computer-use-macos/.build/out/Products/Release` for both triples — so the second build overwrites the first and the legacy per-triple paths `config/scripts/build-computer-macos.mjs:33` expects never exist. Passing `--build-system native` restores the legacy layout: `swift build -c release --triple arm64-apple-macosx --build-system native` produced `.build/arm64-apple-macosx/release/orca-computer-use-macos` (846,056 bytes). `swift build --help` lists `--build-system <build-system>` on this toolchain; older toolchains (SwiftPM < 6.1) do not have the flag.

## What to do (only this)

1. In `config/scripts/build-computer-macos.mjs`, build each triple with `--build-system native` **when the toolchain supports the flag** (detect once: `swift build --help` output contains `--build-system`), otherwise keep today's arguments. Put the argument construction in a small pure module next to the script (e.g. `config/scripts/build-computer-macos-swift-args.mjs` exporting `swiftBuildArgs({ packagePath, triple, supportsBuildSystemFlag })` and `detectsBuildSystemFlag(helpText)`), import it from the script, and add `config/scripts/build-computer-macos-swift-args.test.mjs` covering both branches (flag present / absent) and the exact argv shape. The script's top-level flow otherwise stays as it is (no refactor of `buildUniversalBinary`, `createHelperApp`, signing).
2. Do not touch `build-notification-status-macos.mjs` / `build-keyboard-layout-macos.mjs` (they call `swiftc` with explicit output paths and are unaffected).
3. Report `.axiom-work/reports/M0-12-2.md` as a delta: the diff, the new test's red/green, `pnpm test config/scripts/build-computer-macos`, `pnpm tc:node`, `pnpm run check:code-quality:changed` (with `ORCA_CODE_QUALITY_BASE` set to your starting commit if the default base drags in unrelated files — say so), full `pnpm lint` once.
