# Task M3-06 — Effect outbox v0: `attempt.dispatch` and `verification.enqueue` become durable effects, enqueued in the command's transaction and executed only after commit (D87 / DEF-48 ①)

Planner brief, 2026-11-09 (verifier). The M3-06 row in `docs/plans/M3.md` carries three things — the rule supervisor (exit 8, D60 / D68 as revised on 2026-10-26), D68's Attempt-side `interrupted` semantics, and DEF-48 ①'s durable effect outbox (D87). It is split on 2026-11-09 into three slices: **M3-06 (this brief) = the outbox v0**; M3-06-2 = `interrupted` settlement and retry-after on top of the outbox; M3-06-3 = the rule supervisor (timeout / budget / stalled, observe → auto). This brief changes *how* two existing side effects are driven. It changes no settlement rule, stage, retry policy or verification behaviour.

## Ground truth (verifier, 2026-11-09, main `c3deebe711`; every function below was read in full)

1. **Dispatch today.** `scheduler/scheduler.ts` `runRound`: for each READY candidate → `scheduler_precheck` transaction → `buildWorkerContracts` (async) → `admit()` = the `scheduler_admission` transaction (`insertAttemptBinding { dispatchId: null }`, `transitionTaskStage → RUNNING (admission, attemptCountDelta 1)`, audit `attempt.admitted`) → `result.admitted.push` → **`await launch(admitted)` in-process, after the commit**. A throwing launch is caught right there: audit `attempt.launch_failed { reason: 'launch_rejected' }` (actor `Scheduler`, objectId `<taskId>/<seq>`) + `settleAttemptWithoutSubmission({ ...admitted, dispatchId: null, reason: 'launch_rejected', actor: 'Scheduler' })`. Every production call of `scheduleRound` is fire-and-forget (`control-plane.ts` `onScheduleTrigger`, `control-plane-boot.ts` resume). The `launch` is `execution/attempt-launcher.ts` `createAttemptLauncher(deps)`: its head guard returns when the binding is missing, already has a `dispatchId`, or the Task is no longer `RUNNING`; then `createManagedWorktree` (name `attempt-<taskId>-<seq>`, `branchNameOverride`), `startLocalWorker`, `bindAttemptDispatch`, the `launch_settlement` transaction (`attempt.started | attempt.launch_failed | attempt.start_unknown`). Its own catch never rethrows: an unbound failure settles in `launch_failure` (`attempt.launch_failed { message }` + `settleAttemptWithoutSubmission(reason 'launch_failed')`), a bound one returns ("belongs to recovery"). The Planner calls the same factory directly from `planner-launcher.ts`, not through the Scheduler.
2. **The hole.** If the process dies between the `scheduler_admission` commit and the launch, the binding keeps `dispatchId: null` with the Task `RUNNING`. `recovery/attempt-reconciliation.ts` `reconcileAttempt` (60 s tick) waits `2 * resolveWorkerStartReadinessTimeoutMs(undefined)` (120 s today) and then, in `orphan_launch`, audits `attempt.launch_pending_orphan` and settles `launch_pending_orphan` (NEEDS_FIX → READY(retry) | BLOCKED): an Attempt is consumed although nothing ran.
3. **Verification enqueue today.** `execution/attempt-submission.ts` `settleSubmission` inserts the `QUEUED` VerificationRun inside the submit transaction and afterwards calls `void verificationService.kick(mission.id)`. `verification/verification-rerun.ts` inserts the `QUEUED` run in `verification_rerun`; its RPC handler (`rpc/methods/axiom/verification.ts`) kicks after the transaction. `VerificationService.kick()` is one coalesced global drain (claimNext → prepare → checks) that boot and the 60 s tick in `control-plane-boot.ts` also call. The QUEUED row is the durable queue; the kick is only the wake.
4. **The existing post-commit idiom.** `MissionController.scheduleAfterWrite` (queueMicrotask + "is my audit persisted?") turns a stage change into a Scheduler round. It is not touched here; the outbox needs no such check, because a rolled-back enqueue leaves no row.
5. **Schema.** `src/main/runtime/orchestration/db/schema/create-axiom-tables-sql.ts` `createAxiomTablesSql()` — 17 tables, the query indexes and 3 delete triggers, all `IF NOT EXISTS` — runs on **every open** (`create-tables.ts`). `axiom-tables-migration.test.ts` in the same directory is the independent contract (table / column lists, `sqlite_master` byte-identical across reopen, "clean every Mission table on run deletion"); `docs/reference/orca-mapping.md` §6 states the counts. `SCHEMA_VERSION = 46` (`db/contract-constants.ts`); upstream owns the next numbers (UPSTREAM-3 already shifted Axiom's migrations once). An additive table, index and trigger need **no** version bump and no migrate file.
6. **Stores.** `db/axiom-store.ts` composes per-table stores (`verificationRunsStore(db)` …) and exposes `transaction(savepoint, op)` (`runLifecycleWriteTransaction`); row codecs live in `db/*-rows.ts`; `db.db.isTransaction` tells whether a transaction is open.
7. **Boot / stop.** `control-plane-boot.ts` `startAxiomControlPlane`: `recovery.recover()` → `verification.recoverAtBoot()` → `reconcile()` now and every 60 s (`reconcileAttempts` + `verification.kick`) → `syncConsumer` → `scheduleRound(…, 'resume')` for EXECUTING Missions. `stopAxiomControlPlane` stops the headless watchers, verification, the timer and the consumers.
8. **Registration points for a read method.** `authority/caller-authority.ts` classifies every registered `axiom.*` method (test "classifies exactly every registered Axiom method"); reads are `read`. Method arrays under `rpc/methods/axiom/*.ts` are aggregated by `rpc/methods/axiom.ts`, which sits outside the allowed directory — add the new method to an existing exported array (e.g. `AXIOM_MISSION_METHODS`). CLI: `cli/specs/axiom-mission.ts` paths under `['mission', …]` and `cli/axiom-handler-groups.ts`; a new top-level command would need `src/main/startup/cli-command-names.ts` (out of scope) — nest under `mission`. New params need `pnpm run generate:rpc-params-catalog`.
9. **E2E seams.** `tests/e2e/helpers/axiom-fixture-mission.ts` `withFixtureMission` options (`holdWorkers`, `restart`, `runVerification`, `holdExitSubmission`, …) map to `AXIOM_E2E_HOLD_*` env vars that product code reads only behind `getMainE2EConfig().enabled`; `restart()` relaunches with `extraEnv`; `axiom-fixture-inspection.ts` `inspectFixtureMission` reads rows straight from the database. `tests/e2e/mission-attempt-launch.spec.ts` ("launches three fixture Attempts and preserves identity without relaunch on restart") must keep passing unchanged.
10. **Identity — the question D87 asked this brief to answer.** `attempt_bindings (task_id, seq)` holds one `dispatch_id`; the dispatch id *is* the attempt id everywhere (RPC `attemptId`, `resolveHostAttempt`, the `dispatch:<id>` mailbox, the headless Attempt directory, audits, Artifact `related`), and the kernel models a retry as a new dispatch context. **An Attempt has exactly one dispatch; a continuation after any interruption is a new Attempt (seq + 1).** So an `attempt.dispatch` effect is keyed `<taskId>/<seq>` and is never executed again for a bound Attempt. What an interrupted Attempt's successor starts from, and when, is M3-06-2.

## Outcome

After this Task: admitting an Attempt and queueing a VerificationRun each write one row into a durable effect outbox **in the same transaction** as the state change; an executor that runs only after commit performs the side effect (launch the Worker / wake verification) and records the result on the row; a restart before the launch no longer burns an Attempt — after boot the pending effect launches the same Attempt (same seq, same branch); a launch that was in flight when the process died is retired to the existing orphan rule instead of being started a second time; pending, failed and retired effects are visible through `axiom.effect.list`. Everything a Mission did before this Task it still does, with the same audits.

## Deliverables

1. **Contract** (`src/shared/axiom-contract/effects.ts`): `EFFECT_KINDS = ['attempt.dispatch', 'verification.enqueue']`; `EffectStatusSchema = 'pending' | 'running' | 'done' | 'failed' | 'retired'`; strict payload schemas — `attempt.dispatch { taskId, seq, branch, agentSpecId, contextPackageId }` (`AdmittedAttempt` without `missionId`), `verification.enqueue { runId }`; `EffectSchema { id, missionId, kind, key, payload, status, dueAt, attempts, leaseEpoch: string | null, lastError: string | null, createdAt, updatedAt }` (payload validated per kind); `EffectListParams = strictObject { missionId, status? }` and its response `{ effects: Effect[] }`.
2. **Table and store** (`create-axiom-tables-sql.ts`, `axiom-tables-migration.test.ts`, new `src/main/axiom/db/effects-store.ts` + row codec, joined into `AxiomStore`): table `axiom_effects (id TEXT PRIMARY KEY, mission_id TEXT NOT NULL, kind TEXT NOT NULL, effect_key TEXT NOT NULL, payload TEXT NOT NULL DEFAULT '{}', status TEXT NOT NULL, due_at TEXT NOT NULL, attempts INTEGER NOT NULL DEFAULT 0, lease_epoch TEXT, last_error TEXT, created_at, updated_at, UNIQUE(kind, effect_key))` + an index on `(status, due_at)`; rows of a Mission are removed when its run is deleted, on fresh **and** already-existing databases — do it additively (e.g. a new `AFTER DELETE ON missions` trigger; the existing run-delete trigger cannot be altered by `IF NOT EXISTS`); **no `SCHEMA_VERSION` bump, no `migrate-v47`**; update the contract test (18 tables, the new columns, index and trigger, reopen stays byte-identical, an existing v46 file gains the table on open without touching its rows, run deletion cleans effects). `due_at` is always written as `Date.toISOString()` and compared as text. Store operations, each a compare-and-set on the expected status: `enqueueEffect({ missionId, kind, key, payload, dueAt? })` — **throws unless a transaction is open**; for an existing `(kind, key)`: `pending | failed | retired | done` → payload replaced, `attempts 0`, `status 'pending'`, `due_at` = `dueAt ?? now`; `running` → left untouched and returned; `leaseDueEffect({ kind, missionId, now, epoch })` (the oldest `pending` row of that kind and Mission with `due_at ≤ now`, ordered `due_at, rowid`, and only when no row of the same kind and Mission is `running` → `running` + `lease_epoch`, `updated_at` = the lease time); `completeEffect`; `deferEffect(dueAt)` (→ `pending`, `attempts` unchanged); `failEffectAttempt(lastError, nextDueAt | null)` (`attempts + 1`; `null` → `failed`); `retireEffect(reason)`; `getEffect(kind, key)`; `listEffects({ missionId?, status? })`; `listOrphanedEffects(epoch)` (`running` with another epoch).
3. **Outbox service** (new directory `src/main/axiom/outbox/`): `enqueue(input)` = the store insert in the caller's transaction + `queueMicrotask(() => kick())`; `register(kind, { execute, maxAttempts, backoffMs, onExhausted?, onOrphan })`; `kick()` — one coalesced drain (return the flight promise, as `VerificationService.kick` does): at most one running effect per `(kind, missionId)` lane, lanes independent of each other (today a slow launch delays only its own Mission's round — keep that), lease → `execute(effect)` outside any transaction → `'done'` → `done` | `{ later: ISO }` → `deferEffect` (not a failure) | throw → `failEffectAttempt` with `now + backoffMs[attempts - 1]`, or, at `maxAttempts`, `failed` + audit `effect.failed { kind, key, attempts, lastError }` (actor `EffectOutbox`, objectKind `effect`; `lastError` through `redactContext`, ≤ 2,000 chars) + `onExhausted(effect)`; after each drain arm **one** unref'd `setTimeout` for the earliest future `due_at` (no `setInterval`); after `stop()` and until the next `start()`, `kick()` does nothing (the contract `VerificationService.kick` has). `recoverAtBoot()`: for every `running` row leased by another epoch call `onOrphan(effect)` → `'retry'` (→ `pending`, due now, `attempts` unchanged) | `'done'` | `{ retire: reason }` (→ `retired` + audit `effect.retired { kind, key, reason }`). `start()` / `stop()` are wired in `control-plane-boot.ts`: `recoverAtBoot()` and `start()` run before the first `reconcile()` and before the resume rounds; the existing 60 s tick also calls `kick()`; `stop()` clears the timer and lets a running execution finish. The plane exposes it as `plane.effects`. v0 has no time-based lease expiry: one Control Plane process owns the database.
4. **`attempt.dispatch`**: `Scheduler.admit()` enqueues `{ kind: 'attempt.dispatch', key: \`${taskId}/${seq}\`, payload }` inside `scheduler_admission` (a rolled-back admission leaves no effect — extend the existing "rolls back admission if its audit fails" test); `runRound` no longer calls the launcher and the `Scheduler` no longer receives `launch`. The executor is registered in `control-plane.ts` around the unchanged `createAttemptLauncher(...)` function: `execute` = `await launch({ missionId, ...payload })` → `'done'` (the launcher's own guards make it a no-op for a bound binding or a Task that left `RUNNING`); `maxAttempts: 1` — a throwing launch is never run again; `onExhausted` = exactly what the Scheduler's catch does today (`attempt.launch_failed { reason: 'launch_rejected' }` with the same actor / objectId, then `settleAttemptWithoutSubmission({ …, dispatchId: null, reason: 'launch_rejected', actor: 'Scheduler' })`); `onOrphan`: the binding has a `dispatchId` → `'done'`; else the kernel has a dispatch context for the Task that no AttemptBinding references (`db.getDispatchContext(taskId)` + `store.getAttemptBindingByDispatch`) → `{ retire: 'dispatch_outcome_unknown' }` (the launch may have reached the kernel — never start a second Worker; the orphan rule settles it); else → `'retry'`. E2E hold: when `getMainE2EConfig().enabled && process.env.AXIOM_E2E_HOLD_ATTEMPT_DISPATCH === '1'`, `execute` returns `{ later: now + 250 ms }`. `reconcileAttempt`'s unbound Worker branch: while `getEffect('attempt.dispatch', key)` is `pending` it returns `unchanged` (the launch has not started; the effect owns it); while it is `running` the orphan clock runs from the effect's lease time (`updated_at`) instead of the binding's `created_at`, so a launch that started late — e.g. after a restart — gets the same `2 × readiness timeout` a fresh one gets, and a launch that hangs is still orphan-settled; with the effect `retired | failed | done` or absent (rows from before this Task) the rule applies exactly as today, from the binding's `created_at`.
5. **`verification.enqueue`**: `settleSubmission` enqueues `{ kind: 'verification.enqueue', key: run.id, payload: { runId } }` in the same transaction as `insertVerificationRun` and its post-commit `verificationService.kick(…)` call is removed; `rerunVerification` enqueues in `verification_rerun` and the RPC handler's kick is removed. The executor: `void verification.kick().catch(warn)` then `'done'` — it must not await the drain; `maxAttempts: 3`, `backoffMs: [1000, 5000]`; `onOrphan` → `'retry'`. The boot and 60 s kicks of the VerificationService stay.
6. **Read surface**: `axiom.effect.list { missionId, status? }` — `read` in `caller-authority.ts`, registered in an existing array under `rpc/methods/axiom/`, catalog regenerated; returns the Mission's effects ordered by `created_at`, `rowid`. CLI `axiom mission effect list --mission <id> [--status <s>] [--json]` (text columns `KIND KEY STATUS ATTEMPTS DUE LAST_ERROR`). `inspectFixtureMission` gains `effects`.
7. **E2E (host, verifier-run)**: `withFixtureMission` gains `holdAttemptDispatch` (sets the env; `restart()` clears it the way it clears `AXIOM_E2E_HOLD_EXIT_SUBMISSION`). New `tests/e2e/mission-effect-outbox.spec.ts`, one case under 300 s: with `holdAttemptDispatch`, `restart: true`, `runVerification: true` (limit the plan with `taskIds` as other specs do) — after `mission start` the admitted Attempt is `RUNNING` with an unbound binding, `axiom.effect.list` shows its `attempt.dispatch` effect `pending`, and for ≥ 5 s no `attempt.started` audit and no provider ledger entry appear → `restart()` → the effect becomes `done`, `attempt.started` is audited for seq 1, the Worker submits, the Task reaches `VERIFIED`; bindings are `[1]` only, `attemptCount` is 1, there is **no** `attempt.launch_pending_orphan` and no `attempt.launch_failed` audit, and exactly one `verification.enqueue` effect exists and is `done`.
