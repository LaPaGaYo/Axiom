## Ground truth (verifier probes, 2026-10-28; `.axiom-work/logs/claude-isolation-probe-20261028-045926.txt` on the host CLI 2.1.309, same results on 2.1.312)

A headless `claude -p --output-format stream-json` emits `system/init` before authentication and before any network request, so these facts were measured with a throwaway `CLAUDE_CONFIG_DIR`, no credentials and a dead proxy port. The probe planted a user-tier skill, command, agent, `SessionStart` hook and `.claude.json` MCP server in the config dir, and a repo-tier skill, command, agent, hook, `.mcp.json` and `CLAUDE.md` in the working tree.

1. `--setting-sources=` (empty) alone drops **every user-tier and repo-tier customization**: no planted skills, agents or commands in `init`, no hooks run, `mcp_servers: []` (even without `--strict-mcp-config`). The user's `~/.claude`-linked surfaces Orca refreshes into the account home are therefore invisible to a Mission launch already; the M3-08b pins are the load-bearing isolation.
2. `--managed-settings '<inline JSON>'` is honored on both versions (it is not listed in `--help`): with default setting sources, `{"strictPluginOnlyCustomization":true,"disableAllHooks":true,…}` removed the planted user and repo skills/agents/commands/MCP servers and no hook ran. It adds a builtin plugin `cc-plugin-sec-default` to `init.plugins`. **The file-path form (`--managed-settings /path/file.json`) is silently ignored** on both versions: everything loaded as if the flag were absent. Pass the JSON inline only. The pinned SDK (`@anthropic-ai/claude-agent-sdk` 0.3.284) accepts `Options.managedSettings` as an object and itself serializes it to `--managed-settings <json>` argv (`sdk.mjs`: `managedSettings:a?ae(a):void 0` … `H.push("--managed-settings",this.options.managedSettings)`). Accepted restrictive keys include `strictPluginOnlyCustomization`, `disableAllHooks`, `disableSkillShellExecution`, `disableClaudeAiConnectors`, `disableRemoteControl`, `isolatePeerMachines`, `permissions.disableBypassPermissionsMode`, `sandbox.enabled`.
3. What a clean launch still reports: builtin plugins (`path: "builtin"`: `cc-plugin-agents-md`, `cc-plugin-plugin-authoring`, plus `cc-plugin-sec-default` under managed settings) and, with `CLAUDE_CODE_DISABLE_BUNDLED_SKILLS=1`, the skills `doctor` and `plugin-authoring`. Without that env the bundled skills (`deep-research`, `dataviz`, …) are listed too; `disableBundledSkills` in managed settings does not hide them, the env does. These are the harness's own, not customizations, and M3-08b's `claudeLaunchMismatches` currently reports all of them (`plugin_unexpected:*`, `skill_unexpected:doctor`, …), which is why `claude` cannot be certified today.
4. `--safe-mode` is not stronger than empty setting sources for our purpose (same residue, `memory_paths: null`); `--bare` never reads OAuth or the Keychain (API-key only) and is excluded for BYO subscriptions; `--restricted` removes Bash/WebFetch and confines file tools — not used by this Task (M3-10 candidate).
5. Orca's profile refresh (`src/main/claude-accounts/claude-profile-provisioning.ts`) runs from `ClaudeProfileRouter.prepareLaunch()`: it links every non-runtime directory of the user's `~/.claude` (skills, commands, agents, plugins, …) into the account home, copies `settings.json` and installs Orca's hooks, and merges the user's `.claude.json` (`mcpServers`, `projects`, …) into the account home's. The headless Worker launch does **not** call it (`resolveClaudeHomeForWorkerLaunch` only reads the routed home); the structured Planner launch **does** (`claude-structured-launch-resolution.ts` → `resolveClaudeStructuredLaunchHome` → `router.prepareLaunch()`).

## Outcome

After this Task a Mission Claude launch (Worker on channel A, Planner on channel B) carries an Axiom-owned policy tier the model cannot override, never triggers Orca's account refresh, records what the selected account home contained at launch (names only) and what the harness reported in `system/init`, and computes `attempt.launch_mismatch` against a recorded harness baseline — so a clean install yields an empty mismatch and the verifier's real Claude smoke can turn `claude` from `provisional` to `certified` (D57). The account home itself is not laid out, moved or rewritten by Axiom; credentials are never touched (D83).
