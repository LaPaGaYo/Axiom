## Objective

After this Task every Submission is **claimed by the Control Plane's VerificationService**, gets an **isolated verification worktree checked out detached at exactly the Candidate commit**, and is visible through `axiom verification show / list`. No verdict is produced yet (M3-02 runs the checks); the run stays `RUNNING` with `verdictDetail.phase = 'prepared'` and the Task in `VERIFYING`. Restarting the app requeues every in-flight run idempotently and recycles its worktree.

1. **`src/main/axiom/verification/`** — `verification-service.ts` (+ focused tests; split files by concept, no `utils`):
   - **Claim** (`claimNext()`): in one `store.transaction('verification_claim', …)` pick the oldest `QUEUED` run whose Candidate is `ACTIVE` and whose Task stage is `SUBMITTED`; CAS it `QUEUED → RUNNING` (`UPDATE … WHERE id = ? AND status = 'QUEUED'`, `changes === 1` or the claim is lost and nothing else is written), set `runtime_epoch = plane.runtimeEpoch`, `claim_count += 1`, `started_at`, `verdictDetail = { phase: 'claimed', claim: <claimCount> }`; `missions.transitionTaskStage({ taskId, to: 'VERIFYING', actor: 'VerificationService', reason: 'claimed' })`; audit `verification.claimed` (objectKind `verification_run`, objectId = run id, after `{ status: 'RUNNING', taskId, candidateId, claim }`). A `QUEUED` run whose Candidate is `SUPERSEDED` (or whose Task is no longer `SUBMITTED`) is settled `CANCELED` with `verdictDetail = { phase: 'canceled', reason: 'candidate_superseded' | 'task_stage_changed' }` + audit `verification.canceled` — glossary §4.8 already says so.
   - **Serial, in-process**: one claim/prepare in flight per control plane (a promise chain like the Scheduler's `flights`); `kick(missionId?)` is idempotent and coalesces; the loop drains until no claimable run remains. No `setInterval` of your own — the existing 60 s reconcile closure in `control-plane-boot.ts` additionally calls `plane.verification.kick()`.
   - **Prepare** (outside the transaction): `runtime.createManagedWorktree({ repoSelector: \`id:${mission.repoId}\`, name: \`verify-<taskId>-<claimCount>\`, baseBranch: <the Attempt's branch from attempt_bindings>, branchNameOverride: \`axiom/verify/${runId}/${claimCount}\`, runHooks: false, setupDecision: 'skip', awaitTerminalProvisioning: false, observeSetupCompletion: false, activate: false, lineage: { noParent: true, orchestrationContext: { orchestrationRunId: run.id, taskId } } })` (D64 revision: no terminal, no setup, managed path), then in that worktree (`gitOptionsForWorktree(splitWorktreeIdForFilesystem(id).worktreePath)`): `checkout --detach <candidate.commitSha>`, `branch -f axiom/verify/<runId>/<claimCount> <candidate.commitSha>`, and assert `rev-parse HEAD === candidate.commitSha` and `rev-parse HEAD^{tree} === candidate.treeSha` and `symbolic-ref -q HEAD` fails (detached). Success → `UPDATE` `worktree_id`, `verdictDetail = { phase: 'prepared', claim, worktreeId, candidateCommitSha, candidateTreeSha, baseline: { branch: <attempt branch> } }` + audit `verification.prepared`; write one evidence Artifact (`kind: 'evidence'`, `mediaType: 'application/json'`, `related: [runId, taskId, candidateId]`, `createdBy: 'VerificationService'`; content = the prepared facts + timestamps) and reference its id in `verdictDetail.evidenceArtifactIds`. Failure (commit missing, mismatch, worktree creation error) → remove the worktree you created (if any), `INCONCLUSIVE` with `verdictDetail = { phase: 'prepare_failed', reason: 'candidate_missing' | 'candidate_mismatch' | 'worktree_unavailable', detail }`, `finished_at`, audit `verification.inconclusive`; the Task stays `VERIFYING` (routing of INCONCLUSIVE is M3-05). Never `reset --hard` / `git clean`; never touch the Attempt's worktree.
   - **Restart** (`recoverAtBoot()` — awaited by `startAxiomControlPlane` before the first `kick`, after `plane.recovery.recover()`): every `RUNNING` run is stale (a fresh process has a new `plane.runtimeEpoch = \`epoch_${randomUUID()}\``): remove its recorded worktree with `runtime.removeManagedWorktree(\`id:${worktreeId}\`, { force: true })` (tolerate "already gone"), then `RUNNING → QUEUED` with `worktree_id = NULL`, `runtime_epoch = NULL`, `verdictDetail = { phase: 'requeued', reason: 'restart', previousClaim }` + audit `verification.requeued`; old audits and Artifacts stay. Also remove orphan managed worktrees whose branch starts with `axiom/verify/` and whose run is not `RUNNING` in this epoch (find them through the runtime's own worktree listing; never scan the filesystem). Idempotent: a second boot with nothing in flight writes nothing.
   - **Triggers**: `attempt-submission.ts` calls `plane.verification.kick(mission.id)` **after** `runLifecycleWriteTransaction` returns (never inside it); boot (`startAxiomControlPlane`, after `recoverAtBoot`); the 60 s reconcile closure. Rejected / duplicate submissions must not kick.

## Facts you can rely on
- `createManagedWorktree` returns `{ worktree: { id, … } }`; the id splits with `splitWorktreeIdForFilesystem(id)` into `{ repoId, worktreePath }` (see `candidate-snapshot.ts`). The Attempt's branch is `attempt_bindings.branch` (`axiom/attempt/<taskId>/<seq>`); the Candidate commit was created on it by `snapshotCandidate` and is immutable (`candidates.commit_sha`, `tree_sha`, `UNIQUE(task_id, commit_sha)`).
- `runLifecycleWriteTransaction` / `store.transaction(savepoint, fn)` are synchronous; async work (worktree creation, git) must happen outside and record its outcome in a second transaction.
- The fixture repo has no setup hooks; `setupDecision: 'skip'` is also what M3-02 expects (dependency installation becomes a recorded check there).
- `mission-attempt-launch.spec.ts` restarts before any Submission — it must keep passing unchanged.
- `ATTEMPT_RECONCILE_INTERVAL_MS = 60_000`; `reconcileAttempts` writes nothing for completed dispatches, so a tick during an e2e snapshot pair is harmless once the runs are `prepared`.
