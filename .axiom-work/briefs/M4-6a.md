# Task M4-6a — a Mission whose Tasks are all settled moves on: `FINALIZING`, the target-branch check, the completion gate, `READY_FOR_APPROVAL`

**Why.** Today nothing moves a Mission past `EXECUTING`: when its last Task is integrated the Mission still says "executing" and nothing else happens. This Task adds the first half of finalization (`docs/ARCHITECTURE.md` §6.1, §12.3): the Mission enters `FINALIZING`, an outbox effect checks the integration branch and the target branch, evaluates the completion gate item by item and records what it found, and the Mission becomes `READY_FOR_APPROVAL` when everything holds. **This Task does not align with a moved target branch**: when the target branch has commits the integration branch does not contain, finalization stops, says so, and leaves the Mission in `FINALIZING` (the alignment batch, the Mission-level fix Task and the back edge to `EXECUTING` are M4-6b, a later Task). No Approval is created (M4-7), nothing is delivered (M4-8), no CompletionReport is written (M4-10), and no interface string changes (M4-11): this Task is contract, main process, read side, one e2e spec extended and one added.

High-risk class: it adds a Mission transition and an effect kind.

## Outcome

A Mission in which every Task is `INTEGRATED` or `CANCELED` and at least one is `INTEGRATED` moves to `FINALIZING` in the next scheduling round. Finalization then ends in exactly one of two recorded outcomes: **ready** — the integration branch is where the record says, it contains the target branch, every gate item passes — and the Mission is `READY_FOR_APPROVAL`; or **stopped** with a reason, and the Mission stays `FINALIZING`, shows a blocking pending item, and is looked at again by the sweep. Nothing writes to a git ref, the target branch is only read, and a Mission that never finalizes behaves exactly as today.

2. **The request.** One function, in a new folder `src/main/axiom/finalization/`, called by the scheduling round. In one write transaction it re-reads everything and:

3. **The executor** of `mission.finalize`, registered by the Control Plane next to the integration executor (three tries, two backoff values, an orphan is retried). Per run:
   - the Mission is not `FINALIZING` → done, nothing written;
   - read the integration head (`readIntegrationHead`); it differs from the recorded head, or there is no recorded head → stopped, `integration_head_unexpected`;
   - read the target branch with `readIntegrationGit` on the repository path, passing `true` as `readIntegrationHead` does: `rev-parse --verify --quiet refs/heads/<target>^{commit}` — exit code 1 → stopped, `target_branch_not_found`; then `merge-base --is-ancestor <target head> <integration head>` — exit code 1 → stopped, `target_branch_moved`. Any other failure of a read throws, so the outbox retries — `readIntegrationHead` failing (the branch is gone, the repository is not on this machine) included; after the last try the record says `finalization_unavailable`. No other git call, and no environment of your own (`GIT_CEILING_DIRECTORIES` and `core.hooksPath=` stay in the one file each that has them);

   - after the last failed try (`onExhausted`): stopped, `finalization_unavailable`.

A run whose outcome equals the latest record of the current `FINALIZING` entry — same outcome, reason, heads and gate — writes no second event: the sweep runs this every minute for a stopped Mission.
