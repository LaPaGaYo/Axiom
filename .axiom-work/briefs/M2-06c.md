## Objective

Google's Gemini CLI stopped serving individual accounts on 2026-06-18 (google-gemini/gemini-cli discussion #28017); its replacement is Antigravity CLI (binary `agy`), which Orca already models as the `antigravity` TuiAgent (`detectCmd: 'agy'`). A machine that still has the `gemini` binary installed therefore advertises a provider that cannot run an Attempt. D53 decides: **`gemini` is retired by default in Axiom's provider selection** — it is filtered with the new reason `retired` unless the Mission's `routing.preferredProviders` names it explicitly (API-key / enterprise users keep it that way). Nothing changes in the Orca detection layer or `TUI_AGENT_CONFIG`.

## Facts you can rely on (verified against the checkout)

- `selectProvider(available, routing, role, highRisk, engine)` in `provider-selection.ts` builds `DEFAULT_ORDER = Object.keys(TUI_AGENT_CONFIG)` minus `claude-agent-teams`, then filters each provider with the first matching reason `not_installed` → `disallowed` → `tier_too_low` and ranks the rest through the `DecisionEngine` (`PROVIDER_SELECTION_RULES`: preferred index, then tier A before B, ties by config order). `filtered` entries are persisted in `AgentSpec.selection.filtered` and audited (`agent_spec.created`).
- `ProviderFilterReasonSchema = z.enum(['not_installed', 'disallowed', 'tier_too_low'])` (`agent-spec.ts:4`) is the only place the reason enum is declared; `AgentSpec` ids are content-addressed (`spec_ + sha256(canonical)`), so a changed `filtered` list changes the spec id — the M2-03 determinism tests pin ids by recomputing them, not by literal, so no pinned-id test needs a new constant (check `agent-factory.test.ts` before assuming).
- `antigravity` is a tier-B TuiAgent exactly like `gemini` was (`AttachParams.shape.provider` = tier A = `codex`, `claude`); it is installed on the verifier's host as `agy` 1.4.1, `gemini` 0.46.0 is still installed there too — the host e2e (M2-11) will exercise exactly the situation D53 covers.
- Existing tests use `gemini` as the tier-B exemplar (`agent-factory.test.ts:88,126,128,139,149,159,166,182,188,199,200,237`). Those expectations must change to `antigravity` for the tier-B role; `gemini` keeps appearing only in the new `retired` cases.
- `routing.preferredProviders` is `z.array(TuiAgentIdSchema)` (M2-04 `RoutingPolicySchema`); an explicit preference is the single override for retirement. Reason order is `not_installed` → `retired` → `disallowed` → `tier_too_low`: an installed, retired, not-preferred provider is reported `retired` even when it is also disallowed; a preferred retired provider then goes through the normal `disallowed` / `tier_too_low` checks. Document that order in control-plane.md.
