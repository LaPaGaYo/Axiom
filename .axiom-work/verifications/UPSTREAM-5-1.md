## The gate that failed, and the one-line fix

The floor test's new comment named upstream's pull request with the organisation's name in it. The vendor-egress ratchet counts that word per file under `src/` and `config/` ("baseline 1 -> current 2" for this file), and `pnpm lint` runs the same ratchet as its tenth step of thirty-two. This is the verifier's slip in the text of a comment; the upgrade does not cause it. The fix changes that reference to "upstream PR 43682": one line of one test file, no code. `launchers/upstream-5-integrate.command` applies it on `6475e7dbe1`, checks the file's format and the ratchet, commits it (`5f6e32cfea`), and runs `verify.sh` again; it stops without a record and without a merge unless that run says OVERALL=PASS. The result is the row above.

The other checks of the host step ran on `6475e7dbe1` and are not repeated on `5f6e32cfea`. The two trees differ in that one comment line; the gates that read the file — the floor test itself, the formatter check, lint — are in the repeated `verify.sh`, and verify-main runs the unit suite on the merged main before the push.
