The decision follows the brief's table in order: a Submission whose candidate has a PASS run is a false positive (`verification_pass`); a Submission with no PASS and a non-terminal run is pending; a FAIL with no PASS and no non-terminal run is a hit (`verification_fail`); otherwise `canceled_runs` (all runs canceled) or `unknown` (no run at all; the submit transaction writes the QUEUED run together with the Submission, so this only happens on unusual paths). Without a Submission: the latest binding of a RUNNING Task is pending; then `attempt.stopped` (`timeout` = hit, any other reason = inconclusive `stopped`), `attempt.failed` (`failed` / `unchanged` = hit, `interrupted`, `no_change` / `blocked` = `declared`, anything else `unknown`), `attempt.abandoned`, and finally `unknown` with the `stop_unknown` time or the pass's `now`. `endedAt` is the deciding fact's time through `exposeUtcTimestamp` (the Submission's for a verification outcome); `savedMs = max(0, endedAt − wouldActAt)` for a hit only. A missing or mismatched binding throws inside the transaction, is logged with the observation's sequence and stays for the next pass; a failing scan or one failing observation never stops the others or the pass.
