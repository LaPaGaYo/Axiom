What this Task is: the main-process half of the policy editor (the M3-09-4c-2 row). A Mission's policy decides who plans and who works, how many Tasks run at once and what verification runs, and no control in the interface can change it yet. Two things had to be true before an editor can be built. First, the write: it lived in the RPC handler, which opened the transaction, merged the patch, stored the policy and wrote the audit event itself. From this candidate on it is an operation of the MissionController like every other change of a Mission, with no change in behaviour. Second, an editor that offers a provider must be able to say whether admission would accept it, and the interface cannot know what is installed, which accounts exist or which provider is cooling down. From this candidate on `axiom.policy.show` answers that on request (`providers: true`): for every provider, whether a Planner and a Worker at each risk level would be allowed to use it and, where not, the first reason — computed by the filter that provider selection itself runs, taken out as one function. Main process and contract only: no renderer, no CLI, no new method, no change of a caller class.
