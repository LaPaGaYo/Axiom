Why this Task exists: two defects that have been there since verification got a worktree of its own, found by reading the code on 2026-11-15. A verification run prepares a worktree on a branch `axiom/verify/<runId>/<claim>`, moves `HEAD` off that branch onto the candidate commit, runs its checks and hands the worktree back to the kernel. The kernel deletes the branch of a worktree it removes only when the worktree is on one — so every claim of every run left its branch in the user's repository, for good. And the sweep that removes, at boot, verification worktrees no run records compared the runtime's full ref names (`refs/heads/axiom/verify/…`) with a short prefix; outside tests, whose stub lists short names, it never matched anything. This Task fixes both without deleting a branch from Axiom's own code: the worktree's `HEAD` is pointed at its branch again before it is handed back, and the kernel's rule does the rest. How it does that — one ref operation instead of the checkout and the wait of the integration scratch, and under which three conditions — is the verifier's detail and was reported to Henry on 2026-11-16 (`claude/decisions-pending-2026-11-16-v1.md`).

## Not covered

- The full runtime's removal — deletion of the checkout in the background, the refusal of a dirty unrecorded worktree without `force` — is reached only by the one e2e assertion. The unit tests run the kernel's git functions through a stub that finishes before it returns and always forces.
- A git older than 2.38 was not run: there the kernel cannot prove a verification branch merged, every such branch stays, and each removal first fetches the remote that `origin/HEAD` names. Title 1 and the e2e assertion need the newer git. The documented minimum is still 2.25; whether to raise it is Henry's to decide.
- Inside WSL the ceiling variable does not reach git, so there the check for the directory's own `.git` is the only guard; a parent path that contains `:` splits the ceiling. Neither was run.
- The three checks and the ref write are separate git calls; another git process can act in between. A branch that the kernel cannot prove merged into its recorded base stays and nothing records that; a run whose worktree the kernel made on a suffixed branch is put on the unsuffixed one and the suffixed branch stays.
- The removal is not waited for: a branch can outlive its run's `worktreeId` for as long as the kernel needs to delete the checkout, and a removal that fails in the background is still not seen.
- Branches that earlier versions left behind without a worktree stay. The sweep still sees only worktrees on a branch, removes a clean `axiom/verify/` worktree of another Axiom profile that uses the same repository, and one this process made but had not recorded if a claim ran before the boot recovery.
