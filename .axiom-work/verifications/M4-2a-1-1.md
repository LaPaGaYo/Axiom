Notes that do not change the verdict:

- (a) **This is the first column that reaches an existing database without a version number.** `AGENTS.md` says "Add database migrations for durable schema changes"; so far that meant a numbered step. The step here is tested (an old file gets the column at open, keeps its version and its rows, and a second open does nothing), additive, and nobody edits stored state by hand — but it has no number, because upstream's own chain has used 44 to 46 for other steps and every number Axiom takes has to be moved at the next sync. That is the verifier's reading of the rule, not something the rule says, and it is Henry's to accept or overturn (item 7 of the pending decisions). Until he answers, `AGENTS.md` is not edited; turning the step into a numbered one later is one small Task, and a file that already has the column is not disturbed by it.
- (b) When the `ALTER` fails and the `ROLLBACK` in the `catch` fails too, the second error replaces the first. The numbered runner has the same shape.
- (c) The open-time addition commits before `migrate` runs. On a file older than v46 the new column therefore comes before the five columns of v46; on such a file a failed numbered migration leaves the new column in place and the next open skips it.
- (d) The readers of a Task's runs other than the verification service do not tell a batch's run from a candidate's (`listVerificationRuns` answers both). No product path writes a batch run yet; M4-2a-2 decides for all of them at once, in the store's listing.

## Not covered

- Two processes opening the same old file at the same moment were not run against each other; that the second waits for the first and then finds the column follows from the lock and the second probe.

- The store accepts any id as `batchId`; that the batch exists and belongs to the run's Mission and candidate is the caller's check. The column has no index.
- The boot sweep of verification worktrees goes by branch name, not by run: it would also take a batch run's worktree if one were ever made on an `axiom/verify/` branch. The integration executor uses its own names.
