The structured session leaves no transcript in the account home (`projects/` untouched; `claude-planner-transcript-20261028-205918.txt`), so the denied commands were established by probe:
- Probe 1 (`launchers/probe-claude-planner-permission.command`, `.axiom-work/logs/claude-planner-permission-probe-20261028-210127.txt`; headless 2.1.312 with the Planner's exact `--settings` allow/deny rules, the planner managed-settings tier, `--permission-prompts none`, from the smoke home on a throwaway repo; `axiom` deliberately absent from PATH): **the recipe command the Planner prompt prints — `axiom plan propose … --file /dev/stdin --json <<'AXIOM_PLAN_JSON' {JSON} AXIOM_PLAN_JSON` — is denied** by Claude Code's Bash safety analysis ("brace with quote character (expansion obfuscation)": the unquoted JSON braces in the heredoc body), so it never reaches the `Bash(axiom plan propose --mission … --attempt … --file:*)` allow rule; `permission_denials` lists it. The single-line form `axiom plan propose … --file <path> --json` is allowed (ran, `command not found` in the probe); `git log` allowed; `cat README.md` auto-allowed (read-only command); a `printf '%s' '<json>' | axiom plan propose … --file /dev/stdin --json` pipe is allowed too but would need shell-safe JSON. The Planner therefore has no working output channel; after three attempts the model ended its turn, and nothing settles a finished structured turn without a proposal (recovery rule c′ covers only the terminal channel, and `policy.budget.maxRuntimeMinutes` is unset by default).
- Probe 2 (`launchers/probe-claude-planner-permission-2.command`, `…probe2-20261028-210541.txt`) settles the replacement rule set: an `Edit(//<attemptDir>/proposal.json)` allow rule lets the **Write** tool create that one file outside the worktree (no `--add-dir` needed) and the single-line `--file <that path> --json` command is allowed by the prefix rule (F, J, L); a Write anywhere else is "ask" → auto-denied with no approval surface (G), and an `Edit(//<worktree>/**)` deny rule refuses worktree writes outright ("File is in a directory that is denied by your permission settings", K); a tool-level `deny: [Write]` (the current planner settings) disables the Write tool entirely, allow rules notwithstanding (H); a `Write(//path)` allow rule is not honoured — only `Edit(...)` path rules govern Write (I).
- Consequence: M3-08h (brief `.axiom-work/briefs/M3-08h.md`): Claude Planner proposal through `<attemptDir>/proposal.json` (Write under an `Edit(//…)` path rule) + single-line `axiom plan propose --file`, permission rules per probe 2, and a structured-channel settlement for a finished turn without a proposal (`planner.attempt_failed {reason: no_proposal, evidence: turn_settled}`), plus the denied tool input (redacted) in `attempt.permission_denied`. The smoke spec now settles its Planner poll on `planner.attempt_failed` as well.
