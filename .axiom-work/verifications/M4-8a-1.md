What this Task is: local delivery, the first write of the Control Plane outside the `axiom/*` namespace. Since M4-7b a person can grant the delivery Approval, and nothing used it. This candidate adds the command that does, `axiom.mission.deliver { missionId, approvalId }` (desktop only, a durable mutation). It checks the Approval once more — it belongs to the Mission, it is `GRANTED`, the Mission is `READY_FOR_APPROVAL`, it is the Mission's latest delivery Approval and its hash is the hash of the current report, it has not expired (an expired one is requested again and the call refused, D70 item 3) — then reads git. A repository with a remote, an integration branch that is not at its recorded commit, a repository whose `merge.verifySignatures` is true, a target branch that is checked out: each stops the delivery — nothing is written to git, `mission.delivery_stopped` is recorded, the pending list shows `delivery_stopped`, and the same Approval delivers once the cause is gone (D92 h). A target branch that is not at the commit of the report sends the Mission back `READY_FOR_APPROVAL → FINALIZING` (D70 item 2, by the letter). Otherwise `mission.delivery_started` is committed, the target branch is fast-forwarded by a compare-and-swap with no configuration override and a reflog message, and one write consumes the Approval (`CONSUMED`, `outcome`, `executed_at`) and completes the Mission. Nothing is pushed; no worktree is touched; no interface, CLI command or MCP tool.
