## Overlap rule (three sentences)

For each unordered Task pair with no dependency path in either direction, two literal entries overlap when `matchesPathPattern(a, b) || matchesPathPattern(b, a)` is true, reusing existing normalization and path-prefix semantics. A literal and glob overlap when the literal matches the glob; two globs overlap only when their original strings are equal. A valid normalized `.` overlaps every valid entry, and all overlapping entry pairs are collected into one warning per Task pair with deterministic Task-id and path ordering.
