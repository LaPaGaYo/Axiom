### Turn-end seam and crash recovery

`claude-structured-journal-translation.ts` owns the invocation: it observes each
event, calls the Mission tracker after `journalClaudeResult` consumes a root result,
and invokes its idle fallback at the existing `claudeSessionStateEndsTurn` branch.
`claude-mission-turn-settlement.ts` keeps one pending bit and the last started
command UUID per translator. It consumes the pending bit before notifying, so a
result followed by idle or a duplicate result cannot notify twice. Existing open
journal turns also supply evidence. Startup/queued idle and child end frames do not
notify Mission callbacks.

A turn can fail before any user echo or assistant output. The tracker therefore
arms on a host-correlated `command_lifecycle: started`; acquisition also adds the
optional `resultAnsweredSend` event fact when the existing replay resolver accepts
a correlated terminal result. This retains evidence after the resolver removes
its waiter, without fabricating a journal turn or changing caller authority.

Axiom claims `planner.attempt_failed` synchronously in a store transaction only
when neither proposal nor failure evidence exists. `stopPlanner` coalesces
overlapping callers and deduplicates identical stop receipts. Reconciliation
finishes a durable failure whose live process was not stopped before a crash, and
backfills a missing `planner.stopped` receipt if the kernel stop had already
committed. No Mission status is changed. Tests cover both crash windows, duplicate
signals/ticks, successful proposals, default and explicit budgets, and subsequent
turns.
