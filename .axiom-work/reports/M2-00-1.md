## Workflow jobs and estimated hosted duration

All jobs start with `actions/checkout@v6` (`persist-credentials: false`) followed
by `./.github/actions/install-node-dependencies`. The action selects Node 24 from
`package.json` and the repository's pinned pnpm version. Typecheck and lint use
its default native runtime; tests request `native-runtime: node`. The lint chain
does not include the native-runtime smoke steps present in upstream `pr.yml`.
The optional TypeScript cache is omitted, so there is no PR-only cache key or
history lookup to adapt for push events.

| Job | Steps after checkout | Expected duration on ubuntu-latest |
| --- | --- | --- |
| `typecheck` | Shared install; separate `pnpm tc:node`, `pnpm tc:cli`, `pnpm tc:web` steps | 3–6 min including install and cold typechecking |
| `lint` | Shared install; one `pnpm lint` step running the complete chain | 3–6 min including install |
| `axiom-tests` | Shared install with Node native runtime; `ORCA_BACKGROUND_LAUNCH=1 pnpm exec vitest run --config config/vitest.config.ts` with the exact ten targets below | 2–4 min including install and native preparation |

These are planning estimates, not hosted measurements. The source is
[M1 local gate timings](../../docs/review-evidence/axiom-m1/M1-exit-e2e.md#local-gate-timings):
13 attempts had medians of 1/0/1 seconds for Node/CLI/web typechecks, 80 seconds
for full lint, and 5 seconds for varying scoped unit-test sets. The typechecks
were cached and the 5-second median is not this exact target set or a full-suite
measurement. The hosted ranges allow for dependency installation, cold compiler
state, native preparation, and different CPU capacity. Jobs run in parallel;
their durations should not be summed to estimate workflow wall time. Each has
a 30-minute ceiling. The first hosted run must replace these estimates with data.
