## Read-model rule and SQL

`AxiomStore.getOldestReadModelAuditAfter` delegates to `readModelAuditsStore`. Its schema extends the existing read criteria with required integer `afterSequence >= 0`. It uses `.get()`, `AuditRowCodec`, and explicit `AXIOM_COLUMNS.audit_events`; it never calls `listAuditEvents`.

```sql
SELECT ${AXIOM_COLUMNS.audit_events} FROM audit_events
WHERE mission_id = ? AND sequence > ? AND (? IS NULL OR object_id = ?)
  AND (? IS NULL OR object_kind = ?)
  AND event IN (SELECT value FROM json_each(?))
  AND (? IS NULL OR json_extract(after, '$.stage') = ?)
  AND (? IS NULL OR json_extract(after, '$.status') = ?)
ORDER BY sequence ASC LIMIT 1
```

Parameter order: Mission id, exclusive sequence, object id twice, object kind twice, JSON event names, stage twice, status twice. Optional filters bind `null` when absent. The provider caller supplies the Task's Mission/id, kind `task`, event `task.admission_refused`, and `ctx.stageAudit(task)?.sequence ?? 0`. The existing fallback remains `task.updatedAt`. Existing UTC normalization still happens in `pending.item`.

No schema, index, audit write, or `waitingOn` behavior changes. Run-based times, upstream cancellations, stage times, and budget variants remain on their previous paths.
