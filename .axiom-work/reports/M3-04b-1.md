## Task adjustment rules

`axiom.task.adjust` requires a transport-stamped desktop caller, a rationale, a PLANNED or EXECUTING Mission, its active APPROVED PlanRevision, and Task stage DEFINED, READY, NEEDS_FIX or BLOCKED. It preserves ordered allowedPaths while adding a deduplicated union, and updates both spec.retryPolicy and the retry_policy column through stage CAS. maxAttempts below attemptCount is invalid_argument; a NEEDS_FIX Task needs strictly more remaining attempts or the entire write rolls back with retry_budget_exhausted. BLOCKED returns through persisted previousStage, then NEEDS_FIX → READY with reason adjusted; DEFINED remains for readiness recomputation. Rationale-only adjustment is valid. The same transaction writes task.adjusted, plan.minor_adjustment (MINOR_ADJUSTMENT, origin=task_adjust), and blocked.resolved for every pending typed BLOCKED message of the Task; cancellation resolves them with decision=canceled. RPC mutation receipts and scheduling after commit are tested, including receipt failure rollback. This changes no Mission budget and creates no Approval object in V1.
