## Reader and settlement review

The launch audit is selected by this dispatch id, validated with zod and read once. Its home is not spread into an effect/audit. The only persisted identity remains `{provider,key}`. Only a Codex usage-limit classification invokes the reader; Claude and non-quota Codex failures do not open a session file. The original classifier is unchanged and remains pure. Evidence can enrich `failure.window` and `failure.resetsAt`, never `class`, `retryable`, `source` or `settlement.kind`.

The thread token allows only 1–128 ASCII letters/digits/underscores/hyphens. It cannot contain dots, path separators or glob syntax. The start instant is `worker_dispatches.created_at`, normalized by the existing SQLite UTC conversion. The reader enumerates only its local calendar days through today under the recorded account home's `sessions/YYYY/MM/DD`, matching `rollout-*-<thread id>.jsonl`. Across that range it selects the newest mtime. It does not recurse into the account home or consult any default home.

Canonical paths must remain within sessions. An escaping date/file symlink yields no evidence; a symlinked sessions root is rejected. The single selected file is opened with `O_RDONLY | O_NOFOLLOW | O_NONBLOCK`; fstat checks it is regular, its device/inode agree with the selected identity, and the canonical path still agrees. Only the final 256 KiB are read, once, with the handle closed in finally. When the tail is truncated, its first line is discarded; a tail with no newline is discarded entirely. Lookup is bounded to the Attempt's date interval; content read is bounded to one file/256 KiB.

Only event_msg/token_count rate_limits pass the zod whitelist: limit_id; primary/secondary used_percent, window_minutes, resets_at; rate_limit_reached_type. Null windows remain null, absent fields remain undefined. One CodexUsageLimits receives records in file order through observe; its failure query supplies the output. Axiom neither compares percentages nor chooses/names windows. No conversation, account metadata, discarded fields, home path or file contents enter the output, error, log or new audit. The result is only `{window?,resetsAt?}` (kernel epoch milliseconds); settlement admits an ISO reset only within `now < reset <= now + 8 days`, retaining a window when reset is rejected.

Malformed lines are skipped. Missing/unsafe thread, missing home/file, unreadable file, all-malformed file or kernel exception returns no evidence, without delaying for retries or timers. A test asserts the file open occurs outside every DB transaction. Authority is resolved again inside settlement after the await. Existing continuation/account cooldown logic remains untouched.

## Limitations and risks

- Rollout values at a real usage limit have never been observed. The reset is best-effort; absent evidence leaves M3-06-2a's ladder and per-Task three-strike BLOCKED(environment) behavior.
- A spent window is trusted only together with quota text. An account that keeps working on credits after a window is spent would still wait for that window if a transient quota-like error ended its Worker.
- A record under another limit id, including the upstream all-null report described in the brief, supplies no account reset.
- The 256 KiB tail bound can miss the last useful record of an unusually large final turn. A partially included first record is intentionally discarded.
- The reader depends on Codex's 0.163.0 file layout and field names and on the existing kernel class's behavior; upgrades can change either.
- No real provider account or conversation was accessed during implementation; tests use temporary synthetic homes. Windows/WSL validation is outside this Task.
- Host Electron verification and full environment-capable CLI tests remain required. This report establishes implementation readiness for that review, not final acceptance.
