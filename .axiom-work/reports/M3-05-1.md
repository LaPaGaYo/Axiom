## Necessary differences from the brief's starting assumptions

The checked-out router still forwarded INFORM / HANDOFF to downstream Workers. To satisfy the explicit Run-only requirement, that forwarding was removed; `rpc-attempt-check.test.ts` now seeds Control Plane dispatch mail directly so its mailbox isolation and long-poll assertions remain meaningful. The brief expected only a test pin here, but the production correction was necessary in this baseline.

A fresh QUEUED rerun previously could not be claimed while its Task was VERIFYING. Claiming now checks the schema-validated `verification.rerun_requested` audit bound to the exact run / Task / Candidate. Same-second run ordering uses insertion order after created_at, avoiding random UUIDs making a new rerun appear older. This also moves the existing baseline / persistent-failure ordering pins.

Preparation failures bypass normal verdict settlement, so they use the same escalation helper. Cleanup also accepts a human resolution or rerun cancellation that completed while asynchronous worktree removal was pending; it preserves that detail and current final status and retains epoch / claim fencing. The BLOCKED stage guard has one explicit user / rerun_requested transition to VERIFYING.

## Rerun preconditions

A desktop caller may rerun a VERIFYING Task only when its ACTIVE Candidate's latest run is HUMAN_REVIEW, or rerun a BLOCKED Task that has an ACTIVE Candidate. A latest QUEUED or RUNNING run is refused, the rationale must be nonempty and at most 4,000 characters after trimming, and the shared redactContext scanner must find no secret.

## Limitations, risks and next verification step

- A human can resolve PASS over acceptance_human without supplying proof. That is the V1 human-disposition boundary by design; it does not integrate the Candidate or complete the Mission.
- Rerun executes the whole verification plan, including setup and repository gates, not only a changed criterion. It does not admit another Worker or increment Attempt count.
- Human FAIL counts against maxAttempts like a deterministic FAIL: the already consumed Attempt is retained, and the same remaining-budget test chooses READY or BLOCKED.
- Human resolve / rerun remain desktop-only even though CLI command shapes exist. The pending-item UI is M3-09; no Reviewer or automatic resolution is implemented.
- Independent host E2E and socket-dependent CLI verification remain required. The standard pnpm build wrappers must also be rerun where tsx may create its IPC socket. No milestone completion decision or promotion should be inferred from local unit results.
- V1 CLI Worker write scope remains verification-time enforcement, as before; this change adds no runtime sandbox authority or permission expansion.
