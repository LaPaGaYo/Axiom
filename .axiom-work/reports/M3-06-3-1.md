Identity availability, in flow order:

1. `mission.id` exists after Mission creation, before the fixture callback. Approved-plan materialization has created `task_id`; the spec waits for one bound Attempt before reading the Task id and creating the three held-worker marker paths.
2. Attempt 1's dispatch id exists when the first binding is populated. The spec obtains it later, from `attempt.stopped.object_id`, only after polling for that committed audit. The supervised/preserved/first-started audits are joined using this already-known id.
3. The preservation ref/commit/tree are created during capture before the stopped/preserved settlement commits. After the stop audit is visible, the spec decodes the same-transaction preservation, resolves its ref, and uses the first-started branch (recorded at initial launch) to locate the retained worktree.
4. Attempt 2's dispatch id and started audit exist at launch, but the spec does not assume their timing from Attempt 1's stop. It waits for `submissions.length === 1`. The Candidate and Submission are committed together; only then does it read `submission.attemptId`, `submission.candidateId`, find `candidate.id`, compare Candidate.attemptId, inspect the successor started payload and read the prompt at that attemptId.
5. `baseline.attemptId` in the successor started payload is the already-known Attempt 1 id; its commitSha is the already-read preserved snapshot. Cadence is allowed to commit after the stop, so its one-row condition is polled separately using Attempt 1's id.

Preserved non-row assertions also remain: the retained worktree contains `partialWork = true`; the successor prompt contains the snapshot hash, partial path, last message, JSON-quoted git status command and `timeout`; the successor Candidate tree contains the partial path. `Stopped`, `Supervised`, `Cadence`, `FirstLaunch`, and `ContinuedLaunch` are test-local decoders, not new shared schemas or migrations.

## Differences, limitations and remaining work

No behavioral scope deviation. The existing kernel stop and UTC conversion stay in attempt-reconciliation and are passed into the new step, so the new production modules add no kernel import. SQL qualifies the newest 20 rows before LIMIT rather than capping a batch of unqualified rows; the returned history is bounded without losing eligible older Attempts. A future events mtime is clamped to zero silence; non-regular or unreadable event metadata skips sampling. The existing forced-stop behavior, planner reason and cadence-loss semantics remain as requested.

- Silence is sampled at **60-second resolution**; gaps that begin and end between passes can be missed. These are measured sampled silences, not exact timestamps embedded in every event.
- Cadence entries are lost on process restart and are not reconstructed. A late first sample marks partial only by the specified greater-than-two-interval heuristic. No file means no sample and no cadence audit.
- A Worker able to write its Attempt directory can keep events.jsonl fresh, including altering mtime. **The runtime limit remains the backstop.** CLI write scope remains a verification-time diff boundary; this change adds no runtime filesystem enforcement.
- **There is no wrap-up phase** before the kernel stop. The existing terminal stop kills the harness/tee; no kernel change was made.
- **A crash between stop and settlement is still recovered as kernel_stopped**, as before. The new timeout supervision rolls back with a failed Axiom settlement transaction. stop_unknown still follows the original tolerance/abandon path, without preservation or immediate settlement.
- observe remains audit-only. Outcome reconciliation, evidence tables, upgrades and stall notify/stop tiers are M3-06-3-2; token budgets are M3-06-3-3. No UI or Planner supervision is added.
- Full pnpm entrypoints and the complete CLI/helper test scope cannot be certified in this environment. Host Electron verification and independent acceptance remain outstanding.

The ordinary pre-commit hook invokes the unavailable pnpm launcher and its lint-staged configuration formats Markdown. For the Attempt handoff, its TypeScript work passed direct `oxlint <14 changed TS files>`, `oxlint --config config/oxlint-react-doctor.json <same files>`, and `oxfmt --check <same files>`; the attempted commit used `HUSKY=0` to preserve the explicit instruction not to format Markdown, but Git failed before commit creation because its index lock was not writable. This does not turn any blocked check into a pass.
