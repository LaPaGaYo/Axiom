The new `layoutCodexAccountHome`:

- Unlinks only known resource symlinks whose targets lexically resolve into the supplied system home, including dangling owned links. It does not follow their targets. Regular resources, external links, auth, sessions, logs and state remain.
- Replaces config with the Axiom header, local project trust, attributable Orca hook approvals, apps/plugins disabled, allowlisted MCP tables, user-skill disable entries and daemon guard. No layout-written `features.hooks`.

- Reads user skill names directly under the supplied `.agents/skills`, including linked entries, without reading skill contents. Repository skills are not scanned. Reads the system config only when the MCP allowlist is nonempty, selecting named tables plus descendants verbatim.
- Returns config/MCP SHA-256 hashes, missing MCP names, absolute disabled/enabled user-skill paths, retained approval keys and removed resource entry names. Lists/hashes are deterministic; `removedLinks` naturally becomes empty after the first removal pass.

Settings are read on every layout. `codexAccountHomeAllowlist` defaults to empty skills and MCP arrays. No UI was added. The saved Orca-hash reader was separated from the process/probe module so synchronous layout does not import that subsystem; existing approval reconciliation still supplies its live/memoized hashes.
