## Limitations, questions and follow-ups

- Resolve the two scoped addenda before accepting M2-07; rerun the complete required suite, host submit and launch specs, and independent diff review. No additional product question is unresolved.
- Git snapshotting precedes SQLite by design. A failed settlement can leave a snapshot commit/staged work in the Attempt worktree; an authorized retry adopts clean HEAD. No reset/checkout/clean/push is used to discard that evidence.
- Post-commit message failure can be repaired through an authenticated duplicate; there is no new durable outbox or background recovery service in M2-07.
- CLI-agent write scope remains a verification-time diff check. The fixture retry patch may exceed an individual Task's allowedPaths, as expressly allowed for this M2 host scenario; M3 must enforce it during independent verification.
- M2-08: `exited` after SUBMITTED is normal; `exited` before Submission settles FAILED → NEEDS_FIX. Liveness ambiguity must not be treated as exit.
- M3: VerificationService dequeues QUEUED in its own verification worktree and binds evidence to the immutable Candidate. Worker check results remain advisory.
- M4: SUPERSEDED releases the retained worktree/resource under the integration/retention policy; this Task only records supersession/retention and never merges, promotes, delivers, or declares completion.
- Windows/Linux host execution and all-hook suppression against real Git hooks were not exercised here; portable APIs and fake-runner argument/directory checks are covered. No real Git commit was executed by the Worker.
