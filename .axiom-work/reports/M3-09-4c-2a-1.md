`providerEligibility` first filters Planner/high with the default empty cooldown map, then maps the existing risk enumeration through Worker filtering with the supplied cooldown map. It takes the union of all four candidate/filtered sets by iterating configuration order. Within each entry, the slot is true iff its candidates contain that provider; the optional reason comes only from that slot’s filtered entry. If a provider is outside a slot, membership is false and no reason property is emitted. A missing unlisted combination appears only when installed or role-configured, exactly as in selection; an uninstalled Planner-only Gemini in the test is false/not_installed for Planner and exactly `{eligible:false}` for all Worker slots. A missing non-role Continue is omitted entirely.

No reason ladder or certification table was copied, no DecisionEngine is called by eligibility, and no new cache, constructor input, clock, timer, infrastructure or RPC method was introduced. Factory host discovery is once per requested answer, with stored policy loaded afterwards, as in existing selection. Normal `show` reads call none of those host inputs.
