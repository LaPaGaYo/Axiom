## Remaining product limitations and risks

- Branches left by earlier versions without a worktree stay. Recorded interrupted/uncleaned runs and unrecorded worktrees still on a verification branch, including those from earlier versions, can now lose their branch through the kernel rule.
- In the normal user topology where the main worktree does not contain the candidate, Git older than 2.38 cannot prove a verification branch merged: every such branch stays, and each removal first fetches the remote named through origin/HEAD. Title 1 and the e2e ref assertion require the newer Git proof.
- Newer Git still preserves a branch it cannot prove merged into its recorded base, such as when the Attempt branch is deleted or moved back during verification; it may fetch once before giving up. Axiom ignores preservedBranch and writes no audit or pending item for it. Kernel preservation metadata for a reused branch still applies.
- If the kernel created a suffixed branch because the requested branch was occupied elsewhere or an earlier worktree directory remained, cleanup still requests the unsuffixed run/claim name. When the guards allow, HEAD goes there and the suffixed branch stays; if the requested branch is occupied, the step is skipped.
- The branch also stays when the step cannot run: directory or its own `.git` absent, id with no path, missing branch, mismatched commit, another worktree using it, or any other failure. The step changes no files or index. Checks and the ref write are not one atomic transaction with external Git writers.
- A worktree whose removal fails after reattachment stays on its branch and is visible to the next boot sweep. Removal is not awaited: a branch can outlive the run's worktreeId for as long as deleting the checkout takes; failures occurring in the runtime background remain unseen.
- The sweep still sees only worktrees on branches. An unrecorded detached worktree is never swept. It can remove a clean verification worktree of another Axiom profile sharing the repository, or one this process created but did not record if a claim ran before boot recovery.
- WSL does not pass the ceiling environment through to Git; there the own-.git lstat is the only guard. A parent path containing `:` splits the ceiling list. These are retained boundaries, not fixed here.
- Unit tests use the kernel's Git functions, not the full runtime. The e2e poll is the full-runtime check and was not run in this sandbox. Work scope remains verification-time inspection for CLI agents; the local diff and sidecar gates check this submission's allowlist, not runtime enforcement.
