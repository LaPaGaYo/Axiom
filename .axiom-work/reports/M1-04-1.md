Four internal table modules contain the SQL; seven row schemas parse snake_case database rows into typed contract objects. JSON syntax and contract-shape failures identify the table, row and column without including cell contents. API details for M1-05/M1-08:

- Missing single-row reads return `undefined`; lists return arrays. Mission reads include validated `previousStatus`, `createdAt` and `updatedAt` alongside the existing Mission contract fields.
- Mission and audit lists are unbounded when `limit` is omitted; an explicit limit must be a positive integer. Mission order is ascending `(created_at, id)`; a missing cursor id returns an empty page. Revision lists sort by revision, Task lists by Task id, edges by endpoint ids, and audit by ascending sequence.
- The caller supplies a validated Mission identity to `insertMission`; M1-05 owns minting its `mission_…` id and Run/session identity. Goal/Plan ids use the kernel's `generateId('goalrev' | 'planrev')` helper.
- `transaction` accepts a lowercase safe savepoint suffix and prefixes it with `axiom_`. Callbacks are synchronous, matching the kernel runner. Operations compose inside an existing kernel transaction.
- Task-stage insertion omits the database-owned `updatedAt`. Optional revision pointers and `previousStage` preserve the stored value when omitted and clear it on explicit `null`; omitted `rejectedReason` preserves the prior reason. `previousStatus` is an explicit nullable Mission CAS input. Attempt deltas are nonnegative integers, default zero, applied only when the CAS matches.
- Audit snapshots accept JSON values including `null`; no audit content policy is imposed. SQLite owns sequence allocation and timestamps. Timestamp precision remains SQLite's existing one-second format.
