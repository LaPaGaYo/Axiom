## Attribution evidence shape and bounds

Each recorded request still has `method`, `url`, `remotePort`, and `process`. A known process now has:

```text
{ pid, command, ppid, ps, parent: { pid, ppid, ps } | null }
```

`ps` retains the text from `ps -p <pid> -o ppid=,comm=,args=` after the existing observability credential redactor. Only the leading PPID is parsed: splitting comm from args on whitespace would corrupt paths/process names with spaces. The parent's PPID links to the next ancestor without claiming its identity. Missing process details remain null while a measured socket PID/command is retained. The attributed tally includes these fields plus `count`, grouped by host and PID/command; unknown groups explicitly contain null fields.

Per connection on macOS/Linux:

```sh
lsof -nP -a -iTCP:<remotePort> -sTCP:ESTABLISHED -Fpcn
```

macOS additionally runs, in parallel with lsof:

```sh
netstat -anv -p tcp
```

Both parsers match the complete client-to-proxy endpoint direction. Netstat uses its header to locate either the numeric `pid` column or the `process:pid` column, allowing extra byte-count columns and spaces in process names. The numeric layout is corroborated by [Apple's netstat source](https://raw.githubusercontent.com/apple-oss-distributions/network_cmds/main/netstat.tproj/inet.c); named-process fields are also present in the installed macOS netstat binary. This sandbox denies live netstat socket enumeration (`Operation not permitted`), so actual host-format validation remains with the verifier.

Prefer an owner other than the proxy PID when either tool finds one. Retain a direction-matched own PID when it is the actual loopback test client and neither tool finds another owner. Read ps for the selected process and its parent. Legacy netstat can yield a PID without a name; in that case a further `ps -p <pid> -o comm=` fills the command best effort.

All commands use the existing `runProcess` boundary, with no shell, a 1,000 ms timeout per command, and a 1 MiB output cap (netstat enumerates the socket table). Existing process termination grace can extend a timeout. Unsupported platforms, unavailable tools, permissions, empty output, nonzero exits, timeouts, truncated output, and vanished processes do not prevent recording/refusal. Attribution and the minimum hold are asynchronous; failures retain null evidence. The client itself can close early, and teardown still destroys remaining sockets.
