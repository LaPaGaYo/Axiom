## Final schemas

`Text = z.string().min(1, 'Expected non-empty text')`; ArtifactKind is the existing enum. Both check and criterion objects are strict.

```ts
export const AcceptanceCheckSchema = z
  .discriminatedUnion('kind', [
    z
      .strictObject({ kind: z.literal('command'), command: Text })
      .describe(
        'One exact shell command; independent verification runs it verbatim from the repository root and requires exit 0. No shell operators; the program must be allowed by verification policy. Put expectations and descriptions in text, never in command.'
      ),
    z
      .strictObject({ kind: z.literal('artifact'), artifactKind: ArtifactKind.optional() })
      .describe(
        'The submission must reference a readable, non-empty Artifact of artifactKind when given.'
      ),
    z
      .strictObject({ kind: z.literal('human') })
      .describe(
        'Use only when neither a command nor an Artifact can prove the criterion; a person will confirm it.'
      )
  ])
  .describe(
    'How this criterion is proven: an exact command, a readable non-empty Artifact, or human confirmation.'
  )

export const AcceptanceCriterionSchema = z
  .strictObject({ text: Text, check: AcceptanceCheckSchema })
  .describe(
    'A Task acceptance requirement and its proof. Use human only when neither a command nor an Artifact can prove it.'
  )
```

```ts
export const VerificationAcceptanceSchema = AcceptanceCriterionSchema.extend({
  index: z.number().int().nonnegative(),
  result: z.enum(['pass', 'fail', 'inconclusive', 'skipped', 'human']),
  checkIndexes: z.array(z.number().int().nonnegative()),
  artifactIds: z.array(AxiomIdSchema)
}).describe('Independent verification evidence for one resolved acceptance criterion.')
```

TaskSpec and AgentSpec retain `z.array(z.union([Text, AcceptanceCriterionSchema]))` for stored compatibility. TaskSpec's optional legacy field is described as deprecated; SubtaskRequest has only `z.array(AcceptanceCriterionSchema).min(1)`.

`z.toJSONSchema` needs neither `io: 'input'` nor `unrepresentable: 'any'`. The old `requiredString` transform was replaced by a plain string/min schema; non-string and empty inputs still fail. No transform was added. The prompt and MCP tool input use the same schema. They still mention the retired field in its deprecation/retirement notice, but never instruct the Planner to emit a separate command list.

## Verdict matrix as implemented

Preconditions preserve the existing early routing: invalid policy → INCONCLUSIVE / policy_invalid; remote repository → INCONCLUSIVE / environment / remote_repository_unsupported. Otherwise the following order applies:

| Priority | Condition                                                              | Verdict                                                                                      |
| -------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 1        | Diff gate fails                                                        | FAIL / secret_detected or scope_violation                                                    |
| 2        | Any check fails or a command criterion fails                           | FAIL / checks_failed                                                                         |
| 3        | Explicit artifact criterion fails                                      | FAIL / artifact_missing when no matching reference; otherwise artifact_invalid               |
| 4        | Non-code implicit Artifact requirement: none / invalid format or empty | FAIL / artifact_missing or artifact_invalid                                                  |
| 5        | Non-code Artifact unreadable, absent higher failure                    | INCONCLUSIVE / environment / artifact_unreadable; human; diff environment retains its reason |
| 6        | Diff gate inconclusive                                                 | Existing environment / diff_too_large / test_tampering / dangerous_change; human             |
| 7        | Environmental command result                                           | INCONCLUSIVE / environment; human                                                            |
| 8        | Plan-invalid command result                                            | INCONCLUSIVE / plan_invalid; human; command in detail                                        |
| 9        | Other inconclusive command result                                      | Existing flaky / known_flaky routing                                                         |
| 10       | Skipped command/criterion or criterion without a check result          | INCONCLUSIVE / environment; human                                                            |
| 11       | No command criterion                                                   | INCONCLUSIVE / non_code; existing nonCodeTasks routing                                       |
| 12       | All deterministic criteria pass, one or more human criteria remain     | INCONCLUSIVE / acceptance_human; human; numeric detail = count                               |
| 13       | All deterministic criteria/checks pass, clear gate, no human criterion | PASS / checks_passed                                                                         |

Command criterion result follows its step; environmental and plan_invalid become inconclusive. Shared commands have one step and several criterion indexes. Artifact criteria use at least one valid matching submitted reference; human criteria always record human. Only FAIL admits the existing fix path; INCONCLUSIVE keeps VERIFYING without a fix Attempt.

The explicit artifact check's “else fail” rule is followed literally: unreadable explicit proof fails artifact_invalid (or artifact_missing when the required kind cannot be established). The old implicit non-code unreadability path remains INCONCLUSIVE/environment. This distinction is covered by a regression and documented in the reference.
