## Necessary differences and limitations

- The checkout includes the planner-brief commit after the cited code baseline. No product scope change follows from it.
- Continuation registration is a separate adjacent registrar called by control-plane.ts, so the two existing executors need no edits. The failure branch is the only production extraction. No pinned source string moved.
- HTTP/result-reason interpretation requires the result to be failed; successful result frames with incidental error-status metadata do not create an environmental refund. This is explicitly tested and documented.
- Standard pnpm build-prefixed gates and the full socket/process test set cannot be certified in this sandbox. Direct typecheck/test evidence is provided without representing those wrappers as passing. No Electron was attempted.
- Codex has no reliable structured failure class or reset time. A continuing Codex usage limit reaches BLOCKED(environment) after approximately six minutes plus launch/settlement overhead.
- No account-level cooldown exists here: every READY Task assigned to an exhausted account still launches once before waiting. No read of runtime account snapshots or kernel rate-limit services was introduced.
- Waiting counts against the Mission wall-clock budget. Continuation never bypasses Questions, Approvals, admission budgets, concurrency, pause, or cancellation.
- A failed or retired continuation leaves the Task admissible on any later Scheduler round. A failed round is not a permanent backoff lock.
- An older build that cannot decode attempt.continue cannot safely open/read such effect rows; adding the kind is not backward decoder compatibility. Older rows without failure remain readable by this build.
- Interrupted uncommitted work is not carried over; no worktree snapshot or harness-session resume was implemented. Baseline traversal preserves only the earlier failed immutable Candidate and verification evidence.
- CLI Worker write scope remains verification-time diff enforcement plus provider configuration, as before. This Task adds no runtime filesystem enforcement.
- Host Electron verification and the subsequent immutable Candidate / milestone decision remain outstanding. Do not mark the Mission complete from this report.
