Column counts include timestamps and Mission ownership columns. `mission_id` was added to `agent_specs`, `attempt_bindings`, `context_packages`, `submissions`, `candidates` and `verification_runs` so all retained rows can be cleaned by Mission even after the upstream Task/Dispatch disappears. Each non-Mission table now carries this ownership directly. No extra tables or foreign keys were introduced.

Mutable lifecycle rows have `created_at` and `updated_at`; immutable records have `created_at`. JSON remains TEXT. Mutable status/stage/kind fields are NOT NULL TEXT without CHECK enums; the sole CHECK is `mission_policies.nested_worker_max_depth = 1`. `audit_events.sequence` is an autoincrement primary key. Nullable `previous_status` and `previous_stage` preserve return states. The required uniqueness constraints and default readiness thresholds are covered by tests.

The three new triggers are `trg_tasks_delete_axiom`, `trg_dispatches_delete_axiom` and `trg_runs_delete_axiom`. They mutate only Axiom rows. Task deletion removes stage, both edge directions and bindings but retains other evidence. Dispatch deletion nulls only its binding's `dispatch_id`. Run deletion cleans all 17 Mission tables, with the Mission row deleted last. Tests use different Run and Mission IDs and verify another Mission is unaffected.
