## Outcomes and precedence

Gate precedence (all available findings retained):

| Condition | Gate |
| --- | --- |
| Diff unavailable | inconclusive / environment; detail is the fixed diff reason |
| Any added-text secret | fail / secret_detected |
| Any changed path outside scope | fail / scope_violation |
| Patch exceeds limit | inconclusive / diff_too_large |
| In-scope dangerous path not explicitly named | inconclusive / dangerous_change |
| None of the above | clear |

Combined verdict precedence:

1. Gate fail → FAIL with its reason (secret before scope), including with failed or absent checks.
2. Any check fail → FAIL/checks_failed, including when the gate is inconclusive.
3. Gate inconclusive → INCONCLUSIVE with its reason/detail and escalation=human.
4. Existing M3-02 logic: environmental → environment/human; inconclusive → flaky or known_flaky with policy routing; empty plan → no_checks with nonCodeTasks routing; skipped → environment/human; otherwise PASS/checks_passed.

FAIL still goes through `settleVerificationFailure`: NEEDS_FIX followed by READY or BLOCKED according to attempt budget. INCONCLUSIVE leaves the Task VERIFYING. Commands retain their original deadline/setup/retry behavior; the gate itself never skips commands.

## Limitations and follow-ups

- The inherited provider-token pattern can flag long kebab-case identifiers beginning with `sk-`. This implementation intentionally keeps redaction byte-identical and does not redesign the detector.
- Binary files are listed but not scanned. Only added text is scanned; pre-existing content is outside this gate. Oversized patches become human-routed INCONCLUSIVE rather than an incomplete clean scan.
- CLI write scope remains verification-time enforcement, not runtime isolation. Harness files left inside a worktree, including `.claude/settings.local.json`, enter the Candidate and fail scope unless authorized. Moving harness state outside the worktree or approving snapshot exclusions belongs to M3-08/a product Decision.
- Dangerous path matching is file-based, including any manifest change; content tampering, Artifact schemas and non-code verification are M3-03b.
- DEF-21 ⑦ is documented: dependency changes belong in one early Task explicitly naming package.json and the lockfile. Warnings for parallel Tasks touching them remain M5 Planner v2.
- Host Electron validation and the unrestricted full sidecar run remain outstanding. No product behavior beyond the approved brief was added to compensate for the sandbox.
