**A′ = ACP: factual assessment, sources inspected 2026-10-20**

ACP v1 defines newline-delimited UTF-8 JSON-RPC over stdio. Initialization negotiates a protocol version and capabilities; absent optional capability is not support. `session/new` supplies cwd/MCP servers; `session/prompt` and `session/cancel` drive work. `session/load` is conditional on `loadSession` and replays history; `session/resume` requires the advertised resume capability and does not replay it. Treat these separately from the v2 draft. [Transports](https://agentclientprotocol.com/protocol/v1/transports), [initialization](https://agentclientprotocol.com/protocol/v1/initialization), [session setup](https://agentclientprotocol.com/protocol/v1/session-setup).

Published native integrations include OpenCode (`opencode acp` over stdio), Qoder (`qoder --acp`), and GitHub Copilot CLI (`copilot --acp`, announced as public preview). The protocol's agent directory also lists Gemini CLI, Qwen Code, and Kimi CLI. These are availability claims from documentation, not tested versions or Axiom certifications. The older Kimi CLI repository is archived and points to a successor; verify the maintained binary before choosing it. No CodeBuddy support is asserted without a primary source. [OpenCode](https://opencode.ai/docs/acp/), [Qoder](https://docs.qoder.com/cli/acp), [Copilot announcement](https://github.blog/changelog/2026-01-28-acp-support-in-copilot-cli-is-now-in-public-preview/), [ACP agent directory](https://agentclientprotocol.com/get-started/agents), [Kimi repository](https://github.com/MoonshotAI/kimi-cli).

The historical Zed Codex adapter README now directs development to `agentclientprotocol/codex-acp`. Its current README describes a stdio ACP frontend backed by **Codex App Server**, configurable model/reasoning/approval/sandbox modes, packaged compatible Codex, and an explicit `CODEX_PATH` override. It is a usable integration candidate by its documented interface, but not a tested solution for this installed 0.163.0; it retains an app-server dependency and cannot be presumed to evade F3. README blob SHAs inspected: old `652e5619133258708bda43cf56f8ce22b0448871`, current `0c4ba6678660df58d8c1c46b2a7914a9f3bd0e47`. [Old Zed README](https://github.com/zed-industries/codex-acp/blob/main/README.md), [current Codex adapter README](https://github.com/agentclientprotocol/codex-acp/blob/main/README.md).

The Zed-origin Claude adapter is now described by `agentclientprotocol/claude-agent-acp`, which wraps the official Claude Agent SDK and documents permissions/tool-call support and stable v1 alongside opt-in draft v2. Its inspected README blob is `8af4f74365869e54ecdb078f58059ddf0a6fbbe9`. This is an adapter, not evidence that the standalone Claude Code CLI natively speaks ACP or that a particular subscription/auth route is certified. [Claude adapter README](https://github.com/agentclientprotocol/claude-agent-acp/blob/main/README.md).

An ACP client can answer `session/request_permission` with advertised allow/reject choices and select advertised session modes/configuration. Tool execution remains agent-owned; permission requests are optional protocol interactions, not a universal OS/filesystem/network sandbox. Axiom would have to translate AgentSpec deterministically into each harness's supported policy, reject unsupported scope, and keep ApprovalGateway authoritative. Client filesystem/terminal capabilities can narrow client-mediated operations but do not prove confinement of an agent's own tools. Therefore A′ is a credible vendor-neutral interface to evaluate separately, with per-adapter permission and recovery certification; it is not an immediate F3 repair or a new dependency in this Task. [Tool calls/permissions](https://agentclientprotocol.com/protocol/v1/tool-calls), [session modes](https://agentclientprotocol.com/protocol/v1/session-modes).
