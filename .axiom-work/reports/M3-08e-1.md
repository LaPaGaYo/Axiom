## Implementation and call sites

| Path / caller | Change |
| --- | --- |
| `codex/codex-worker-launch-home.ts` | `prepareCodexWorkerLaunchHome` resolves once; null/mirror stay unmanaged. Account layout precedes the token check. API-key auth is not applicable; a timestamp newer than seven days is fresh. Stale launches re-read under the existing per-home lock before refreshing and after the refresh. Only an advanced timestamp is refreshed. All token errors become `refresh_failed`; no credential bytes or error text escape the adapter. |
| `codex-accounts/runtime-home-service-auth-sync-identity.ts` | Exports the existing timestamp parser. |
| `codex-worker-launch-home.ts` → `resolveCodexStructuredInvocation` / `runCodexAppServerSession` | Default refresh resolves the command through the catalog/session resolver, uses `CODEX_SHORT_LIVED_PROBE_APP_SERVER_ARGS`, explicit `CODEX_HOME`, a 10-second session deadline and `account/read {refreshToken:true}`. Axiom does not write auth. |
| `runtime/session-tabs/structured-session-account-home.ts` | Public `resolveCodexHomeForWorkerLaunch` invokes only the read-only resolver with `resolveTuiAgentLaunchEnv`. It refuses an uninitialized resolver. The inherited resolver type also permits asynchronous implementations; this synchronous desktop seam rejects such a result without changing out-of-scope runtime contracts. |
| `axiom/control-plane.ts` → `AttemptLauncherDependencies.codexWorkerHome` | Wires the selected runtime home and current allowlist into preparation. `RuntimeStore`'s narrowed settings type omits the existing allowlist property; `readCodexAccountHomeAllowlist` validates it locally with zod rather than editing an out-of-scope contract or casting. Its parse also snapshots the arrays used by the audit. |
| `execution/headless-worker-launch.ts` | Resolves the home before command construction. Refusals propagate to existing launch-failure settlement. Binds the dispatch, records the prepared combination, and emits one mismatch audit containing all reasons. `attempt-launcher.ts` spreads the same launch audit into `attempt.started`. |
| `execution/headless-worker-command.ts` / `runtime/.../control-plane-worker-start.ts` | Every headless argv includes `-c features.hooks=false`. Only account homes add an explicit env entry. The POSIX wrapper puts quoted `NAME=value` operands immediately after `/usr/bin/env`, so login-shell rc changes cannot override the selected home. The audited argv remains the Codex argv. Sandbox, JSON output, stdin prompt and no-bypass posture are preserved. |
| `execution/worker-launch-combination.ts` | Requested model/effort/channel/home/allowlist/hooks; effective layout hashes/counts, user-skill package digests and token status. Version probes are cached by binary fingerprint. Account-only missing MCP/skills, unknown version and failed refresh become mismatch reasons. TUI records `effective:null, adapter:'none'`. |
| `execution/attempt-exit-submission.ts` → `attempt-worker-release.ts` | Failure settlement schedules release after the existing two-second grace. Shared release code honors the hold switch, uses `releaseLocalWorker`, and records safe receipts with `reason:'attempt_failed'`; it does not stop/re-settle the dispatch. Failure targets take precedence over an incidental extra `id` property. |
| `recovery/attempt-recovery-effects.ts`, `attempt-reconciliation.ts`, `recovery-service.ts` | Recovers lost failure-release timers after 60 seconds from the durable failure audit. Requires failed headless state, no Submission, and an eligible retained resource. Includes retained resources even when the Task has since reached a terminal stage; already-released resources are not released again. |
| `agent-factory/agent-factory.ts` | Read-only `selectWorkerProvider` uses the same installed set, policy, role, risk and RulesEngine selection as `build`. `buildWorkerContracts` creates one ContextPackage for the selected channel and one AgentSpec, then checks the provider did not change. |
| `codex-accounts/runtime-home-service-home-routing.ts` | Quota preparation catches only the account-layout call and returns `skip`, retaining the selection. |

Paths above are relative to `src/main/` unless stated otherwise. Existing `settleAttemptWithoutSubmission`, `retryOf`, subscription endpoint profile and release boundaries remain intact.
