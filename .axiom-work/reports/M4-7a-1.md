## Implementation and scope review

The existing table and transaction runner are reused. The shared contract validates lifecycle and rows without narrowing legacy hashes, risks or date strings. AxiomStore adds exactly four methods. The request and revocation functions accept the controller clock and rely on the caller transaction. Finalization passes its validated report hash after rebuilding the report; the controller moves then requests. Cancel revokes open delivery rows inside its existing transaction. Show reads the latest row regardless of status. Pending shows the matching pending request only in READY_FOR_APPROVAL. No approval RPC or CLI method, schema change, timer, effect, report change, gate change, scheduler change or renderer change was introduced.

New-request revocation and cancel both use the legal transition guard and expected status SQL predicate. Only actual transitions produce revocation audits. Optional resolver/resolution fields are preserved when omitted and can be cleared explicitly with null. Insert fixes PENDING and null resolution fields instead of accepting caller status. Row columns come from the dedicated Row shape; outcome/executed_at are excluded. A malformed stored cell produces a fixed error without its value.

Production source files stay below 300 non-blank lines: AxiomStore 285, MissionController 267, mission RPC 168, pending 194, finalization record 83. The existing integration e2e spec becomes 312 non-blank lines; its existing test/spec lint override is 800, and the required 13 added lines are within this brief’s 30-line e2e allowance. No existing e2e code was removed to make room, and no lint configuration changed.
