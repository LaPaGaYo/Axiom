## Implementation and scope

The Codex Worker channel on macOS/Linux now uses sandboxed `exec` inside Orca's existing terminal/dispatch lifecycle. The command builder resolves an executable through the existing Codex resolver and existing literal-executable override parser, uses the shared model/effort catalog, and passes the prompt via stdin. Windows, other providers, and the Planner retain their prior launch paths. Worker launch audits distinguish `headless` / `headless-sandboxed` from `tui` / `tui-bypass`; argv and stdin path are recorded without prompt content.

The service-only D14 extension prepares and binds the Attempt before creating a raw-command terminal, forces terminal mode, and skips startupAgent/default args, interactive readiness, and preamble delivery. It retains normal dispatch creation, terminal custody, `prepareStartingWorkerAuthority`, recovery, and release. The Bash wrapper tees stdout to `events.jsonl`, preserves Codex's status through `PIPESTATUS[0]`, publishes `exit-code` by rename, and keeps the shell alive for D76 release. No second process launcher or `child_process` import was added under `src/main/axiom`.

The host writes an immutable baseline/binding record and prompt under `<userData>/axiom/attempts/<attemptId>/`; the same prompt, with the Attempt id filled in, is written to `.axiom/prompt.md`. Headless context tells the Worker to re-read that file after compaction, put deliverables in `.axiom/artifacts/`, and finish with the strict JSON report. Terminal protocol bytes and their existing digest pins remain unchanged. The added headless fixture pin is `ctx_b471fb5ff6cab6ed5671c82e6fd7e6e063b9ddafa8dfc09539ff89d6cb5932e3`. Retry context retains the transcript reference but omits the CLI read recipe on the headless channel.

`attempt-exit-submission.ts` shares the existing per-Attempt serialization queue and caller-independent Submission transaction. The CLI retains its caller checks; host settlement checks the current dispatched dispatch, latest binding, RUNNING Task, Mission/Run, and worktree/branch. It computes changed paths from the recorded baseline and immutable Candidate, stores the final message as `worker_report`, ingests confined Worker artifact paths, and retains transcript archive/release. Attempt-attributed Artifact identities now include provenance, so identical bytes from different Attempts cannot inherit the first Attempt's metadata; underlying bytes remain deduplicated.

Headless snapshots use a private index, omit `.axiom/`, and update only the checked Attempt ref with a compare-and-swap old commit. Repository hooks are disabled. A linked-worktree test leaves a stale real `index.lock` in place and proves that the snapshot still succeeds, includes code changes, excludes even staged `.axiom/`, and adopts the same commit on a repeat snapshot.

Exit watchers and reconciliation use the same durable exit-file path. Nonzero exit or invalid/missing report settles without a Submission, with the D68 classification, exit code, selected error event/message, redacted last-message excerpt, and report validation error when applicable. Event parsing ignores unknown types/non-JSON lines, prefers `turn.failed` over reconnect `error` notices, and stores `providerSessionId` plus the last `turn.completed.usage` values without summation or double counting.

The installed exec help lines relied on are:

```text
Run Codex non-interactively
Usage: codex exec [OPTIONS] [PROMPT]
[PROMPT]
    Initial instructions for the agent. If not provided as an argument (or if `-` is used),
    instructions are read from stdin.
-c, --config <key=value>
    Override a configuration value that would otherwise be loaded from `~/.codex/config.toml`.
    Use a dotted path (`foo.bar.baz`) to override nested values. The `value` portion is parsed
    as TOML. If it fails to parse as TOML, the raw string is used as a literal.
-m, --model <MODEL>
    Model the agent should use
-s, --sandbox <SANDBOX_MODE>
    Select the sandbox policy to use when executing model-generated shell commands
    [possible values: read-only, workspace-write, danger-full-access]
-C, --cd <DIR>
    Tell the agent to use the specified directory as its working root
--color <COLOR>
    [possible values: always, never, auto]
--json
    Print events to stdout as JSONL
-o, --output-last-message <FILE>
    Specifies file where the last message from the agent should be written
```

`exec --help` does not advertise `-a`. The root help documents `-a, --ask-for-approval <APPROVAL_POLICY>` and `never: Never ask for user approval Execution failures are immediately returned to the model`. The exec builder therefore uses the supported `-c` configuration mechanism for `approval_policy="never"`, alongside `sandbox_workspace_write.network_access=false`. The config-key spellings are existing Codex configuration, not separate flags advertised by exec help. Model and reasoning arguments come from `CODEX_SESSION_OPTION_CATALOG`.

Final argv for a Worker with an explicit model:

```json
[
  "<resolved Codex executable or literal agentCmdOverrides.codex>",
  "exec", "--json", "--color", "never",
  "-s", "workspace-write",
  "-c", "sandbox_workspace_write.network_access=false",
  "-c", "approval_policy=\"never\"",
  "-C", "<Attempt worktree>",
  "-o", "<userData>/axiom/attempts/<attemptId>/last-message.md",
  "-m", "<AgentSpec.model>",
  "-c", "model_reasoning_effort=<AgentSpec.reasoning.effort>",
  "-"
]
```

`-m` and its value are omitted for `policy-default`; effort still maps from AgentSpec. Builder env is `{}` (the runtime supplies its existing host environment). stdin is redirected from `<attemptDir>/prompt.md`. The wrapper invokes `/usr/bin/env` with quoted argv so it cannot resolve Orca's Codex shell function. Neither sandbox-bypass nor full-auto flags are emitted. Compound/shell-expression overrides are refused by the existing literal-executable parser rather than interpreted as shell code.
