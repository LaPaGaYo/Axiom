Without a record, the component returns nothing. A ready record shows the Control Plane outcome word, the all-items-passed gloss, timestamp, target branch, both heads, and each recorded gate item in order. A stopped record shows its raw reason and gloss; an evaluated gate shows failed detail, while an unevaluated gate says so. Missing heads display a dash. A ready record without report fields says that no report was recorded. A report-bearing ready record exposes the Artifact id and twelve-character hash with the full hash in its title. Results use normal text colors; errors use the existing destructive token.

The report view is ordered as requested: Goal objective and optional constraints; zero-based criterion coverage with Task titles or unresolved ids; the ordered Task table (raw/glossed stage, candidate, verification status and check counts, optional human verdict, regression and merge commit, cancellation rationale); only populated Task writing blocks; Control Plane recorded risks or its empty sentence; plans and provenance with risks and mitigations; heads, promoted commits and Decision count; a button to expose raw JSON. Lists have visible labels and no accessible names of their own. The report adds no Task navigation, evidence opener, export, copy, or download. Check commands, full verification rationales, attempts and other contract detail not assigned a structured label by the brief remain available in raw JSON; no extra label or localization key was invented.

All report values are React text children. Text wraps and preserves line breaks; the raw JSON has bounded height and the standard scrollbar. No content is passed to a rich-text renderer, executable element, external resource, or navigation target. The only report content used in a title is a validated commit. Stage glosses reuse `TASK_STAGE_LABELS`; no `TaskStageBadge` is rendered, and none of the five existing page selector attributes is used by the new views.

## Read isolation and stale answers

The component has one client call site: `axiomClient.readArtifact({ id: artifactId })`, only in the disclosure button handler. There is no effect that fetches and no timer. A child keyed by Artifact id **and recorded hash** owns its read state, so a fresh but equivalent Mission response preserves the report without another read. The Mission-level key resets it on selection changes. A new Artifact, changed recorded hash, missing report reference, stopped record, or missing finalization unmounts that child.

Each click increments a generation counter. Hiding while loading is allowed and immediately closes the disclosure. Cleanup also increments the counter. After the await, the current generation must still match before either success or failure can update the view; answers from hidden or replaced reads are dropped. Hiding and showing again starts a new read, as permitted by the brief.

Validation is ordered: kind, media type before the semicolon, metadata hash against `reportSha256`, then base64 bytes, fatal UTF-8 decode, JSON parse and strict `CompletionReportSchema`. A hash mismatch has its dedicated sentence; every other failure has the read-failed sentence. Only a rejected request appends the unmodified `missionErrorText` code/message in monospace, separate from the sentence. The renderer never hashes bytes or computes completion/approval eligibility.

## Limits and interpretation

1. The section shows only the latest finalization record after the most recent entry into FINALIZING. It shows none while the Mission is being finalized again, until another record exists. Read-side status handling is unchanged: the record can remain after COMPLETED, CANCELED, or FAILED.
2. A record written before M4-10 shows its seven gate items and no report. A runtime that omits finalization has exactly the earlier page layout.
3. Gate rows show how many references an item was judged by, not their identities. Their ids are available in the report's raw JSON when a report exists. The record caps evidence at 200, so the displayed count also stops at 200; the page does not infer truncation or list unavailable identities for a stopped record.
4. The report is read whole, up to 8 MiB, into memory and rendered without paging or virtualization. Expanded raw JSON repeats that content in a bounded scroll area. Large reports may be expensive to parse or render; this task adds no streaming, pagination, or chunking.
5. The hash comparison checks two values sent by the main process. It establishes that the read Artifact is the one the finalization recorded, not that the main process is honest. The main process verifies stored bytes; the renderer does not hash them.
6. Report texts are shown as stored, in whichever language they were written. They are neither translated nor redacted by the page. What a Worker or person wrote in a summary, rationale, question, command, risk, or Goal can therefore be visible as stored; the page does not upgrade those claims into verification evidence. The schema checks structure, not the truth of prose.
7. Nothing in the report can be opened: no Task, run, or Artifact. There are no export/copy/download controls. Full stored details beyond the requested structured summary remain in raw JSON.
8. The section offers only display toggles and no Mission-changing action. A person still cannot approve or deliver from this page. Approval and delivery controls belong to M4-11b; existing MissionActions elsewhere are unchanged.
9. New strings exist in en and zh only under D94. The other five languages fall back to English. Refusal code/message text remains the Control Plane's original wording.
10. The two extended Electron specs observe a real ready record of a completed Mission and a real stopped record caused by target-branch movement. A stopped record with gate (`completion_gate_failed`) and the other three reasons (`target_branch_not_found`, `integration_head_unexpected`, `finalization_unavailable`) are covered only by unit-built records. All five stop glosses are asserted by the component test.
11. Local UI evidence is happy-dom behavior, not a pixel/layout run on macOS, Windows, or Linux. Electron host runs remain required and have not been claimed as passed here. Existing Button, table, definition-list, token and scrollbar conventions are reused without platform-specific code.
