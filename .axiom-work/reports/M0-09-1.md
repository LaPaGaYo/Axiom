## Attribution details

On macOS/Linux, each connection runs:

```sh
lsof -nP -a -iTCP:<remotePort> -sTCP:ESTABLISHED -Fpcn
```

The extra `n` field is essential: a port filter returns both sides of a loopback connection. Only a socket name matching `remoteAddress:remotePort->localAddress:localPort` supplies the client PID/command; the reverse proxy endpoint is ignored. The lookup uses no shell, captures at most 64 KiB, and has a 1,000 ms timeout through `runProcess` (whose existing termination handling can add exit grace). Missing tools, unsupported platforms, errors, timeouts, truncated output, and no match produce null, never omitted requests.

Recording happens immediately. Refusal waits for the bounded lookup to preserve an ESTABLISHED socket for inspection, then returns the same HTTP/CONNECT 502 or destroys an upgrade. This introduces diagnostic latency and may affect retry timing/counts; host tallies must be treated as measurements of the instrumented capture. Socket identities are cached in a WeakMap, not by a reusable numeric port.
