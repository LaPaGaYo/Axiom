## Necessary differences

- The precise capability rule checks the current reported harness version against evidence. It does not impose an extra predecessor-version equality condition absent from that ordered rule.
- To reuse the existing ending sentence for both preserved and empty predecessors without fabricating a SnapshotAttemptBaseline, `endingLine` is exported and its parameter is narrowed, type-only, to the two fields it already consumes. Runtime behavior and every sentence are unchanged. This is slightly beyond “may only gain exports”; together with the export-only `readEnding` change, the two files remain within the sidecar's eight-line delta cap.
- The snapshot helper stays pinned. All new Git commands and the private-index snapshot input carry the preservation timeout, but the helper's first branch check ignores that input and uses 120 seconds. The 30-second per-Git-read requirement is therefore not fully met; a minimal optional timeout parameter and forwarding call would resolve it, requiring a sidecar exception. No timer or parallel snapshot implementation was introduced.
- The required pnpm entrypoints and host Electron gates could not be certified here. Direct checks and their exact limitations are reported above. The unmodified broad CLI/helper tests have environment-sensitive failures; this task does not alter them.

## Limitations and risks

- A takeover that fails after writing a ref leaves launch_failed. There is no fresh-placement fallback within that launch; the next Attempt follows ordinary launch-failure baseline selection from the integration base. Prior branch and preserved snapshot evidence remain.
- The kernel worktree record can lag its real branch. This implementation uses binding.branch and real Git, not that branch projection.
- An explicit model together with resume has not been probed on the real harness. The command builder retains model/effort exactly as instructed and unit-tests their placement.
- A rollout that exists but cannot be read passes the filename/metadata check; only the harness refusal exposes that condition. Contents are never read for resume eligibility.
- Resumed usage is the session's running total, not an Attempt increment. No differences or token budget are calculated.
- Resume is disabled for every harness version without evidence, silently apart from capability_unproven in the launch audit.
- Earlier workers' owned terminal resources may accumulate in the reused worktree; releasing them remains deferred.
- Harness descendants can outlive the accepted exit marker and still write into the reused worktree. The continuation cautions and independent final verification remain necessary.
- Claude does not resume (DEF-50); neither do TUI or planner sessions. No Windows/WSL support or session-length threshold was added.
- Filesystem reads, Git admission waiting and multiple commands have no aggregate deadline. The inherited first-branch timeout conflict remains as detailed above.
- Host e2e execution, broad process/socket fixtures, candidate sealing and independent verifier acceptance are outstanding. This report does not mark the milestone complete.
