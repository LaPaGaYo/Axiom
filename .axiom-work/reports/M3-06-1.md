AFTER DELETE ON missions

END;

## Effect outcomes

**Enqueue and lease.** Enqueue refuses calls outside an existing transaction. A new or non-running `(kind,key)` row becomes pending with the supplied payload, failure count zero and canonical ISO due time; a running row is unchanged. The caller's rollback removes the enqueue as well as its command state. A post-commit microtask requests the coalesced drain. The oldest due row is leased with status/epoch fencing only when no same-kind/Mission row is running. Execution occurs outside any transaction. Independent lanes can begin while another lane is awaiting its executor.

**Done.** An executor returning `done` completes the fenced running row. An effect for an older sequence is skipped before launch; a bound/no-longer-running Attempt is still guarded by the unchanged launcher. A launcher that internally records its own failure and returns produces a done effect while preserving the original failure/settlement audits. Verification enqueue finishes after requesting the existing drain without awaiting that drain.

**Later.** `{later: ISO}` returns the fenced row to pending without increasing attempts. The one unref timeout wakes the earliest future eligible due row. E2E dispatch hold uses this outcome at 250 ms intervals. Stop clears the timer, refuses new kicks until start, and allows active executions to finish.

**Retry and failed.** A thrown execution error is redacted through redactContext, truncated to 2,000 characters, and increments attempts. Non-exhausted failures return to pending at the configured backoff. At the limit, failed state and `effect.failed` audit commit together, then onExhausted runs. Dispatch allows one failure and retains the former Scheduler launch_rejected audit/settlement; verification wake allows three failures with 1 s/5 s backoff.

**Boot retry, done, or retirement.** Only running rows leased by a different process epoch are recovered. Handler retry returns pending due now without changing attempts; done completes the row; retirement records retired state and `effect.retired` atomically, leaving the reason in lastError. There is no time-based lease expiry. The dispatch orphan decisions and database evidence are recorded below.

## Limitations and risks

- One dispatch executes at a time per Mission; different Missions and effect kinds have independent lanes. v0 assumes one Control Plane process owns the database and has no time-based lease expiry.
- An orphaned in-flight launch with an unbound kernel dispatch is retired and still costs an Attempt through the existing orphan rule.
- `done` rows are never pruned. Done means the executor returned, not Worker success or verification completion.
- An older build opening the database ignores pending effects and retains its own orphan behavior.
- Existing Attempt runtime-budget measurement still starts at binding creation; this Task does not redefine how queue or restart delay affects that budget.
- External Codex/Gemini bridge availability was not established; the fallback reviews are local, not cross-provider.
- Host Electron acceptance remains verifier-owned. No Electron process was launched in this sandbox.

## Necessary differences and implementation choices

- Final review reproduced a stale replay edge: seq 1 timed out unbound, seq 2 was admitted, boot retried seq 1, and seq 2's kernel process exited before Axiom reconciliation. The unchanged launcher could then start seq 1 while seq 2 remained authoritative. The dispatch executor therefore skips an effect whose seq is no longer the latest binding sequence, marking it done without reaching the launcher. This is an extra idempotency guard; the specified three orphan branches, launcher, settlement, retry counts, and stage rules stay unchanged.
- Effect recovery failure prevents startup dispatch/reconciliation/resume. Only the current boot generation clears `started`, so a failed old boot cannot overwrite a newer successful start; the next boot can retry recovery. The brief did not specify recovery-exception behavior.
- New execution/recovery code lives in `outbox/effect-execution.ts`; product executor registration lives in `outbox/mission-effect-executors.ts`. No existing functions were moved. The outbox constructor starts stopped, matching the required stop/start lifecycle.
- The E2E test reuses the frozen fixture's `agent-crash` successful continuation and the existing human-review deterministic content criterion, avoiding dependency installation. No new fixture scenario was invented.
- Mapping metadata now counts 12 query indexes and four delete triggers: the pre-existing DDL had 11 indexes and three triggers, despite the older reference text's count. Schema version stays 46.
- Scripted typechecks are blocked by tsx's IPC listener; direct repository compiler runners provide additional evidence, not a claim that the scripted commands passed. No dependency rebuild or borrowed toolchain was used.
