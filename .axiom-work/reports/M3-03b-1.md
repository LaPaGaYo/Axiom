## Implementation and exact rules

candidate-diff.ts now returns removedText alongside addedText, collected only inside hunks. Both maps use the same section ordering and T-entry two-section pairing. Headers are excluded; an incomplete patch leaves both maps empty.

test-tampering.ts is a pure function. A test file matches any testPathPatterns entry using shared path-patterns semantics. Defaults are:
~~~json
["**/*.test.*", "**/*.spec.*", "**/__tests__/**", "**/test_*.py", "**/*_test.py", "**/*_test.go"]
~~~
An explicit policy list replaces these defaults, including an empty list.

Each file uses added occurrences minus removed occurrences. Findings contain only path, rule and positive count, sorted lexically by path then rule:

| Rule | Condition | Count |
| --- | --- | --- |
| test_file_deleted | D entry for a test file, unless exempt below | 1 |
| test_skip_added | Test-file skip/focus/pending occurrences increase | Net increase |
| assertions_reduced | Assertion occurrences decrease in a test file whose status is not D | Net decrease |
| suppression_added | Suppression occurrences increase in any file | Net increase |

Exact JavaScript patterns (all source is ASCII; global matching, and multiline only for the Python assertion rule):
~~~ts
const SKIPS = [
  /\b(?:describe|it|test|suite|context|bench)\.(?:skip|only|todo|skipIf|runIf|fails)\b/g,
  /\b(?:xit|xtest|xdescribe|xcontext|xsuite|fit|fdescribe|ftest)\s*\(/g,
  /@pytest\.mark\.(?:skip|skipif|xfail)\b/g,
  /\bpytest\.skip\s*\(/g,
  /@unittest\.skip/g,
  /\bt\.Skip(?:f|Now)?\s*\(/g
]
const ASSERTIONS = [
  /\b(?:expect|assert)(?:\.\w+)*\s*\(/g,
  /\bassert[A-Z]\w*\s*\(/g,
  /^\s*assert\s/gm,
  /\.should\b/g,
  /\bt\.(?:Error|Errorf|Fatal|Fatalf|Fail|FailNow)\s*\(/g
]
const SUPPRESSIONS = [
  /(?:eslint-disable|oxlint-disable|biome-ignore|@ts-ignore|@ts-nocheck|@ts-expect-error|#\s*noqa\b|#\s*type:\s*ignore|pylint:\s*disable|\bnolint\b|istanbul\s+ignore|c8\s+ignore|v8\s+ignore)/g
]

~~~

Deletion exemptions are narrow: (1) an A entry that is also a test file has the same collected added text as the D entry's collected removed text; or (2) an allowedPaths entry, normalized by normalizePathPattern, equals the deleted path exactly. Broad directories, repository-wide entries and wildcard entries do not grant the exact-path deletion exemption. A move with edited content still reports deletion of the source. These exemptions affect only test_file_deleted; they do not exempt skips, assertion reductions, suppressions, scope or secrets.

evaluateDiffGate runs tampering only for a complete patch and retains findings even when secret/scope/check failures win. verdictDetail.diff caps each list at 50, the full diff evidence Artifact at 1000, and counts.tampering records the uncapped number of findings. A winning test_tampering verdict adds up to 50 findings to verification.inconclusive audit evidence and always escalates to human. The Task remains VERIFYING.

## Artifact checks and non-code Tasks

A non-code Task has no non-empty requiredEvidence command after trimming. Repository gates and setup commands still execute and do not change that classification.

After command execution, checkWorkerArtifacts loads the Candidate's Submission via getSubmissionByDispatch(candidate.attemptId) and checks every report.artifacts reference through ArtifactStore.read:

- Read/metadata corruption or missing bytes: unreadable, with no raw storage errors in evidence.
- Zero bytes: empty.
- text/*, application/json and application/*+json: fatal UTF-8 decoding; invalid bytes produce invalid_utf8.
- JSON media types also parse; invalid syntax produces invalid_json.
- Media-type matching ignores case and parameters after a semicolon. Other media types require readability and nonzero bytes only.

Every completed run through runVerificationChecks, including invalid-policy and remote-repository results, records this object in verdictDetail and the verdict evidence Artifact:
~~~text
artifacts = {
  required: boolean,
  checked: [{ id, kind, mediaType, bytes, problem? }], // at most 50 references
  counts: { checked, unreadable, empty, invalid_utf8, invalid_json }
}
~~~
The summary preserves submission-reference order. Counts cover all references even beyond the 50-entry list. Unreadable entries retain available metadata; unknown fields are null. No Artifact content is copied into this summary. Each reference records one primary problem, in read → empty → UTF-8 → JSON order.

Non-code Tasks without references fail artifact_missing; empty/invalid UTF-8/invalid JSON fail artifact_invalid. Unreadable Artifacts are environmental, INCONCLUSIVE(environment), detail artifact_unreadable, escalation human. Valid Artifacts cannot automatically PASS a non-code Task: absent a higher-priority reason, non_code routes to human for human_confirm or rules.inconclusiveRouting for artifact_only. This also covers plans with no commands. Code-Task Artifact problems are evidence only, and never change the verdict.

Precedence is:
~~~text
secret_detected
scope_violation
checks_failed
artifact_missing / artifact_invalid (non-code only)
environment (diff unavailable or non-code Artifact unreadable)
diff_too_large
test_tampering
dangerous_change
environment (environmental check)
flaky / known_flaky
environment (skipped check)
non_code
PASS
~~~
policy_invalid remains unchanged. When diff unavailability and Artifact unreadability coexist, the diff reason is retained within their shared precedence tier. FAIL settlement and claim fences remain unchanged.

## False positives and limitations

- Rules are the specified lexical patterns, not an AST or semantic proof. Marker/assertion text in strings, comments or documentation can count; legitimate expected-failure tests, assertion consolidation and justified suppressions require review. Changing assertion arguments or replacing equal numbers of assertions may evade counts.
- Netting is per file. Moving skip/suppression markers across files can flag the destination even if the deletion is exempt as a pure move. Pattern matching can span the joined changed lines; it does not reconstruct unchanged lines.
- Rename comparison uses the specified collected patch text, without final-newline metadata. Binary sections carry no text; this is not a bytewise binary equivalence check. Truncated patches have no content findings and require human review through diff_too_large.
- A policy can replace testPathPatterns (even with []), changing which paths get test-specific rules; suppression checks still apply to every file. The allowedPaths deletion exemption does not waive any other rule.
- Artifact validation is readability, nonzero bytes, UTF-8 and JSON syntax only. Non-empty whitespace text is allowed; JSON primitives are allowed; non-text/non-JSON media types are not decoded. Semantic usefulness and per-kind schemas remain for Reviewer/human confirmation and the future requiredArtifacts contract.
- All references affect verdict counts, but only the first 50 Artifact references are in the persisted checked list. A problem after that cap still prevents a non-code PASS but its id is not in the short fix-loop section. Diff evidence separately retains up to 1000 findings.
- Artifact reads use the existing content-addressed store and its hash checks; no migration, new storage mechanism or new dependency.
- Runtime write-scope enforcement for CLI agents remains the documented V1 limitation; these rules enforce verification-time policy only. No new Approval or M3-05 review routing was implemented.
- Host Electron regressions and sandbox socket/process failures remain external verification work, not accepted failures or disabled tests.
