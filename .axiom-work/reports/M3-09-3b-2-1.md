The interval is installed by `useMissionsPageController` at its `installWindowVisibilityInterval` effect, with `intervalMs: 5000`. Its dependencies, `canRead` and `refresh`, are stable callbacks. The read hook registers the mount/selection effect first, so the helper's synchronous installation callback sees the mount read already pending. The effect returns the kernel stop function. Visibility behavior is entirely the kernel helper's; view exit unmounts the page through the existing `AppWorkspaceShell`.

Idle means `reads.current.pending === 0`, no recorded read failure, `confirmingRef.current === false`, `missionCreateOpen === false`, and no pending `missionRequests` entry. Store values are read at the tick, not captured at installation. The count includes superseded reads until they settle; a selection can still start its normal read immediately. Skipped ticks are dropped.

Both manners call the same `refresh` body, with the original `Promise.all([listMissions(), readMission(...)])` and generation check. Quiet reads omit loading changes and successful error clearing. A current failed read sets the failure flag; quiet reporting writes only the existing error line, while foreground reporting retains its toast. Only a current successful foreground read clears the flag and error. No component, `mission-read.ts`, Task evidence reader, client, store, translation, runtime or helper file changed.

## Limits and risks

- The page can be one interval behind the Control Plane, and further behind while a read is slow or the page is not idle.
- A skipped timed read is not queued.
- After a failed read, following stops until a successful non-timed read: the person can refresh or select, or a mutation can trigger reconciliation. Nothing but the error line announces the pause; there is no retry or backoff.
- A read that no longer offers an action still closes its form under the existing component behavior. This can now happen without the person requesting a read and may invoke that existing form-close focus behavior.
- A partial failure in the pending view, verification runs or usage shows its existing note, just as after a manual read. Partial failures retain their existing form consequences.
- Nothing follows while the document is hidden or another view is open. Becoming visible requests an immediate read through the kernel helper, subject to the same idle rule.
- Independent host verification and screenshot review remain necessary; this implementation report is not an acceptance decision.
