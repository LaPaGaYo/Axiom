## Summary

- Artifact bytes live at an injected root/<sha256>; writes use a random temporary file then rename. Rows hold metadata only. Artifact identity binds Mission/kind/content; repeated puts return first metadata, while different kinds or Missions share bytes. Reads verify hash and size, including missing-file corruption. The service and wire put path enforce 8 MiB; ids/hashes are validated before path resolution.
- AxiomStore now provides artifact insert/get/list, ContextPackage insert/get, and Mission/status-filtered Decision reads. Zod codecs validate every row and JSON cell. The audit codec was split by concept to keep the row module compact. No SQL schema changed.
- Seven mandatory sections are rendered in the prescribed order, followed by upstream handoff/worker_report evidence and the D16 protocol. Candidate ordering reuses the existing edge order (from_task_id), then artifacts.created_at/id, with duplicate Artifact ids removed. Budget exhaustion drops the remaining ranked suffix; mandatory content survives even a zero-token budget.
- Repository rules are read with git show at the target branch, never from the worktree. Only AGENTS.md and CLAUDE.md are read; each is capped at 16 KiB after redaction. Missing files are omitted; a bad branch or repository fails rather than silently omitting safety rules. UTF-8 clipping avoids introducing a replacement character.
- Private-key blocks, specified provider token prefixes, and AKIA keys are redacted. The task's ghp_ test case requires underscore support in addition to the supplied hyphen regex; both are covered. Redacted candidates remain usable as sanitized text and have a redacted omission record; repository headers carry the redaction marker.
- Manifest serialization fixes all object key orders and preserves arrays. Identity is ctx_ + SHA-256(canonical manifest), without timestamps or live Attempt credentials. Protocol bytes are hashed and charged in mandatory section 4 even though the protocol renders last. The rendered template and manifest are persisted as separate Artifacts; mandatory_refs stores [manifestArtifactId, renderArtifactId], ranked_refs stores included upstream Artifact ids. Repeated builds perform no insert calls or file writes.
- The Control Plane exposes artifacts and contextBuilder; the root is computed there through getAppEnvironment().getPath('userData'). New methods are aggregated and axiom.artifact.put participates in the existing mutation fence and durable receipts.

## Limitations and follow-ups

1. M2-05 must replace **every** literal {{attemptId}} and {{dispatchCapability}} at delivery time using the admitted Attempt and its actual capability. Do not persist the substituted capability in the ContextPackage or alter package identity. The protocol lists all eight D16 verbs; M2-06 implements their remaining payload semantics.
2. M3 replaces section 7's fixed `none (first attempt)` with attributable prior-Attempt failure evidence. This task does not implement retry selection, verification, or integration.
3. Shared BudgetSchema is strict and currently rejects contextTokens. The allowed database code can read/validate this optional field if already present in policy JSON, while preserving the old shared policy projection. The existing policy mutation contract is unchanged; adding a public policy setter for contextTokens needs a follow-up within that contract's scope. An explicit build tokenBudget works now.
4. ArtifactStore is a byte-preserving evidence store. Sanitization occurs when building context; original caller-provided evidence may contain sensitive bytes and must be authorized appropriately. ContextPackage artifacts contain only sanitized context. Regex redaction is the exact bounded M2 subset (plus the necessary underscore variants), not a general secret scanner.
5. The 8 MiB cap also applies to internal puts. Garbage collection/retention of crash-left temporary files or unreferenced content is not introduced here. A repeated metadata put preserves first-writer related/mediaType/createdBy values by contract.
6. CLI agents still lack runtime write-scope enforcement. The rendered submission contract explicitly requires verification-time diff inspection; no runtime permission expansion is implemented.
7. Resolve the three scope registrations above and rerun their tests; rerun real-Electron startup tests on the launcher host. Only then can the launcher create an immutable Candidate and perform independent acceptance. M2-02 remains open.
