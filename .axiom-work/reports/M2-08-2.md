This is the kernel's intended boundary, consistent with the upstream parity evidence supplied in the addendum.

- Cancellation now abandons a pre-existing `stop_unknown` worker regardless of host observation, then calls the existing release service. Its `attempt.abandoned` audit includes `reason: mission_canceled`, `priorStop: stop_unknown`, the folded host liveness at abandonment, disposition, and release receipt. `start_unknown` continues to use the supported stop path when live/exact.
- A RUNNING `stop_unknown` row uses the existing uncertainty/tolerance path regardless of observed liveness. The next tick records `{status: unverifiable, reason: stop_unknown}`; repeat ticks preserve the clock, Task stays RUNNING, and tolerance expiry creates evidence, abandons through the kernel, and settles through NEEDS_FIX to READY/BLOCKED.
- Reconciliation reports retain the actual folded host observation. The `stop_unknown` fact explicitly describes the uncertain stop outcome; it does not fabricate an observed process exit.
- Factored the existing indexed Attempt-audit lookup so cancellation can reuse its previous `priorStop`/liveness on release-only replay. A changed host observation on the third tick does not create another abandonment event.
- Renamed and corrected the cancellation regression; added runtime-budget cases with both live and exited host observations; updated the stranded-stopping expectation to `reason: stop_unknown`. Tests check one stop, one clock, no new binding, evidence, release disposition, and idempotence.

Execution sequence: verify the addendum against the kernel, write failing regressions, apply the narrow Control Plane fix, update Recovery documentation, run the original gates and negative control, then hand off for independent verification.
