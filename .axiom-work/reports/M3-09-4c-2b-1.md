## Limits and delivery boundary

- The write has no revision check. Two windows or a concurrent CLI save can overwrite each other key by key. An untouched field is rebuilt from the page's latest read, which may be one refresh old; this is not a server-side compare-and-swap.
- An emptied gate list is unset. An explicitly empty list can be retained but cannot be created here; clearing setup yields `[]`.
- The form cannot repair rules that do not parse; only concurrency remains editable.
- The first rules update makes today's schema defaults explicit for every absent defaulted key, just as any Control Plane rules update does. Later default changes no longer reach those values for that Mission. A concurrency-only update does not rewrite rules.
- A failed policy read during editing blocks saving until a read succeeds; the draft remains local.
- Commands receive no validation beyond nonempty trimmed lines; they run as written on this computer. A policy change does not alter a verification run already running.
- Confirmation names changed fields, not values, and joins labels with the same comma and space in both languages.
- Routing is neither shown nor edited; eligibility/provider controls and the pending-item entry are M3-09-4c-2c.
- This section shows no change history; audit records retain it.
- The other five locales show English for the new strings.
- CLI Worker write scope remains a verification-time diff check; this Attempt kept its changes to the explicit allowlist.
