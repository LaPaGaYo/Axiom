## Limitations and follow-up Tasks

- M1-03/04/05: persist each Mission's synthetic `axiom-mission-<UUID v4>` id and Run id. Do not recreate the Run on restart or reuse its id for another Mission. Test Mission/Run transaction and crash composition before relying on createRun inside a lifecycle transaction; its current implementation owns BEGIN IMMEDIATE.
- M1-05/07: materialize empty-deps Tasks, keep authoritative readiness in task_stages, and reject non-Control-Plane dispatch and nonempty Mission deps. This spike does not implement these guards.
- M1-08: register the existing Run waiter dependencies, consume backlog after restart and make processing replay-safe before ack. DB reopen is proven; runtime restart, scheduler recovery and side-table recovery are not implemented here.
- M2 Scheduler/worker-start adapter Task (no numbered M2 plan exists yet): add optional `worktreeId?: string` and `branchNameOverride?: string`. Reuse the existing managed-worktree service; validate placement/branch ownership and mutually exclusive creation options. Keep `callerSession.workspaceId` as the Mission repository workspace.
- M2 adapter Task: add service-only `dispatchCreator?: DispatchCreator`, defaulting to legacy resolution; the Control Plane supplies `{ kind: 'system' }`. Populate existing `params.from = caller.address` and both `coordinator` and `callerSession`. Never accept an RPC-supplied system principal or make the dispatcher accept synthetic session claims.
- M2 ContextBuilder/Worker protocol Task: add trusted `preambleBuilder?: (params: PreambleParams) => string` through startLocalWorker, readiness and preamble delivery. Changing the already-existing cliCommand is insufficient for `axiom attempt` verbs and ContextPackage content.
- M2 policy/lineage follow-ups: consider internal `dispatchMaxDepth?: number` for the Mission cap of 1, and `callerIdentity?: OrchestrationCallerIdentity` in kernel worktree-creation args if that path remains in use. A precreated `worktreeId` bypasses the synthetic-address-as-terminal-lineage issue. Preserve old behavior when optional fields are absent.
- M1-10: reconcile stale mapping text and qualify D6a's ordering rationale. The accepted sequence-based branch rule remains in force; this Worker did not amend Decisions.
- No full startLocalWorker, terminal, provider, transport, host-liveness, Candidate-retention, QUESTION or production migration behavior was exercised. The assumption table explicitly limits certification of the broader mapping §4a rows. No external audit or immutable Candidate exists until the launcher performs its separate verification/commit flow.
