Identifier timing:

- `mission.id` exists when the fixture calls the callback, after desktop Mission creation. It can be used for settings before any Worker is released.
- Task id exists after the plan materializes. Waiting for one binding guarantees a Task exists; only task_id is read at this point. A binding may initially have a null dispatch id, and the spec does not use that early id.
- Attempt 1's dispatch id is minted/bound during launch and is read only from `attempt.stopped.object_id`, after a confirmed kernel stop and the audit transaction. It then identifies supervised, preserved, started and cadence rows.
- The preserved snapshot ref/commit exists after stop confirmation and capture, before `attempt.preserved` commits. The spec reads both from that persisted audit before resolving the ref and identifying the retained worktree.
- The successor is a new seq-2 Attempt. Its branch/binding/dispatch and started audit exist before it submits. The spec reads its id only after a persisted Submission appears, then uses it to find the started audit and prompt file.
- Submission id and Candidate id are assigned during submission settlement; the spec reads candidateId only from that persisted Submission and resolves the Candidate row in the same read snapshot. Candidate commitSha is then used for a Git tree membership check. No pre-launch Candidate or Submission id is assumed.
- No Artifact id or ContextPackage id is used as an early synchronization condition; the spec does not dereference either.

## Limitations and risks

- The effective mode is read once per Attempt's supervision pass. A change after that read takes effect on its next pass; it does not revoke an in-flight stop.
- A notify item remains listed until its Attempt is no longer the latest unsubmitted RUNNING Task binding, even if output resumed. No UI, desktop notification, message or effect is created.
- Stop has no wrap-up phase. It uses the existing kernel stop contract, then confirmed exit, preservation and settlement.
- Silence/cadence measurement has 60-second resolution. Events between samples are not a precise event-gap trace; no sampling timer was added.
- A Worker able to write its attempt directory can keep events.jsonl fresh. The heuristic cannot authenticate useful progress; the unchanged runtime budget remains a backstop when configured.
- Global default changes have no Mission audit, only their immutable revision with actor/provenance and audit watermark.
- As before, a crash after kernel stop but before Axiom settlement is recovered as kernel_stopped; stop_unknown does not prove exit and cannot preserve or settle in this path.
- Write scope for CLI Workers remains a verification-time diff check, not runtime filesystem enforcement.
- Host Electron acceptance is still required. The full sidecar test command is not green in this sandbox; process inspection and Unix socket creation are restricted, and existing unrelated CLI tests also require host follow-up. Their source was not changed.
