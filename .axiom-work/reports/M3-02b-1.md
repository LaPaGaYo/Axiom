## Settlement order

1. Authority/report checks and Candidate snapshot remain unchanged. Refused submissions, including `candidate_unchanged`, never archive or schedule release.
2. `runLifecycleWriteTransaction(..., 'axiom_submit', ...)` commits Candidate, Submission, observation facts, worker success, Task SUBMITTED, queued VerificationRun, and settlement audits.
3. The existing asynchronous verification `kick` is invoked.
4. `archiveAttemptTranscript` is awaited outside the transaction, while the Worker is still alive.
5. `publish(result)` persists the SUBMISSION message and records the completed mutation receipt.
6. `scheduleSubmittedWorkerRelease` installs an unref timer for `WORKER_RELEASE_GRACE_MS = 2_000`.
7. The timer calls `releaseSubmittedWorker`, which delegates to Orca `releaseLocalWorker`. Orca owns release request, identity proof, its own archive, terminal close, and daemon descendant sweep. Axiom never calls `stopLocalWorker` for submission release.

Authenticated duplicate submits only replay/publish the existing result. They do not rearchive, rekick verification, or schedule release. A publish failure also leaves no release timer; recovery handles the lost-timer case. The delayed-storage test confirms the receipt remains pending until Artifact storage completes and that advancing timers while storage is blocked cannot release the Worker.

## Artifact and process evidence

One content-addressed Artifact is written through the existing Control Plane ArtifactStore:

- `kind: log`, `mediaType: application/json`, `createdBy: AttemptSettlement`.
- `related: [taskId, attemptId, submissionId]`.
- JSON: `{type:'attempt_transcript', version:1, missionId, taskId, attemptId, submissionId, capturedAt, source, status, processesAtSubmission, content}`.
- `source`: `structured_journal`, `transcript_pin`, or `terminal_tail`; `status`: Orca's `captured` or `empty`.
- Every string value in captured objects/arrays passes through `redactContext` before JSON serialization. Object keys and non-string values are preserved. The reader's original object is not mutated.
- If the serialized document exceeds `MAX_ARTIFACT_BYTES`, only `content` becomes `{omitted:'too_large'}`. Attribution and source/status/process evidence remain.
- Mission/Task/Attempt/Submission ids are embedded in the bytes, preventing identical output from different Attempts from sharing the first Artifact's relation metadata.

Process evidence uses `inspectTerminalProcess` live POSIX evidence, the fence's PTY shell PID, a fresh process table, and the existing indexed descendant walker. Zombies are dropped. `count` includes all remaining descendants; `names` contains only executable basenames, sorted, unique, and capped at 50. Arguments are never stored; basename strings are also redacted defensively. Unsupported/missing/throwing inspection records only a fixed `{unverifiable: reason}`. Persisted host scope prevents using remote or WSL PIDs with the local process table.

`attempt show` adds optional `submission.transcriptArtifactId`, selecting the newest matching Mission log Artifact created by AttemptSettlement and related to the Submission. CLI text prints `Transcript: <id>`. Old payloads remain valid. The existing `workspace` projection becomes `released` when the kernel resource is released. `docs/GLOSSARY.md` already defines this as a neutral resource projection and did not require an edit.

## Audits and recovery

All four effect audits use `objectKind: attempt`, `objectId: attemptId`, actor `AttemptSettlement`:

| Event | `after` |
| --- | --- |
| `attempt.transcript_archived` | `{submissionId, artifactId, source, status, processCount?}` |
| `attempt.transcript_archive_failed` | `{submissionId, reason}`; reason is `capture_failed` or `store_failed` |
| `attempt.terminal_released` | `{submissionId, state, processAction, archive}` copied from the kernel receipt |
| `attempt.terminal_release_failed` | `{submissionId, reason:'release_failed'}` |

No raw exception text or kernel `lastError` is recorded by these effects. A failed archive or release does not undo the settled Submission/Candidate, Task stage, or VerificationRun. Failure to write even the failure audit produces only a fixed warning with ids, preserving receipt delivery. `attempt.terminal_released` is the audit of a release receipt; its `state` remains truthful if the kernel returns retained/pending/unknown rather than released.

Recovery releases only a Submission at least 60,000 ms old whose owned resource is `not_requested`, `retained`, or `requested`. UTC timestamp parsing reuses the kernel helper. Younger, gone, released, releasing, or unknown resources are left alone. If neither transcript success nor transcript failure audit names that Submission, recovery archives first, including a fixed failure audit if capture is no longer possible. It then uses the same release effect. Recovery does not change Task stage or the Submission.

`AXIOM_E2E_HOLD_WORKER_RELEASE` is read only after `getMainE2EConfig().enabled`. Setting it to `1` suppresses scheduling and direct/recovery release; initial submission archival still runs. `withFixtureMission` enables the hold by default; `releaseTerminals:true` omits it.

## Limits and follow-up

- The archive is bounded recent output, not full history: Orca caps terminal tail at 262,144 characters, structured journal at 262,144 bytes, and provider transcript at the last 50 messages with its block/message bounds. Mid-turn provider-source races may fall back to terminal output.
- SSH provider transcript files cannot be read locally and fall back to the terminal tail. Process-tree evidence is local POSIX only; Windows, WSL guests and remote scopes report unverifiable. It is informational and never a submission refusal or permission decision.
- The immutable Candidate is the D4 snapshot. Work still running after that snapshot is excluded; verification assesses that Candidate. The release receipt proves the kernel close operation, not a new independent per-descendant death census.
- The two-second grace is the established receipt-delivery allowance, not a transport acknowledgement handshake. A crash before the timer is recovered after the sixty-second threshold.
- M4 follow-up: `src/main/axiom/recovery/recovery-service.ts:61` currently omits `INTEGRATED` Task bindings while their Mission remains nonterminal, and its legacy kernel scan covers only active workers. M3 does not integrate Tasks. When M4 adds integration, enumerate still-unreleased submitted resources independently of that Task-stage filter so an already-integrated Task cannot hide a lost release timer. That file is outside this brief; no edit was made.
- No required production edit outside the allowed files was made. Host verification and future M4 recovery enumeration are not claimed complete by this Worker report.
