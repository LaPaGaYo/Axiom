## Empty, the two diffs, and settlement races

Empty means the private-index tree equals `baselineSha^{tree}`, not `HEAD^{tree}`. A Worker-created commit whose tree differs from its launch baseline is therefore preserved even when its worktree is clean. A Worker that returned its tree to the launch baseline is empty even if its HEAD differs. Empty creates neither a commit nor a ref. The normal private-index capture can write Git blob/tree objects while computing that equality, just as Candidate capture does.

The preservation commit has the captured tree and parent=Worker HEAD. The three-point diff `merge-base(axiom/integration/<missionId>, preserved)..preserved` is the unchanged verification routine: cumulative scope paths, added-text secret findings and completeness. Separately, the kernel change-list routine compares launch baseline and preserved commit directly: this Attempt's own changed paths/status/line counts, including rename/copy metadata. The former controls whether the snapshot can be inherited; the latter explains what this Attempt left. A preserved snapshot never creates a Candidate, Submission or VerificationRun.

`submitExitedAttempt` serializes its own same-Attempt calls, but preservation awaits Git / Artifact I/O outside the database transaction. During that interval RecoveryService can settle a process exit, reflect a terminal kernel state, or finish a runtime-budget stop. Mission / Task cancellation can change stage and stop or abandon its Worker; another authenticated settlement can revoke dispatch authority. A newer binding can also make the old Attempt stale. The transaction re-runs `resolveHostAttempt`: mismatched ownership, a non-dispatched dispatch, a non-RUNNING Task, a Worker outside ready/start_unknown, or a newer binding refuses with existing errors before failDispatch and audits. Nothing inside this transaction is awaited.

The stale-authority test makes the kernel dispatch fail while capture is pending and observes `inactive_dispatch`: neither local `attempt.failed` nor `attempt.preserved` is written. A real competing recovery path retains its own audit (`attempt.failed`, `attempt.stopped`, `attempt.abandoned` or cancellation consequences, according to that path). Capture's immutable ref / commit and a successfully written log Artifact may remain without a preservation audit; baseline selection will not discover or use them without the audit. An audit-write failure test confirms both exit / preservation audit rows and dispatch mutation roll back together. No preservation failure, incomplete diff or Artifact failure schedules a retry of capture or prevents normal exit settlement.

Same-Attempt replay reuses a ref whose commit message identifies that Attempt and writes no further objects. A concurrently introduced external ref between lookup and the create-only update is never overwritten; that unusual race may be diagnosed as generic git_failure and retain the just-created commit identity rather than re-reading the external winner. Existing Candidate branch-assertion behavior is preserved, so a symbolic-ref lookup error is classified as branch_mismatch; later Git timeouts are git_timeout. Neither diagnostic edge changes settlement or authorizes continuation.
