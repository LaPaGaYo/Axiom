## Hygiene 结论

### Hidden-before-spawn

旧断言 `vi.waitFor(() => expect(mintedSessionId).toBeDefined())` 隐含“异步 spawn preflight 一秒内进入 daemon.spawn”的负载假设。既有广跑日志 `.axiom-work/logs/verify-merged-d29f0aa316-20261020-064647.log:33880` 报的是 `expected undefined to be defined`，不是 hidden 标志为 false；该测试用时约 1010ms。

仅修改原文件两个同形等待：daemon mock 写入 minted id 后 resolve `spawnEntered`；断言先 await `Promise.race([spawnEntered.promise, spawnPromise])`，然后仍在 `spawnGate` 未释放时检查 hidden。race 保留提前拒绝/意外完成时的失败，deferred 消除一秒的调度 deadline，未增加任何 timeout。目标组含该文件全部 9 个测试通过。没有运行整仓 full-suite / verify-main，所以不声称广跑稳定性已经证明，也不修改 verifier 的 known-environmental 登记。

### typecheck:e2e 215 → 214

唯一差值来自已有的 **Axiom e2e** 文件，不是 upstream：

```text
tests/e2e/mission-plan-real-codex.smoke.spec.ts(254,7): error TS2322:
Type '{ attemptId: string | null; ... }' is not assignable to type '{ attemptId: string; ... }'.
```

`MissionPlanResponseSchema.attempt.attemptId` 合法为 null；原成功分支直接赋给要求 string 的变量。仅将该处分支改为：

```ts
const startedAttempt = MissionPlanResponseSchema.parse(planOk.data.result).attempt
if (startedAttempt.attemptId === null) {
  throw new Error('Planner launch has no bound dispatch')
}
attempt = { ...startedAttempt, attemptId: startedAttempt.attemptId }
```

按脚本每个 `file(line,column): error TS…` 计数，初始 215、修复后 214；集合比较仅移除上面一行，新增为 0。恢复到 M1-10 的 214-location 基线，不修改其他 upstream 诊断。新的 exit spec、共享 helpers 与新增回归均不得引入诊断。
