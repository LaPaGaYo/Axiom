## Summary and execution plan

Task M2-03 follows the approved M2 plan (D52), consuming M2-02 ContextPackages. The brief supplies the objective, scope and acceptance criteria. Implemented in four units: shared contracts/v44 migration; storage/closed-set engine/factory; policy RPC/CLI; documentation, negative control and required gates. No new product Decisions or glossary terms.

- v44 adds only `agent_specs.spec` and `mission_policies.routing`, both TEXT NOT NULL DEFAULT '{}'; fresh DDL, guarded migration, schema version and version-skew list agree. Existing enums and other tables are unchanged.
- AgentSpec is a strict role-discriminated execution contract. The store derives its id from canonical JSON, uses INSERT OR IGNORE, validates stored scalar indexes against the full spec and exposes get/list. AgentFactory writes the spec and `agent_spec.created` in one transaction, once per identity.
- Provider selection uses the injected host installed set, excludes the named Claude Agent Teams launch mode, and applies not-installed/disallowed/tier filters before RulesEngine ranking. Tier A comes from the existing structured-session enum; default provider order comes from TUI_AGENT_CONFIG. The factory validates that advisory ranking is an exact eligible-set permutation. It never launches work, writes attempt_bindings or changes Task state/readiness.
- RulesEngine implements choose/score/classify/rank with ordered score rules, stable ties, bounded input candidates, empty-set rejection and no network/model dependency. Provider ranking records installed providers, every rejected known provider and reason, fallback order, chosen provider and rationale.
- Mission routing is parsed and persisted; contextTokens is now a positive optional Budget field and ContextBuilder reads the parsed policy. Policy show/update and CLI subgroup registration are complete, including mutation classification/receipts, generated catalog and error passthrough.
- Policy update applies only routing/concurrencyLimit, atomically with `policy.updated` before/after snapshots. The budget field is retained solely for the handler's explicit `approval_required` pre-check: dispatcher schema failures always become invalid_argument, so z.never would not preserve the required error code. All other unknown patch keys are schema-rejected. Routing replaces the routing object and applies defaults to omitted members.
