## Rule and implementation

| Human verdict | Recorded reason | Allowed disposition | Persisted value |
| --- | --- | --- | --- |
| FAIL | Any, including missing or unknown | fixed | fixed, also when omitted |
| PASS | acceptance_human or non_code | None | Key omitted |
| PASS | Every other reason, including missing or unknown | rejected, intentional, not_worth | Required supplied value |

`src/shared/axiom-contract/verification-disposition.ts` contains the sole reason
classification. Its pure function accepts the recorded reason as unknown so missing,
future and malformed values follow the flagged-run rule without a cast. The enum
remains strict at the mutation boundary. The main process adds enforcement after
criterion validation and before its first write, with existing checks, error messages,
transaction, Task transitions and receipt handling preserved. An unknown stored
disposition is removed by the tolerant reader without dropping a valid resolution.
The strict next-Attempt reader accepts the new optional field without code changes.
