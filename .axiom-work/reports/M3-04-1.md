## Implemented baseline and launch

`resolveAttemptBaseline(store, {taskId, seq})` reads only the immediately preceding binding and Submission. A Candidate is continued only when ACTIVE and its latest run, ordered by `created_at, id` without filtering by verdict, is FAIL with reason other than secret_detected. All other paths use integration:

| Reason | Condition |
| --- | --- |
| first_attempt | seq 1; preserves the original first context |
| previous_attempt_not_submitted | missing binding, dispatch, or Submission; never searches farther back |
| previous_candidate_superseded | Candidate absent or no longer ACTIVE |
| previous_verification_not_failed | no run or latest run not FAIL |
| secret_detected | latest FAIL names a secret; failed run is returned for safe findings |

The launcher passes the full Candidate commit to `createManagedWorktree.baseBranch`, preserving the new Attempt's branch name. `prepareWorkerFixLaunch` checks returned `git.head`, or runs only `rev-parse HEAD` with the established Git runner/options in the new worktree. A mismatch raises exactly `fix_base_mismatch`, is audited and settled as launch_failed, and does not reset/rewrite/remove anything. The real-Git regression proves HEAD and status remain intact on rejection. Integration and Planner bases retain their existing behavior. `attempt-launcher.ts` is 294 lines.

After HEAD validation and immediately before WorkerStartParams construction, the helper re-reads the Orca task. completed plus the immediately preceding Submission invokes public `updateTaskStatus(taskId, 'ready')`, re-reads the task and starts without retryOf. This includes secret-detected clean retries. completed without that Submission remains unstartable; failed/blocked retain retryOf. A real-kernel test confirms reopening refuses an active dispatch. Planner launches skip this helper.

Worker launch receipt audits (started/start_unknown/launch_failed) record `{baseline:{kind,reason? ,candidateId?,commitSha?}}` and `orcaTaskReopened:true` when applicable. Pre-receipt exceptions also preserve resolved baseline metadata and any completed reopen, alongside the existing redacted message.

## Failure evidence

ContextBuilder resolves the upcoming `nextAttemptSeq(taskId)` before admission inserts its binding. The seventh mandatory section is prepared separately and still passes through per-section redaction. Mandatory order and section-4 protocol hashing are unchanged. First Attempt bytes/source remain `none (first attempt)` / `previous-attempt:m2`.

Integration retries explain the baseline and fixed reason in one line, source `previous-attempt:<reason>`. Secret retries additionally name only path/pattern findings and prohibit reintroduction; no matched secret or prior commit history is included.

Candidate retries use source `verification:<runId>` and render:

1. Candidate commit/previous Attempt continuation instruction and the prohibition on weakening/skipping/deleting checks.
2. FAIL verdict and reason.
3. Failed checks ordered by index: command, exitCode, at most 20 failure names, and matching stored verdict-Artifact excerpts. Excerpts are limited to 40 lines each and 8 KiB UTF-8 combined; truncation does not split UTF-8 characters. Missing/unreadable/unparseable Artifact or missing excerpt yields `excerpt unavailable` without blocking retry.
4. Scope findings with remove/revert and merge-base explanation; secret findings limited to path/pattern; dangerous path/pattern findings.
5. All Task acceptance criteria under `Not yet demonstrated`.
6. Optional previous transcript id and its Artifact-read command, using the exported lookup shared with attempt projection.
