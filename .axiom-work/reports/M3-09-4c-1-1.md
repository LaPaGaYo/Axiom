The verifier must capture these working-tree changes as the immutable Candidate; no staging, commit, push or submission was attempted.

- Every committed update requests a round, including an update that changes nothing. A replay of a completed receipt does not re-enter the handler.
- Each round adds one `task.admission_refused` row per Task that still has no eligible provider. Refusals are not deduplicated.
- A failing round's error is not reported when a later pending trigger takes over. A later failing round reports its own error if it has no pending successor.
- The flight result omits admissions already committed by a failed round. Durable bindings, stages and effects remain; no production caller reads that result.
- Only the updated Mission is looked at. Other Missions are not awakened, and the Planner is not started.
- A non-EXECUTING Mission still gets a request, but the round returns without work.
- The request exists only in the process handling the update and is not persisted. A crash between commit and admission leaves READY Tasks for the boot pass.
- Policy updates do not remove budget, attempt-limit, Question or Approval blockers. Existing policy authority, admissible keys, admission rules and provider caps remain in force.
- Write scope for CLI agents remains a verification-time diff check, not a runtime guarantee. This Task's scope was checked locally and still requires the independent verifier's inspection.
