## Limitations and follow-ups

No sandbox escalation is available in this session. The full acceptance test command must be rerun by the launcher in an environment that permits local listeners and supports Electron child startup. Electron aborts with SIGABRT before fixture entry in this environment; its deeper cause was not established. Do not interpret focused green checks as a full-suite PASS.
- **M1-09:** consume the shared response schemas. Mission create returns the ACTIVE Goal and policy; Mission show/list/transitions return only `MissionSummary` (id, repoId, repoPath, targetBranch, status, active Goal/Plan IDs). Load `goal.show` and `plan.show` via those IDs. Task list/show/cancel return `TaskListItem`, not a full Attempt/spec/evidence view; Plan revisions retain proposal Task specs. Derive progress from Task stages for now; adding counters or full Task detail should be additive. Treat `mutation` as the kernel receipt and `orcaStatus` as execution-only.
- **M1-07:** upstream admission is unchanged and still must intercept all §4b paths: taskUpdate status, reset, workerStart/dispatch, forbidden Worker message types, gateCreate/gateResolve, runUse legacy takeover, and taskCreate with nonempty deps. The new facade does not replace those guards.
- **M2:** Mission start only changes Mission state/recomputes readiness. No Attempt launch is added. Existing M1 cancellation stop/abandon hooks remain no-ops; integrate execution-host liveness and stop/abandon before permitting active-Attempt cancellation. Existing M1 budget and Question/Approval readiness limitations remain owned by M2.
- **M5:** Goal changes while EXECUTING persist REPLANNING and MAJOR_REPLAN evidence; replacement Plan approval/inherit/cancel/rebind is still refused by the existing M1 controller. Goal activation in PLAN_REVIEW/PLANNED/paused/terminal states is rejected rather than invalidating a pending or approved plan silently.
- **Policy/user identity:** M1 commands are user RPCs under the existing runtime authentication. No agent-session attestation is attached to `axiom.*`; Worker capabilities are reserved for the later Attempt channel. Markdown Goal author is recorded as `user` and provenance time is file mtime; JSON callers can provide explicit provenance.
- **Delivery state:** uncommitted changes on the assigned Attempt branch; no immutable snapshot, independent verification, promotion, or merge performed by this Worker. Launcher owns candidate creation and the completion decision. No unresolved product decision was required within the given M1 scope.
