## Behavior and tradeoffs

- ask uses M2-06a authority, the kernel's one original QUESTION message, then an acceptance receipt before notification/wait. Resume verifies dispatch ownership. Timeout/cancellation preserve the pending thread; kernel settlement closes it. Control Plane consumer recognizes kernel question rows without payload.axiom.
- answer validates Mission/Attempt ownership, uses current consumer_generation, writes question.answered, recomputes readiness, records the receipt and notifies the dispatch status waiter. Answer whitespace is preserved exactly (regression tested). Identical answers are idempotent; conflicting answers and closed threads retain kernel errors.
- createTask materializes DEFINED stage/empty Orca deps/TaskEdges under the active APPROVED plan. It audits task.created and plan.minor_adjustment, recomputes readiness, and schedules only after commit; rollback suppresses the trigger. The original PlanRevision proposal remains an immutable proposal snapshot; new Task rows reference that same revision.
- D50 checks run for every consumed request and again on acceptance. Automatic creation requires a strictly parsed boolean true. Rejection only audits. Successful human/automatic decisions write subtask.resolved; failed acceptance preserves checks_failed evidence and leaves the item pending. Duplicate resolution is invalid_argument; a repeated mutation request id replays its receipt.
- The existing common ProvenanceSchema does not include `model`. The allowed `task-params.ts` derives a task-creation provenance schema supporting model for D50 audit evidence, without changing shared PlanRevision provenance or any out-of-scope file.
- Kernel createQuestion/answerQuestion each own BEGIN IMMEDIATE. Their writes therefore precede the synchronous Axiom audit/receipt transaction, as the upstream question path does. Notification occurs after receipt persistence. A crash precisely between the kernel commit and Axiom receipt remains a kernel seam; an unfinished receipt is inspectable as operation_unknown rather than blindly recreating work. No forbidden kernel transaction refactor was made.
