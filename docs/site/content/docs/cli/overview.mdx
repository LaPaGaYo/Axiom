The Axiom CLI is the `axiom` command-line interface for scripting a running Axiom editor from any shell. Use it to create and inspect worktrees, drive agent terminals, open files and diffs, automate the built-in browser, run scheduled automations, and control Axiom-native tools from scripts or AI agents.

It ships with the desktop app; register it under [Settings → General → Axiom CLI](/docs/settings).

Agents can install the matching Axiom CLI skill with:

```bash
npx skills add https://github.com/LaPaGaYo/Axiom --skill orca-cli
# headless / no Settings UI:
axiom skills install --skill orca-cli
```

See [Skills registry & MCP](/docs/cli/skills) for every installable Axiom skill, including `axiom skills install` / `axiom skills update`.

## Install & verify

```
command -v axiom
axiom status --json
```

## Worktree commands

```
axiom worktree ps --json
axiom worktree create --repo id:<repoId> --name my-task --issue 123 --json
axiom worktree create --repo id:<repoId> --name review-pr-123 --pr 123 --json
axiom worktree current --json
axiom worktree set --worktree active --comment "reproduced bug" --json
axiom worktree set --worktree active --gitlab-issue 42 --gitlab-mr 77 --json
axiom worktree set --worktree active --pr null --json
axiom worktree rm --worktree id:<id> --force --json
```

For selectors, setup flags, parent/child worktrees, and the broader command map, see [Axiom CLI reference](/docs/cli/reference).

## Terminal commands

```
axiom terminal list --json
axiom terminal read --json
axiom terminal send --text "continue" --enter --json
axiom terminal wait --for tui-idle --timeout-ms 30000 --json
axiom terminal create --worktree path:/projects/app --command "npm test" --json
axiom terminal split --direction vertical --command "npm run dev" --json
```

For tracked multi-agent work, use [Orchestration](/docs/cli/orchestration) instead of plain terminal prompts.

## File commands

Open files and diffs as tabs in their Axiom worktree from a shell. They open without changing what you are looking at; add `--focus` to be brought to the file:

```
axiom file open src/App.tsx
axiom file diff src/App.tsx --staged
axiom file open-changed --mode both
```

Use `--worktree <selector>` when the shell's current directory is not inside the target worktree.

## Browser profiles

Browser profiles isolate tab session state, so a script or agent can test with different cookies, local storage, and logged-in identities. The CLI exposes profile commands under `axiom tab profile`; start with `axiom tab profile list --json`, then use `create`, `set`, `clone`, or `use-default` as needed.

## Scheduled automations

Use `axiom automations` to create, inspect, run, and remove scheduled Axiom tasks from a shell. Start with [Scheduled automations](/docs/cli/automations) when you want a recurring prompt to run against a repo or an existing worktree.

## Artifacts

Artifact sharing is not part of Axiom V1.

## Browser automation

The CLI also drives the built-in browser with a snapshot-interact-re-snapshot loop:

```
axiom goto --url https://example.com --json
axiom snapshot --json     # returns refs like @e1, @e3
axiom click --element @e3 --json
axiom fill --element @e1 --value "user@example.com" --json
axiom screenshot --json
```

For responsive browser checks, switch the active tab to a named device profile:

```
axiom set device --name "iPhone 12" --json
axiom screenshot --json
```

## Mobile emulator

The CLI can also drive an iOS Simulator through Axiom's mobile emulator bridge. It is scoped to the active worktree, so agents and scripts can attach a simulator from `axiom emulator list`, tap normalized coordinates, type text, send gestures, rotate the device, and shut it down without leaving Axiom.

```
axiom emulator list --json
axiom emulator attach "<device-name-or-udid>" --json
axiom emulator tap 0.5 0.7 --json
axiom emulator type "hello" --json
axiom emulator gesture '[{"type":"begin","x":0.5,"y":0.8},{"type":"move","x":0.5,"y":0.4},{"type":"end","x":0.5,"y":0.2}]' --json
axiom emulator rotate landscape_left --json
axiom emulator kill --json
```

Use `--worktree <selector>`, `--device <udid-or-name>`, or `--emulator <id>` when a script needs an explicit target.
