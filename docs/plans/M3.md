**M3 出口标准**（§20 + §11 + D61 前置项）：
1. **独立验证**：在 `fixture-v1` 上，Submission 的 `verification_runs(QUEUED)` 被 VerificationService 领取 → Task `SUBMITTED → VERIFYING`，在**独立的验证 worktree**（从 Candidate commit 检出，不是 Worker 的 worktree）里运行 Task 的 `requiredEvidence` 命令 + policy 要求的仓库门禁，记录命令、工具版本、每项 check 的 `pass / fail / inconclusive / skipped`（skipped 带策略依据）、证据 Artifact；PASS → Task `VERIFIED`；验证 worktree 回收，日志进 Artifact。
2. **故意注入的失败被 FAIL 拒绝并自动生成修复 Attempt**（§20 原文）：S1 候选 → `FAIL`（verdict 指名失败的 check 与测试）→ Task `NEEDS_FIX` → Scheduler 自动起修复 Attempt（seq 2，分支从上一 Candidate 继续，D64），其 ContextPackage 含失败证据（失败命令、输出摘录、未满足的 acceptance 条目）→ 修复候选 → `PASS` → `VERIFIED`；`retryPolicy.maxAttempts` 耗尽 → `BLOCKED(retry_budget_exhausted)`。
3. **FAIL 不能被 review 推翻**（§20 原文）：deterministic FAIL 的 VerificationRun 不接受任何 Reviewer 提案把它改成 PASS（单测 + e2e 各一）；Reviewer 只能对 `INCONCLUSIVE` 给出收敛建议，建议经 Control Plane 校验后才改状态。
4. **diff scope 检查（G2）**：候选 diff 触及 `scope.allowedPaths` 之外的路径 → `FAIL(scope_violation)`，即使全部测试通过；危险改动清单（policy）与生成文件判定记录在 verdict。
5. **acceptance 逐条评估**：每条 `acceptanceCriteria` 有 `pass / fail / inconclusive / skipped` + 证据引用；非代码 Task（`requiredEvidence` 为空）走 Artifact 存在性 + schema 校验 + Reviewer advisory + policy 要求的人工确认（G7）。
6. **升级与人工处置**：`INCONCLUSIVE` 按 policy 升级到 `SPECIALIST_REVIEW`（Reviewer）或 `HUMAN_REVIEW`；人经 `axiom.verification.resolve` 给出 PASS / FAIL（带理由），审计可追；UI 的待处理项显示它。
7. **可重启**：进程死亡时处于 `RUNNING` 的 VerificationRun 重启后重新入队（幂等、证据保留）；孤立的验证 worktree 被回收；不重复领取。
8. **Attempt Supervisor V1（D60）**：对 RUNNING Attempt 的有界输出做分类（RulesEngine 基线 + Jev 适配器，同一 `DecisionEngine` 接口），只写 `attempt.supervised` 审计与待处理项，不自动停止 / NEEDS_FIX / 重规划（单测证明越权动作不存在）。

## 固定约定（所有 M3 brief 共用）

- 内核改动只许 additive、service-only 的可选入参；RPC schema 不变；不建第二套 worktree manager——验证 worktree 经 Orca worktree service 创建，带 Axiom 标记（不进 renderer 列表）。
- VerificationRun 身份 = `verification_runs.id`；verdict 只由 VerificationService 与 `axiom.verification.resolve`（人）写入；Reviewer 只提议。deterministic FAIL 不可逆（状态机测试固定）。
- 所有 `axiom.verification.*` 的 Worker / Reviewer 侧动词走 envelope `orchestrationCapability`；人侧动词走既有 UI mutation 通道；拒绝复用 Orca 的 `LifecycleRejectionCode`。
- 内容寻址：verdictDetail、证据 Artifact、ContextPackage 的失败证据段都是 sha256 寻址；数据库只存引用。
- Supervisor / Jev：DecisionEngine 输出只是建议；任何自动动作需要单独的修订行；API key 永不进日志 / Artifact / 测试输出。
- 验证门同 M2 + 托管 `axiom-ci.yml` 第二信号；涉及 launcher / 内核 seam 的 Task 把 `src/main/runtime/rpc/methods/orchestration src/main/runtime/orchestration src/main/axiom` 全部列进 targets。
- 文档：枚举改动先改术语表并记 Decision；每个 Task 回填 `docs/reference/control-plane.md` 与映射的对应节。
